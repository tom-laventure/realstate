## Spacing Scale

Declared values (must be multiples of 4) — project-standard 8-point scale, confirmed via existing admin components (`BoardRegistrations.tsx`, `DomainCardList.tsx`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`mr-1`, `gap-1`) |
| sm | 8px | Compact spacing between list rows' internal elements |
| md | 16px | `CardContent` padding (`p-4`), dialog internal spacing |
| lg | 24px | Section header padding-bottom (`pb-4` in `CardHeader` — rounds to nearest scale step), gap between page-level sections |
| xl | 32px | Not used this phase |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions:
- `Card className="mt-6"` (24px top margin) is the established pattern for spacing the Ownership Management card below the `AdminBoard` page header — reuse verbatim from `BoardRegistrations.tsx`, do not invent a new top-margin value.
- Owner list rows use `divide-y divide-border` (1px hairline borders) per D-01 — no row padding beyond `py-3` (12px), matching the existing `BoardRegistrations.tsx` row pattern; 12px is an accepted half-step exception for dense list rows, consistent with existing codebase usage.

## Typography

Confirmed from existing admin surfaces (`BoardRegistrations.tsx`, `RolePermissions.tsx`, `DomainCardList.tsx`) — reuse exactly, no new sizes introduced:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label / Section title | 16px (`text-base`) | 600 (`font-semibold`) | 1.2 |
| Small / muted meta | 14px (`text-sm`, `text-muted-foreground`) | 400 (regular) | 1.5 |
| Dialog title | 18px (`text-lg`, shadcn `DialogTitle` default) | 600 (semibold, shadcn default) | 1.2 |

Only 2 weights used across this phase: **400 (regular body/description text)** and **600 (semibold — CardTitle, DialogTitle, row name, warning-box lead line)**. No 3rd weight introduced.

Font sizes used: 14px (body/list rows/muted meta) and 16px/18px (section + dialog titles) — 3 distinct sizes total, within the 3-4 size budget.

## Component-Level Notes (executor guidance, not in template but load-bearing)

- **Current Owners list (OWN-01, D-01, D-02):** Plain stacked rows, `divide-y divide-border`, each row = `<div className="flex items-center justify-between py-3">` with name (`font-medium text-sm`) + email (`text-sm text-muted-foreground`) stacked or inline — no table, no cards, no avatars, no timestamps, no "You" badge. All rows render identically regardless of viewer identity.
- **Add Owner modal primitive:** Use `Dialog` (not `AlertDialog`) — the modal contains an interactive `Popover`/`Command` combobox, and this codebase reserves `AlertDialog` for pure static-text confirm/cancel (see `DeleteDomainDialog.tsx`, `BoardRegistrations.tsx`'s delete flow). This satisfies REQUIREMENTS.md's "Dialog/AlertDialog" either-or wording.
- **Warning callout placement:** Renders conditionally only after a user is selected in the combobox (per RESEARCH.md Pattern 3) — do not show the warning box before selection, since it references the selected user's name and current role inline.
- **RolePermissions call site (D-05/D-06/D-07):** `<RolePermissions roles={['owner', 'admin', 'agent']} />` — must explicitly pass this prop; do not rely on the component's default (`['client', 'agent', 'admin', 'owner']`), which would incorrectly include `client`. Shown only in the admin/agent (read-only) branch, never to owners.
- **Focus/accessibility:** `Popover`/`Command` combobox already has ARIA/keyboard nav from shadcn/cmdk — no custom work needed. Dialog must trap focus (shadcn `DialogContent` default behavior) and return focus to the "Add Owner" trigger button on close. Confirm button must show a visible disabled state (not just `opacity`) when no user is selected or a submission is in flight.
