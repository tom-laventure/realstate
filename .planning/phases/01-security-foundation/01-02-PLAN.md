Create `backend/app/controllers/v1/admin/base_controller.rb` with this exact content per D-01/D-02/D-03:

```ruby
module V1
  module Admin
    class BaseController < ApplicationController
      include BrokerageAuth
      include CognitoAuth
      include Pagy::Backend

      before_action :authenticate_cognito_user!
      before_action :require_admin!

      private

      def require_admin!
        membership = BrokerageMembership.find_by(
          user_id: Current.user.id,
          brokerage_id: Current.brokerage.id
        )
        unless membership && %w[owner admin].include?(membership.role)
          render json: { error: { code: "forbidden", message: "You do not have permission to perform this action." } },
                 status: :forbidden
        end
      end

      def require_owner!
        membership = BrokerageMembership.find_by(
          user_id: Current.user.id,
          brokerage_id: Current.brokerage.id
        )
        unless membership&.role == "owner"
          render json: { error: { code: "forbidden", message: "Owner access required." } },
                 status: :forbidden
        end
      end
    end
  end
end
```

Critical ordering: `include BrokerageAuth` comes FIRST because its `included do` block registers `before_action :resolve_brokerage`. Then `include CognitoAuth`. Then explicit `before_action :authenticate_cognito_user!`. Then `before_action :require_admin!`. This ensures `Current.brokerage` and `Current.user` are both set before `require_admin!` runs.

The class name `V1::Admin::BaseController` matches the directory path `v1/admin/base_controller.rb` — required for Rails autoloading per D-01.

| T-02-02 | Elevation of Privilege | BrokeragesController#update/destroy | mitigate | require_owner! enforces owner-only; admin receives 403 on these actions specifically |

| T-02-04 | Spoofing | InvitationsController#validate_token | accept | Public endpoint by design (invitees access from email link with no account); no sensitive data returned — token validity check only |
