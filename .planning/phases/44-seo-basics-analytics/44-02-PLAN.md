**Vendor the font.** Copy `/usr/share/fonts/truetype/lato/Lato-Semibold.ttf` to `landing/scripts/fonts/Lato-Semibold.ttf` (create the directory). Satori requires an explicit font `Buffer` — TTF, OTF, or WOFF only, **never WOFF2** — and has no "use the system font stack" mode, so the font must be bundled for the script to be re-runnable on any machine. Also write `landing/scripts/fonts/LATO-LICENSE.txt` containing the SIL Open Font License 1.1 text and copyright line for Lato, sourced from `/usr/share/doc/fonts-lato/copyright` (the OFL requires the license accompany redistributed font files). Per RESEARCH.md Assumption A3, exact font match with the live site's system-ui stack is cosmetic only — OG images are viewed in link-preview surfaces, never side by side with the site.

**Write `landing/scripts/generate-og-image.mjs`.** Requirements:
- ES module (`landing/package.json` already sets `"type": "module"`), 2-space indent, no semicolons is NOT required — match the `.ts`/`.mjs` style already in `landing/` (`consts.ts` uses 2-space + no semicolons; `astro.config.mjs` uses 2-space + semicolons — pick one and be internally consistent).
- Header comment recording provenance: satori usage pattern per `github.com/vercel/satori`, Resvg usage per `github.com/yisibl/resvg-js`, and that the two hex colors are pre-converted from `--primary`/`--primary-foreground` in `src/styles/global.css` (with the oklch source values named in the comment so a future palette change is traceable).
- Import `satori` from `satori`, `Resvg` from `@resvg/resvg-js`, `readFileSync`/`writeFileSync` from `node:fs`.
- Import `SITE_NAME` from `../src/consts.ts`. Node 22 can import a `.ts` file only with type-stripping enabled; if a plain `import { SITE_NAME } from '../src/consts.ts'` fails to run under `node scripts/generate-og-image.mjs`, do NOT hardcode the string — instead read `src/consts.ts` as text and extract the `SITE_NAME` value with a regex on `export const SITE_NAME = '...'`, so the constant remains single-sourced. Record whichever approach worked in the SUMMARY.
- Resolve all paths relative to the script via `new URL(..., import.meta.url)` so the script runs correctly regardless of the caller's cwd.
- Build the satori element tree as plain objects (`{ type, props: { style, children } }`) — no JSX, no React, no build step. Structure: a full-bleed root `div` (`width: '100%'`, `height: '100%'`, `display: 'flex'`, `alignItems: 'center'`, `justifyContent: 'center'`, `backgroundColor: '#394658'`) containing a single child `div` holding the `SITE_NAME` text with `color: '#FAFAFA'`, `fontSize: 96`, `fontWeight: 600`, `fontFamily: 'Lato'`.
- Use the literal hex strings `#394658` and `#FAFAFA`. Do NOT pass `oklch(...)` strings or CSS custom properties — satori's CSS parser does not support either and will throw or mis-render (RESEARCH.md Assumption A1, Open Question 3).
- Call `satori(tree, { width: 1200, height: 630, fonts: [{ name: 'Lato', data: fontBuffer, weight: 600, style: 'normal' }] })`.
- Rasterize with `new Resvg(svg).render()`, then assert the rendered `width === 1200 && height === 630` and throw with a clear message if not, before calling `.asPng()`.
- Write the PNG buffer to `../public/og-image.png` and log the output path plus byte size.
- The script must NOT be wired into `astro build` — no Astro integration hook, no `prebuild` script. Per D-01 this is a one-time-generated static asset that sits in `public/` untouched, exactly like `favicon.ico`.

**Add an npm script** to `landing/package.json`: `"generate:og": "node scripts/generate-og-image.mjs"`, placed after the existing `astro` entry, preserving the file's 2-space indentation. This documents the regeneration command without coupling it to the build.
