## Interaction States

NotFound has **no interactive states** per D-05. The page is purely presentational.

| State | Description | Implementation |
|-------|-------------|----------------|
| Default | Static centered text on white background | Single render, no state |
| Hover | No hover targets | Not applicable |
| Focus | No focusable elements | Not applicable |
| Loading | Not applicable — guard renders synchronously | Not applicable |
| Error | Not applicable — NotFound is not a data page | Not applicable |

**Accessibility baseline (CLAUDE.md requirement):**
- `<h1>` provides semantic heading for screen readers
- Page has a meaningful title hierarchy (single h1 only)
- No ARIA roles needed beyond native HTML semantics
- Color contrast: `text-foreground` on `bg-background` = dark near-black on white, ratio >7:1 (AAA)
- Color contrast: `text-muted-foreground` on `bg-background` = `oklch(0.552)` medium gray on white, estimated ratio ~4.5:1 (AA compliant)

## Full NotFound.tsx Contract

The executor must implement `NotFound.tsx` to match this specification exactly:

```
frontend/src/containers/errorPage/NotFound.tsx
```

**Structure:**
```
<div.flex.min-h-screen.items-center.justify-center>
  <div.text-center>
    <h1.text-2xl.font-semibold.text-foreground>
      Page not found
    </h1>
    <p.mt-2.text-base.text-muted-foreground>
      The page you're looking for doesn't exist.
    </p>
  </div>
</div>
```

**Constraints from locked decisions:**
- No `useRouteError()` — this is a regular `element`, not an `errorElement` (RESEARCH.md Pattern 4)
- No `<Button>`, no `<a>` tags, no navigation links — D-05
- No HTTP status codes in visible copy — D-05
- Default export, functional component, no props — used as `element: <NotFound />`
- Must be co-located at `containers/errorPage/` alongside `ErrorPage.tsx` — D-04
