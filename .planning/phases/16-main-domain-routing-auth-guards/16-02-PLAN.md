<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser ↔ React Router | Routing decisions for `/dashboard/*`, `/no-access`, and `/auth/*`. UX enforcement only — backend enforces actual access on `/v1/admin/**`. |
| LoginSuccessful ↔ axios (via hook) | Token is written to localStorage via `setToken`, then axios interceptor reads it to call the function returned by `useFetchAdminBrokerages`. Ordering is critical. |
| Browser ↔ localStorage | JWT stored as `auth_token`. Vulnerable to XSS — addressed at the application layer outside this phase (deferred to v2 per STATE.md "JWT → HttpOnly cookies migration"). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-02-01 | Elevation of privilege | `/dashboard/*` accessible to unauthenticated user | mitigate | `portalDashboard` route in `main.tsx` is wrapped by `<ProtectedRoute />` (from Plan 01's portal.tsx). ProtectedRoute redirects to `/auth/login` with `state={{ from: location }}` when `isAuthenticated()` is false. AUTH-07 requirement. |
| T-16-02-02 | Elevation of privilege | Subdomain user reaches main-domain portal by URL manipulation | mitigate | `MainDomainOnly` guard wraps the portal route block in `main.tsx`. On a subdomain, `MainDomainOnly` returns `<Navigate to="/" replace />`, bouncing the user back to the subdomain home. Backend `MainDomainOnly` concern (Phase 15) is the actual security control — frontend guard is UX. |
| T-16-02-03 | Spoofing | Token-bearing user with no admin roles bypasses no-access screen by navigating directly to /dashboard | mitigate | ProtectedRoute lets them through to `/dashboard` (token is valid), but the dashboard placeholder is read-only / does nothing in Phase 16. Phase 18 will gate the actual admin panels behind backend `X-Brokerage-Id` resolution which enforces admin role on the backend. Frontend cannot trust admin status. |
| T-16-02-04 | Tampering | User mutates `localStorage.auth_token` to forge a session | accept | Tokens are JWTs signed by Cognito. Tampered tokens fail signature verification on the backend (`CognitoAuth` concern). Frontend `isAuthenticated()` only checks `exp` claim — an unverified, expired-claim-stripped token passes locally but fails on first `/v1/**` call, which triggers global 401 → clearToken → redirect to login. |
| T-16-02-05 | Information disclosure | Open redirect via `returnTo` parameter on `/auth/login-success#returnTo=https://evil.com` | mitigate | The subdomain branch uses `params.get('returnTo') \|\| '/'` and calls `navigate(destination, { replace: true })`. React Router `navigate()` treats absolute URLs (with `http://`) as relative paths — `navigate('https://evil.com')` becomes a relative path navigation, not an external redirect. The main-domain branch ignores `returnTo` entirely and uses hardcoded `/dashboard` or `/no-access`. No open redirect surface. |
| T-16-02-06 | Information disclosure | Token leaked in `window.location.hash` if user shares URL after login-success | mitigate | `window.location.hash = ''` is called immediately after `setToken(token)` and before any further navigation. The hash is cleared from the URL bar before the user sees the post-login page. Existing behavior — preserved unchanged. |
| T-16-02-07 | Denial of service | Hook's returned function hangs indefinitely; LoginSuccessful spinner never resolves | accept | No timeout in axios for this call. User can refresh manually. Per RESEARCH.md, this is a v1.5 resilience concern, not Phase 16 scope. The existing error path (`.catch(() => setError(true))`) handles network failures but not infinite hangs. Acceptable for current threat model. |
| T-16-02-08 | Repudiation | No audit log of post-login routing decision | accept | Phase 15 backend already logs `GET /v1/account/admin_brokerages` requests. The frontend routing decision is a deterministic function of the backend response, so backend logs are sufficient for audit. |
| T-16-02-09 | Elevation of privilege | Redirect loop on `/no-access` → `/auth/login` → `/no-access` → ... | mitigate | `noAccess` route is bare (no `<ProtectedRoute />`) per D-08. Even if the user is unauthenticated, they can render `/no-access` directly. The Sign Out button uses `window.location.href` (hard navigation), not `navigate()`, ensuring a full page reload that resets all React state. No loop surface. |
| T-16-02-10 | Tampering | A future maintainer modifies LoginSuccessful to import `fetchAdminBrokerages` directly, bypassing the hook | mitigate | Acceptance criteria explicitly grep for the absence of `from '@/assets/api/account/fetchAdminBrokerages'` in LoginSuccessful.tsx, and the presence of `import useFetchAdminBrokerages from '@/store/hooks/Account/useFetchAdminBrokerages'`. CI will fail on regression. |
</threat_model>
