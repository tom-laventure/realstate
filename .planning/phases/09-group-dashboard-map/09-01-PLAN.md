<objective>
Deliver the backend foundation for the group dashboard map: a new `GET /v1/dashboard/groups/:group_id/estates/coordinates` endpoint that returns one lightweight record per filtered estate in the group with a non-null latitude/longitude pair. Coordinate records also include the minimum popup fields (price, address, beds, baths, sqft, hero image URL) so the frontend can render single-pin popups without a second round-trip.

Purpose: Decouples map pin rendering from the paginated /estates index (which caps at 100/page) while keeping filter sync free via the shared GroupEstatesQuery. This is the data source for MAP-02 (pins per listing) and MAP-03 (filter-driven pin set).

Output: New collection action, route, and integration test that covers happy-path return, filter forwarding, soft-delete exclusion, NULL coord exclusion, and non-member 404.
</objective>

class EstatesController < ApplicationController
  include CognitoAuth
  include BrokerageAuth
  include Pagy::Backend

  before_action :authenticate_cognito_user!     # auth — inherited by new action
  before_action :set_group                      # tenancy/membership — inherited

  # Existing #cities action serves as the structural analog:
  def cities
    cities = @group.estates.without_deleted
      .joins(:listing_detail)
      .where.not(listing_details: {city: nil})
      .where.not(listing_details: {city: ""})
      .distinct.pluck("listing_details.city").sort
    render json: {cities: cities}, status: :ok
  end

  private
  def set_group
    @group = ::Group.without_deleted
      .where(brokerage_id: Current.brokerage.id)
      .joins(:user_groups)
      .where(user_groups: {user_id: Current.user.id})
      .find_by!(uid: params[:group_id])
  end
end

```ruby
# GET /v1/dashboard/groups/:group_id/estates/coordinates
def coordinates
  scope = GroupEstatesQuery.new(@group, Current.user, params).call
    .joins(:listing_detail)
    .where.not(listing_details: {latitude: nil})
    .where.not(listing_details: {longitude: nil})
    .select(
      "estates.id",
      "listing_details.latitude",
      "listing_details.longitude",
      "listing_details.list_price",
      "listing_details.address",
      "listing_details.bedrooms",
      "listing_details.full_bathrooms",
      "listing_details.sqft",
      "listing_details.hero_image_url"
    )

  coords = scope.map do |e|
    {
      id: e.id.to_s,
      latitude: e.latitude,
      longitude: e.longitude,
      listPrice: e.list_price,
      address: e.address,
      beds: e.bedrooms,
      baths: e.full_bathrooms,
      sqft: e.sqft,
      heroImageUrl: e.hero_image_url
    }
  end

  render json: {coordinates: coords}, status: :ok
end
```

Important notes:
- Use `e.bedrooms` and `e.full_bathrooms` (the actual DB columns surfaced by `.select`). Emit them as `beds:` and `baths:` in the JSON to match the camelCase the frontend interceptor expects on response keys (note: the json key shape is what the response body literally contains; the axios interceptor recursively camelCases all object keys — so `listPrice`, `heroImageUrl`, `beds`, `baths` will arrive as-is).
- DO NOT use `e.beds` or `e.baths` — those are model methods aliased on the AR object; with `.select` the AR record only exposes the selected columns.
- Auth and tenancy are inherited from the controller `before_action` callbacks — no additional guards needed.
- `listing_details` does NOT use `acts_as_paranoid` — no `deleted_at` guard on that join.
- No Pagy pagination — return all matching records.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → API (HTTPS) | Cognito JWT-authenticated agent requests reach `/v1/dashboard/groups/:group_id/estates/coordinates` |
| Brokerage → Brokerage (multi-tenant) | One brokerage's user must never see another brokerage's coordinates |
| Non-member → Group | A user who is NOT a member of the requested group must not receive its coordinates |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01-01 | Information Disclosure | EstatesController#coordinates | mitigate | `before_action :authenticate_cognito_user!` + `before_action :set_group` are inherited; `set_group` uses `find_by!(uid: ...)` scoped to `Current.brokerage` + user's `user_groups` membership join → non-members get `ActiveRecord::RecordNotFound` (404). Test case (f) asserts the 404. |
| T-09-01-02 | Information Disclosure (cross-tenant) | GroupEstatesQuery scope | mitigate | `@group.estates` is the join through the user's group; `GroupEstatesQuery` further applies `.accessible_by(@group.brokerage_id)` — verified in `app/queries/group_estates_query.rb`. No raw `Estate.all`. |
| T-09-01-03 | Tampering | Filter params (min_price, cities[], etc.) | accept | Filter params flow through `GroupEstatesQuery` which already validates them safely (same code path as existing `#index`). No new attack surface; existing tests in `group_estates_query_test.rb` cover the filter pipeline. |
| T-09-01-04 | Information Disclosure (leaked PII) | Response payload | accept | Coordinates + address + price + bed/bath/sqft + hero image URL are already visible to group members via the existing `/estates` index. No new fields exposed beyond what `EstateSerializer` already returns. |
| T-09-01-05 | Denial of Service | Unpaginated endpoint | mitigate | Endpoint returns only filtered estates in a single group. Even at the high end (~500 listings/group), payload is ~50KB. Per-record cost is low (no AR object instantiation; `.select` projects raw columns). If group sizes grow to 10k+, future capping can be added — out of scope for v1.2. |
| T-09-01-06 | Spoofing | JWT validity | mitigate | `CognitoAuth` concern verifies the JWT signature against AWS Cognito JWKS on every request — established pattern, no Phase 9 change required. |
