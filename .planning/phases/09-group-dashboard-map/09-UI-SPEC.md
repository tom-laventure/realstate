## Spacing Scale

8-point scale. Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (`gap-1`) |
| sm | 8px | Compact element spacing (`gap-2`, `p-2`) |
| md | 16px | Default element spacing (`gap-4`, `p-4`) |
| lg | 24px | Section padding (`gap-6`, `p-6`) — dashboard default |
| xl | 32px | Layout gaps (`gap-8`) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Map container height: 384px (`h-96`) — explicit pixel height required by Google Maps internals; not expressible as a spacing token
- Popup card padding: 12px (`p-3`) — compact card format matches existing listing card density
- Touch target minimum: 44px for map close/dismiss buttons — accessibility baseline

## Interaction Contract

### Map Panel

**Placement:** Inside the `max-w-5xl` container, between `<ListingsFilterBar>` and `<ListingsGrid>`. Full width of container. Collapsible toggle is out of scope for this phase — map is always visible when coordinates exist.

**Container dimensions:**
- Width: `w-full` (fills `max-w-5xl` container, same as grid)
- Height: `h-96` (384px) — fixed height required for Google Maps internal absolute positioning
- Border: `rounded-xl border border-border overflow-hidden`
- Margin below: `mb-4` to match existing `<ListingsFilterBar>` margin

**Map behavior:**
- Default center: Vancouver BC `{ lat: 49.28, lng: -123.12 }` — fallback when no coordinates exist
- Initial zoom: 11
- Fit bounds on data load: `map.fitBounds()` called after coordinates load to frame all pins; only on initial load and when group changes, not on every filter change (prevents jarring re-centering)
- Gesture handling: `gestureHandling="cooperative"` — prevents scroll hijacking on touch and scroll-wheel

### Pin States

| State | Visual |
|-------|--------|
| Default | `AdvancedMarker` with default Google Maps pin appearance |
| Hovered | Cursor `pointer`; browser default hover behavior on `AdvancedMarker` |
| Selected (popup open) | Pin remains in place; `InfoWindow` anchored above it |
| Clustered | `@googlemaps/markerclusterer` default cluster appearance with count badge using `bg-primary text-primary-foreground` |

### Single Pin Popup (MAP-06)

Triggered by: click on a single `AdvancedMarker`.

**Popup anatomy:**
```
┌─────────────────────────┐
│  [Hero photo — h-32]    │
├─────────────────────────┤
│  $1,200,000             │  ← text-base font-semibold
│  123 Main St, Vancouver │  ← text-sm text-muted-foreground
├─────────────────────────┤
│  🛏 3 bd  🛁 2 ba  □ 1450 sqft │  ← text-xs text-muted-foreground
├─────────────────────────┤
│  [View details →]       │  ← text-sm, link to /:groupId/estate/:id
└─────────────────────────┘
```

- Popup width: `w-56` (224px) — matches Google Maps InfoWindow default; no overflow
- Hero image: `h-32 w-full object-cover` — same object-fit treatment as ListingsGrid card
- Close button: Google Maps InfoWindow native close `×` — no custom close button needed
- Only one popup open at a time: opening a new popup closes the previous one

### Cluster Popup — Max Zoom (MAP-05)

Triggered by: clicking a cluster pin when `map.getZoom() >= 19`.

At zoom < 19: default `defaultOnClusterClickHandler` (zoom in) — no custom popup.

**Cluster popup anatomy:**
```
┌──────────────────────────────┐
│  3 listings at this location │  ← text-sm font-semibold
├──────────────────────────────┤
│  $1.2M  123 Main St →        │  row 1
│  $950K  125 Main St →        │  row 2
│  $1.1M  127 Main St →        │  row 3
└──────────────────────────────┘
```

- Each row: `flex items-center justify-between gap-4 text-sm py-1`
- Price: `font-medium` — left-aligned
- Address: `text-muted-foreground` — left-aligned
- "→" link: navigates to `/:groupId/estate/:estateId` — right-aligned `text-primary`
- Max rows shown: all listings in cluster (no pagination at cluster level — cluster count is naturally bounded by zoom level)
- Popup width: `w-64` (256px)

### Filter Sync (MAP-03)

Automatic via TanStack Query key invalidation. No explicit interaction needed. When the user changes any filter:
1. `GeneralDashboardContext` state updates
2. `useFetchGroupEstateCoordinates` query key changes (includes all filter params)
3. TanStack Query refetches — map pins update within 200–500ms depending on network
4. During refetch: existing pins remain visible (`keepPreviousData: true`) — no flash to empty state

### Loading State

Displayed inside the `h-96` map container while `useFetchGroupEstateCoordinates` is pending:

```
┌──────────────────────────────┐
│                              │
│    [Loader2 animate-spin]    │  ← h-6 w-6 text-muted-foreground
│                              │
└──────────────────────────────┘
```

Container: `flex h-96 items-center justify-center rounded-xl border border-border`
Spinner: `Loader2` from lucide-react, `h-6 w-6 animate-spin text-muted-foreground` — matches `DashboardLoading.tsx` pattern

### Error State

Displayed when the `/coordinates` fetch fails:

Container: same `h-96` wrapper as loading state
Content: `MapPin` icon (lucide) + heading + body + retry affordance

```
[MapPin icon — h-8 w-8 text-muted-foreground]
"Couldn't load map"
"Location data failed to load. Try refreshing the page."
```

No retry button in this phase — user refreshes the page. Error is silent to the map panel; the listings grid continues to work normally.

## Copywriting Contract

| Element | Copy | Notes |
|---------|------|-------|
| Map section heading | "Listings on the map" | Displayed above the map panel; `text-sm font-medium text-muted-foreground`; no count appended (count is visible from the listings section heading above) |
| Pin popup CTA | "View details" | Link navigating to listing detail — verb + noun, action-oriented |
| Cluster popup heading | "{N} listings at this location" | N = cluster.count; lowercase "listings"; communicates the situation without jargon |
| Cluster popup row CTA | Arrow icon only (`→` via `ArrowRight` lucide icon, `h-4 w-4`) | Inline with each row; no text label needed — space is tight |
| Empty state heading | "No listings with location data" | Shown when `coordinates.length === 0` after a successful fetch |
| Empty state body | "Location data isn't available for the listings in this group yet." | No next-step action — this resolves automatically as geocoding runs |
| API key missing (dev only) | "Google Maps API key not configured" | Single line, `text-sm text-muted-foreground`; only shown in development when `VITE_GOOGLE_MAPS_API_KEY` is unset |
| Loading state | No text — spinner only | Matches `DashboardLoading.tsx` established pattern |
| Error state heading | "Couldn't load map" | Plain language |
| Error state body | "Location data failed to load. Try refreshing the page." | Problem + next step |

No destructive actions in this phase. No confirmation dialogs required.

## States Inventory

Every visual state the map panel must handle:

| State | Trigger | Visual |
|-------|---------|--------|
| Loading | `coordinatesQuery.isLoading === true` | `h-96` container with centered `Loader2` spinner |
| Error | `coordinatesQuery.isError === true` | `h-96` container with `MapPin` icon + error copy |
| Empty (no coords) | `coordinates.length === 0` after success | `h-96` dashed border container with `MapPin` icon + empty state copy |
| API key missing | `VITE_GOOGLE_MAPS_API_KEY` is empty string | `h-96` dashed border container with single-line developer message |
| Loaded — pins visible | `coordinates.length > 0` | Full Google Map with `AdvancedMarker` pins |
| Pin selected | User clicked a single pin | `InfoWindow` popup anchored above clicked pin |
| Cluster selected (zoom < 19) | User clicked cluster | Default zoom-in behavior via `defaultOnClusterClickHandler` |
| Cluster selected (max zoom) | User clicked cluster at zoom >= 19 | Multi-listing `InfoWindow` at cluster position |
| Filter refetch | Filter state changed, query refetching | Existing pins remain visible (`keepPreviousData: true`); no spinner overlay |
