## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → local node_modules | Tarball integrity verified by `package-lock.json` `integrity` hash |
| Browser bundle → Google Maps API | Outbound HTTPS calls from end-user browsers carry the API key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03-01 | Tampering | Supply chain (npm install) | mitigate | Pin to exact versions (1.8.3 and 2.6.2); `package-lock.json` records SHA-512 integrity hashes; subsequent `npm ci` will refuse mismatched tarballs. Both packages are from well-known publishers (visgl, googlemaps). |
| T-09-03-02 | Spoofing | API key abuse (key extracted from JS bundle) | mitigate | Mitigation is documented in `user_setup.dashboard_config[1]` — restrict the key to HTTP referrers in Google Cloud Console. The key being in the bundle is by design for `VITE_` prefixed vars; referrer restriction is the standard GCP control. |
| T-09-03-03 | Information Disclosure | .env.example committed value | accept | Placeholder string `your-google-maps-api-key` is non-functional; no real credential is committed. Standard pattern matches existing entries. |
| T-09-03-04 | Denial of Service | Google Maps API quota | accept | Map only loads on the group dashboard for authenticated users; quota abuse requires logged-in brokerage members. If quota is hit, the map panel renders with the library's default "quota exceeded" tile — does not crash the dashboard. |
</threat_model>
