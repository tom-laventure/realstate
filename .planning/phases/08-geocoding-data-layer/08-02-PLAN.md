**File 1 - Create `backend/app/services/geocoding_service.rb` with EXACTLY this content:**

```ruby
class GeocodingService
  Result = Struct.new(:success, :latitude, :longitude, :error, keyword_init: true) do
    def success? = success
  end

  def initialize(address)
    @address = address
  end

  def call
    return Result.new(success: false, error: "No address") if @address.blank?

    response = HTTParty.get(
      "https://nominatim.openstreetmap.org/search",
      query: {format: "json", limit: 1, q: @address},
      headers: {"User-Agent" => ENV.fetch("NOMINATIM_USER_AGENT")},
      timeout: 10
    )

    return Result.new(success: false, error: "HTTP #{response.code}") unless response.success?

    results = response.parsed_response
    return Result.new(success: false, error: "No results") if results.blank?

    first = results.first
    Result.new(
      success: true,
      latitude: first["lat"].to_d,
      longitude: first["lon"].to_d,
      error: nil
    )
  rescue HTTParty::Error, Net::OpenTimeout, Net::ReadTimeout => e
    Result.new(success: false, error: e.message)
  end
end
```

Concrete values / non-negotiables (per CONTEXT.md and RESEARCH.md pitfalls):
- `ENV.fetch("NOMINATIM_USER_AGENT")` - NOT `ENV[...]` (silent nil). Fails loud at runtime if not configured (project convention from CalendarSyncJob).
- Nominatim response fields: `"lat"` and `"lon"` - three letters each, NOT `"latitude"`/`"longitude"`/`"lng"` (Common Pitfall 2 from RESEARCH.md).
- `.to_d` (BigDecimal), NOT `.to_f` - matches `decimal(10,6)` column type without precision loss.
- Empty array check uses `.blank?` to also handle `nil` from `parsed_response` (defensive).
- Rescue `HTTParty::Error, Net::OpenTimeout, Net::ReadTimeout` - same trio as RetsAuthService. Do NOT rescue `StandardError` (let unexpected bugs propagate).
- Inline hash literals follow standardrb style: `{format: "json", ...}` (no whitespace inside braces - standardrb-enforced; matches RetsAuthService's `basic_auth: {username: @username, password: @password}`).

**Deterministic-implementation note (Open Questions §1 RESOLVED):** `after_discard` is part of ActiveJob's official public API (Rails 7.x, defined in `ActiveJob::Exceptions`). SolidQueue is a thin queue adapter — it invokes the standard ActiveJob lifecycle synchronously inside its worker, so `after_discard` runs in-process whenever `retry_on` exhausts its attempts. The implementation below uses `after_discard` as the canonical mechanism (not a workaround) and Test 8 fires the callback chain via Rails 7.1's `run_callbacks(:discard)` to deterministically prove the wiring is correct, independent of the SolidQueue runtime. The acceptance criteria below grep for the exact block header to guarantee the deterministic implementation lands in the committed file.

**File 1 - Create `backend/app/jobs/geocode_listings_job.rb` with EXACTLY this content:**

```ruby
class GeocodeListingsJob < ApplicationJob
  queue_as :default
  retry_on StandardError, wait: :polynomially_longer, attempts: 3
  discard_on ActiveRecord::RecordNotFound

  after_discard do |job, _exception|
    estate_id = job.arguments.first
    estate = Estate.without_deleted.includes(:listing_detail).find_by(id: estate_id)
    estate&.listing_detail&.update_columns(geocoding_failed: true)
  end

  def perform(estate_id)
    estate = Estate.without_deleted.includes(:listing_detail).find(estate_id)
    listing_detail = estate.listing_detail

    return if listing_detail.nil?
    return if listing_detail.latitude.present?
    return if listing_detail.geocoding_failed?
    return if listing_detail.address.blank?

    result = GeocodingService.new(listing_detail.address).call

    if result.success?
      listing_detail.update!(
        latitude: result.latitude,
        longitude: result.longitude
      )
    end

    sleep(1) unless Rails.env.test?
  end
end
```

Concrete values / non-negotiables:
- `queue_as :default` - D-11 (same queue as CalendarSyncJob). NOT `:photos` (that's SyncListingPhotosJob's queue).
- `retry_on StandardError, wait: :polynomially_longer, attempts: 3` - D-09. Exact same form as SyncListingPhotosJob line 3.
- `discard_on ActiveRecord::RecordNotFound` - line 4 of SyncListingPhotosJob. Handles soft-deleted estates cleanly.
- `after_discard do |job, _exception|` - **deterministic failure-flag mechanism per Open Questions (RESOLVED) §1.** Fires AFTER 3 retries exhaust, via ActiveJob's public discard lifecycle (not a custom workaround). `_exception` underscored to silence standardrb unused-arg warning. Inside: `find_by(id:)` not `find` - soft-deleted estate yields nil, safe-navigation handles it. The block must be present verbatim — Test 8 + the grep acceptance criterion below verify it.
- `update_columns(geocoding_failed: true)` (not `update!`) - skips validations/callbacks, guarantees the flag sticks even if a future validation would block.
- Single-arg `perform(estate_id)` - D-08. NO brokerage_id (geocoding is a per-listing operation; rake task does not have brokerage context).
- Four guard returns in order: nil listing_detail, latitude present (already geocoded), geocoding_failed (previously hopeless), blank address. Same ordering as SyncListingPhotosJob's guard cascade.
- `sleep(1) unless Rails.env.test?` - the sleep is the Nominatim rate-limit guard (D-08, 1 req/sec). Skip in test env so test suite runs fast. Production rate limiting preserved.
- Do NOT rescue StandardError inside perform - would defeat retry_on (Common Pitfall 1 from RESEARCH.md) AND would short-circuit the after_discard callback chain, breaking the deterministic failure-flag mechanism.

```ruby
namespace :geocode do
  desc "Enqueue GeocodeListingsJob for all listings with an address but no coordinates"
  task backfill: :environment do
    scope = ListingDetail
      .joins(:estate)
      .where(latitude: nil)
      .where.not(address: [nil, ""])
      .where(geocoding_failed: false)
      .where(estates: {deleted_at: nil})
      .select(:id, :estate_id)

    count = 0
    scope.find_each do |ld|
      GeocodeListingsJob.perform_later(ld.estate_id)
      count += 1
    end

    puts "Enqueued #{count} GeocodeListingsJob(s)"
  end
end
```

Concrete values / non-negotiables (per D-10 and RESEARCH.md Pitfall 5):

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Job worker -> Nominatim API | Outbound HTTPS request from Rails to a third-party public geocoding service |
| Operator shell -> rake task | A human or scheduled task triggers `rake geocode:backfill`, which enqueues many jobs |
| Job worker -> DB | `GeocodeListingsJob` writes lat/lng (via `update!`) and `geocoding_failed` (via `update_columns` in after_discard) to `listing_details` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-02-01 | Information Disclosure | Address string sent to third-party Nominatim API | accept | Listing addresses are intrinsic to MLS data already public via real-estate listings; transmitting to OSM for geocoding is the explicit feature requirement (MAP-01). No PII (no buyer/seller names, no agent contact info) is transmitted. The User-Agent header reveals the application identity per Nominatim usage policy - that is required, not a leak. |
| T-08-02-02 | Spoofing | Missing `NOMINATIM_USER_AGENT` env var leads to default User-Agent which may be blocked by OSM | mitigate | `ENV.fetch("NOMINATIM_USER_AGENT")` raises `KeyError` at runtime, failing loud before any HTTP call. Operator must configure the env var before running the rake task. This is documented in `user_setup`. |
| T-08-02-03 | Denial of Service | Bulk backfill exceeds Nominatim 1 req/sec rate limit, gets IP-banned | mitigate | `sleep(1)` in `GeocodeListingsJob#perform` enforces 1 req/sec per worker thread. SolidQueue `:default` queue has 3 threads (per `config/solid_queue.yml`) - combined throughput is ~3 req/sec, slightly above the 1 req/sec policy. | T-08-02-04 | Denial of Service | Hopeless addresses retried indefinitely, exhausting job queue | mitigate | `geocoding_failed: true` flag (set via `after_discard` after 3 retries exhaust) prevents re-enqueuing. | T-08-02-05 | Tampering | Job swallows StandardError inside `perform`, masking real errors | mitigate | No `rescue StandardError` inside `perform` body. | T-08-02-06 | Elevation of Privilege | Operator who can run `rake geocode:backfill` could enqueue arbitrary jobs | accept | Rake tasks run with full Rails privileges. Standard Rails operational threat model; no specific mitigation needed for this task. |
