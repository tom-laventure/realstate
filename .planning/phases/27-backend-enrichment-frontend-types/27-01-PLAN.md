Exact replacement for the `index` method:

```ruby
def index
  admin_memberships = BrokerageMembership
    .without_deleted
    .includes(:brokerage)
    .where(user_id: Current.user.id, role: %w[admin owner])

  brokerage_ids = admin_memberships.filter_map(&:brokerage_id)

  return render json: { admin_brokerages: [] } if brokerage_ids.empty?

  all_memberships = BrokerageMembership
    .without_deleted
    .includes(:user)
    .where(brokerage_id: brokerage_ids)

  memberships_by_brokerage = all_memberships.group_by(&:brokerage_id)
  member_roles = %w[agent staff owner admin]

  render json: {
    admin_brokerages: admin_memberships.filter_map { |m|
      next if m.brokerage.nil?
      group = memberships_by_brokerage[m.brokerage_id] || []
      {
        id: m.brokerage.id,
        name: m.brokerage.name,
        role: m.role,
        client_count: group.count { |r| r.role == "client" },
        member_count: group.count { |r| member_roles.include?(r.role) },
        owners: group
          .select { |r| r.role == "owner" }
          .map { |r| { first_name: r.user.first_name, last_name: r.user.last_name } }
      }
    }
  }
end
```

Implementation notes:
- `brokerage_ids` uses `filter_map(&:brokerage_id)` (not `.map`) — drops nil IDs defensively
- Early return `if brokerage_ids.empty?` prevents full-table scan (Pitfall 3 from RESEARCH.md)
- Second query uses `.without_deleted` (mandatory per D-04 and CLAUDE.md)
- Second query uses `.includes(:user)` to avoid N+1 on `r.user.first_name` / `r.user.last_name` (Pitfall 1 from RESEARCH.md)
- `member_roles` variable declared outside `filter_map` so it is not re-created per iteration
- `owners` returns `[]` when no owner memberships exist for a brokerage (D-06)
- No serializer — inline hash per Claude's Discretion decision
- Role values are double-quoted strings to match Ruby convention in this file
