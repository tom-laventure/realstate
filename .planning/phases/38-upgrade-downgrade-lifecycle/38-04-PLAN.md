<objective>
Enforce the runtime consequences of a downgrade: (1) a suspended client membership is rejected outright at the brokerage-auth layer with a 403 on every authenticated request (D-09), not just hidden from scoped queries; (2) suspended board credentials become fully invisible in the member-visible board list (D-07), so the board-connect UI reverts to Free-tier (TEST-only) behavior with no distinct "suspended" indicator; and (3) suspended credentials are also immutable — an admin cannot reactivate or disconnect one via `update`/`destroy`, because a suspended row behaves as if it never existed (D-07), returning 404.

Purpose: Suspending records (Plan 03) is meaningless unless suspended clients are actually blocked, suspended credentials actually disappear, AND the freeze cannot be trivially undone with a plain PATCH. These are the enforcement points.
Output: Two modified files, two tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client request → brokerage-scoped API | A suspended client must not reach any authenticated endpoint; the auth concern is the single enforcement point |
| API response → board-connect UI | Suspended credentials must not leak into member-visible board lists |
| Admin write request → suspended credential | A suspended credential must not be reactivatable via `update` or disconnectable via `destroy` — it must behave as nonexistent (D-07), because owner/admin/agent callers are never themselves suspended (D-10) and would otherwise bypass the freeze |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-03 | Elevation of Privilege | Suspended client still accessing brokerage endpoints | mitigate | Request-level 403 in `CognitoAuth#authenticate_cognito_user!` (D-09) — rejection before any controller action runs, not a query filter; integration test asserts the 403 |
| T-38-04 | Information Disclosure | Suspended credentials leaking into board list / a "suspended" hint | mitigate | `index` excludes `status: "suspended"` and no serializer field exposes suspended state (D-07); controller test asserts absence |
| T-38-10 | Elevation of Privilege / Tampering | `board_credentials_controller#update` (and `#destroy`) reactivating/mutating a suspended credential to bypass the freeze | mitigate | `update`/`destroy` lookups add `.where.not(status: "suspended")` so a suspended row 404s before any `assign_attributes` — same-as-nonexistent (D-07); controller test asserts a suspended credential cannot be PATCHed back to `"active"` |
| T-38-09 | Spoofing / Repudiation | Ambiguous 403 (suspended vs non-member) | accept | Distinct error messages are intentional for support triage; both are 403 with `next_step: "no-access"`, no sensitive detail leaked |
| T-38-SC | Tampering | Package installs | accept | No new packages — controller/concern edits only |
