    Create `TestBoardPurgeService` with a single public class method `self.call!(brokerage:)` following `GroupCreationService`'s class-method + helper shape. Implement this exact traversal (per RESEARCH.md Pattern 2, verified associations):
    1. `test_board_ids = RealEstateBoard.test_boards.pluck(:id)`; `estate_ids = Estate.without_deleted.where(real_estate_board_id: test_board_ids).pluck(:id)`. If `estate_ids` is empty, return early (natural idempotency per D-12 — nothing to purge).
    2. `group_ids = brokerage.groups.without_deleted.pluck(:id)` (explicit `.without_deleted` — `Group` is `acts_as_paranoid` and CLAUDE.md forbids relying on the default scope for paranoid models). Capture `estate_date_ids = EstateDate.without_deleted.joins(:group_estate).where(group_estates: {group_id: group_ids, estate_id: estate_ids, deleted_at: nil}).pluck(:id)` BEFORE deleting, so the calendar-event cleanup below can target them. Note the explicit `deleted_at: nil` on the joined `group_estates` table — `GroupEstate` is also `acts_as_paranoid`, and per CLAUDE.md's multi-model join-guard rule every joined paranoid model must be guarded explicitly, not just the primary `EstateDate`.
    3. Hard-delete the join rows: `BrokerageEstate.where(brokerage_id: brokerage.id, estate_id: estate_ids).delete_all` — plain join table, no children, no acts_as_paranoid, so `delete_all` is safe.
    4. Cascade the group-scoped tree: `GroupEstate.without_deleted.where(group_id: group_ids, estate_id: estate_ids).find_each { |ge| ge.really_destroy! }`. Use `really_destroy!` (paranoia), NOT `destroy`/`destroy_all` (which soft-delete under acts_as_paranoid) and NOT raw `delete_all` (which would raise a Postgres FK violation on subcomments and orphan RSVPs). `really_destroy!` fires the Ruby `dependent: :destroy` chain, correctly cascading through comments→subcomments and dates→rsvps.
    5. Defensive orphan cleanup (RESEARCH.md Open Q3): `EstateDateCalendarEvent.where(estate_date_id: estate_date_ids).delete_all` — these rows have no FK to estate_dates and are not covered by dependent:destroy, so they must be removed explicitly.
    Wrap steps 3–5 in an `ActiveRecord::Base.transaction` (step 2's plucks may stay outside). Do NOT scope the purge to anything other than TEST boards AND this brokerage's own groups/estates — real-board data and other brokerages' data must never be reachable by this query.
    Do NOT emit any notice/email — D-13 requires the purge be silent.
