From frontend/src/components/common/guards/RequireRole.tsx:
```tsx
interface RequireRoleProps {
    roles: UserRole[]
    redirectTo?: string
    children: ReactNode
}

const RequireRole = ({ roles, redirectTo = '/', children }: RequireRoleProps) => {
    const { role, isUserLoaded } = useRole()
    if (!isUserLoaded) return null
    if (!role || !roles.includes(role)) {
        return <Navigate to={redirectTo} replace />
    }
    return <>{children}</>
}
```

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser -> `/admin/*` routes | `RequireRole` in `admin.tsx` is a client-side UX gate only — the real boundary is Phase 30's backend `require_agent_or_above!`/`require_admin!` enforcement on each controller action |
| Browser -> Domain mutation buttons | `<Can permission="manage_brokerage_settings">` hides the button; if bypassed client-side, the backend's `domains#verify`/`domains#set_primary` endpoints remain the actual authorization boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-01-01 | Elevation of Privilege | `admin.tsx` route gating is cosmetic, not a security boundary | accept | Opening `readTierRoles` to agent grants no new backend capability — Phase 30 already returns 2xx for agent on every read endpoint behind these routes and 403 on every write endpoint. This plan only makes the frontend route reachable where the backend was already permissive. |
| T-32-01-02 | Elevation of Privilege | `DomainCard.tsx`'s "Verify now" button re-triggers backend DNS verification (`domains#verify`), which Phase 30 RBAC-02 already permits for agent | accept | ACCESS-05/ACCESS-08 treat this as a UX concern (agent should not see a mutation-shaped control at all), not a security gap — hiding the button does not change what the backend allows; the backend remaining permissive here was an explicit Phase 30 decision, not a bug this plan fixes. |
| T-32-01-03 | Tampering | Client could bypass `RequireRole` by manipulating Redux state directly (dev tools) to force `role: 'owner'` | accept | Even with a spoofed client-side role, every write action still routes through Phase 30's backend RBAC — the route-gate bypass carries no privilege with it, only visual access to already-read-permitted data. |
