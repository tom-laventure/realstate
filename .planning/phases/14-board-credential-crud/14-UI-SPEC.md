## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), icon internal padding |
| sm | 8px | Compact element spacing (`p-2`, `gap-2`) |
| md | 16px | Default element spacing (`space-y-4`, `px-4`, `gap-4`) |
| lg | 24px | Section padding (`py-6`, `gap-6`) |

| 2xl | 48px | Major section breaks |

- Touch target for the `⋯` ghost icon button: minimum 44px × 44px (WCAG 2.5.5 AAA recommendation). Achieve via `h-8 w-8` button with `p-0` and the parent row's `items-center` providing vertical stretch, or use `size-8` variant — executor must verify click target area.

## Color

All colors are resolved via CSS custom properties defined in `src/index.css` (:root, zinc base, oklch scale). No hardcoded hex/rgb values permitted except for the semantic status badges below.

| Role | CSS Variable | Usage |
|------|-------------|-------|
| Dominant (60%) | `--background` (oklch 1 0 0 — white) | Page background, card background |
| Secondary (30%) | `--card` / `--muted` | Card surfaces, table header row |
| Accent (10%) | `--primary` (oklch 0.21 — near-black) | Primary Button fill, focus ring |
| Destructive | `--destructive` (oklch 0.577 0.245 27 — red) | Delete AlertDialog button, destructive Badge variant |

**Accent reserved for:** Primary action Button (Connect Board, Save Changes, Re-verify connection, Delete in AlertDialog). NOT for informational elements, row actions, or hover states.

**Semantic status colors (carried from existing BoardRegistrations):**
- Active badge: `bg-green-100 text-green-800` — do not change
- Invalid badge: `variant="destructive"` — do not change
- Info notice (blue): `border-blue-200 bg-blue-50 text-blue-800` — mirror exactly from ConnectBoardDialog test-board-info step

**Destructive confirmation button:** Use `variant="destructive"` from shadcn Button — resolves to `--destructive` background automatically.

## Interaction Contracts

### 1. Row Actions Dropdown (MoreHorizontal)

**Trigger:** Ghost icon button (`variant="ghost"`, `size="icon"`) containing `MoreHorizontal` (16px, `h-4 w-4`) from lucide-react. Right-aligned in the Actions column cell (`flex justify-end`).

**Guard:** Entire actions cell wrapped in `<Can permission="manage_brokerage_settings">`. When permission absent, cell renders empty (preserving grid column alignment — render `<span />` not null to maintain `grid-cols-5`).

**Dropdown items:**
1. `Edit credentials` — opens `EditBoardCredentialDialog` for the row's credential
2. `Delete connection` — opens AlertDialog for the row's credential

**Dropdown alignment:** `align="end"` on `DropdownMenuContent`.

**Keyboard:** DropdownMenu is Radix-based; arrow key navigation and Enter/Space activation handled by Radix automatically.

---

### 2. EditBoardCredentialDialog

**Trigger:** "Edit credentials" dropdown item.

**Dialog width:** `sm:max-w-md` — matches ConnectBoardDialog exactly.

**State machine:**

```
idle → submitting → success (toast) | error (inline)
```

No multi-step — single view, no step transitions.

**Test board path** (credential.realEstateBoard.isTestBoard === true):
- DialogTitle: "Edit Board Connection"
- DialogDescription: "Manage connection to [Board Name]."
- Blue info notice (identical markup to ConnectBoardDialog test-board-info step):
  ```
  rounded-md border border-blue-200 bg-blue-50 px-4 py-2 text-xs text-blue-800 flex items-start gap-2
  ```
  Notice text: "Test board — no credentials required."
- No username/password inputs rendered.
- Submit button label: "Re-verify connection"
- Submit disabled while `isSubmitting`.
- On success: dialog closes + `toast.success("Board connection verified.")`.

**Real board path** (isTestBoard === false):
- DialogTitle: "Edit Board Connection"
- DialogDescription: "Re-enter RETS credentials for [Board Name]."
- RETS Username field: `Label` + `Input` (id="edit-rets-username"), placeholder "Enter your RETS username", autoComplete="off"
- RETS Password field: `Label` + `Input` (id="edit-rets-password", type="password"), placeholder "Enter your RETS password", autoComplete="new-password"
- Submit disabled when `isSubmitting || !username || !password`.
- Submit button label: "Save credentials"
- On success: dialog closes + `toast.success("Board credentials updated.")`.

**Error state (both paths):**
- Inline below form fields / notice: `<p className="text-sm text-destructive">{serverError}</p>`
- Error cleared on each new submit attempt.

**Dialog reset on close:** clear username, password, serverError, isSubmitting — identical reset pattern to ConnectBoardDialog `handleOpenChange`.

**Footer layout:** `flex items-center justify-end` (no back button — single step). For real board, submit button is right-aligned. For test board, same.

---

### 3. Delete AlertDialog

**Trigger:** "Delete connection" dropdown item.

**Component:** shadcn `AlertDialog` (not `Dialog` — semantically distinct for destructive confirmation).

**Copy:**
- AlertDialogTitle: "Delete [Board Name] connection?"
- AlertDialogDescription: "This cannot be undone."

**Footer buttons (left to right):**
1. `AlertDialogCancel`: "Cancel" — `variant` default (resolves to outlined/secondary visually via shadcn AlertDialogCancel)
2. `AlertDialogAction`: "Delete" — render as `<AlertDialogAction asChild><Button variant="destructive">Delete</Button></AlertDialogAction>` to apply destructive color

**Loading state:** AlertDialog does not show spinner — fire-and-forget on confirm. If delete fails, `toast.error("Failed to disconnect board. Please try again.")` is shown. AlertDialog closes immediately on confirm (optimistic UX, matching established delete patterns in groups_controller).

## Accessibility Contract

- `MoreHorizontal` ghost button: `aria-label="Row actions for [Board Name]"` (dynamic). Provides screen reader context since button has no visible text label.
- AlertDialog: Radix handles focus trap, aria-modal, role="alertdialog", aria-labelledby, aria-describedby automatically.
- Dialog (EditBoardCredentialDialog): Radix handles focus trap, aria-modal automatically. Set `autoFocus` on first input (username for real board, submit button for test board).
- Delete confirm button: As `AlertDialogAction`, receives role="button" from Radix. No additional aria attributes needed.
- Status badges in the existing table: no change (existing implementation is correct).
