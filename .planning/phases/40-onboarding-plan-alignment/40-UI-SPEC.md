| 3xl | 64px | (available, not used by this phase's two screens) |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display | 24px (`text-2xl`) | 600 semibold | 1.2 — page heading ("Choose your plan", "Set up your domain") |
| Heading | 18px (`text-lg`) | 600 semibold | 1.3 — card titles (Free / Independent / Growth), `CardTitle` |
| Body | 14px (`text-sm`) | 400 regular | 1.5 — descriptions, feature list bullets, toggle option copy, subheader text |
| Label | 14px (`text-sm`) | 500 medium | 1.4 — field labels and radio-option text via shadcn `Label` primitive (500 is the primitive's built-in default across the whole design system, not a weight introduced by this phase — declared as a pre-existing exception to the 2-weight rule below) |
| Caption | 12px (`text-xs`) | 400 regular | 1.4 — inline availability/error status ("Checking availability…", "This subdomain is already taken"), price-per-month sub-label if shown under the display price |

**Phase-introduced weights (2 max, per contract rule):** regular (400) and semibold (600). The 500-weight `Label` primitive is inherited from the existing design system and is not a new weight this phase adds.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` — `oklch(1 0 0)` (white, light mode) | Page background, card surfaces (`Card` component) |
| Secondary (30%) | `--secondary` / `--muted` — `oklch(0.967 0.001 286.375)` (light zinc) | `Badge variant="secondary"`, muted description/helper text (`text-muted-foreground`), unselected feature-list icon tint (`text-muted-foreground/40`) |
| Accent (10%) | `--primary` — `oklch(0.21 0.006 285.885)` (near-black, light mode) | Reserved for: the "Recommended" badge fill on the Growth card, the Growth card's `border-primary` highlight ring, the primary CTA button on the recommended card ("Select Growth"), the final "Create brokerage" submit button, the checkmark icon color on *included* feature-list rows, the selected `RadioGroupItem` fill/border on the custom-domain-ownership toggle, and default focus rings |
| Destructive | `--destructive` — `oklch(0.577 0.245 27.325)` (red) | Inline validation errors only: subdomain/custom-domain-taken messages, invalid-domain-format message. No destructive *actions* (button/confirmation) exist in this phase |

Accent reserved for: Recommended badge + card border, recommended-tier CTA button, final submit CTA, included-feature checkmarks, selected radio indicator, focus rings. Never applied to plain body text, unselected cards, or non-recommended CTA buttons (those use `variant="outline"`, per existing `PlanCard.tsx`).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (plan card) | `Select {Tier}` — e.g. "Select Free", "Select Independent", "Select Growth" (existing `PlanCard.tsx` pattern, unchanged template) |
| Primary CTA (final step) | `Create brokerage` (existing `DomainStep.tsx` submit button, unchanged) |
| Empty state | Not applicable — `GET /v1/onboarding/plan_tiers` always returns exactly 3 fixed tiers (`free`/`independent`/`growth`); a response with zero tiers is a backend/network failure and must be treated as the Error state below, not rendered as an empty-state UI |
| Error state (plan-tiers fetch) | Heading: "Couldn't load plan details" — Body: "We couldn't load pricing information. Check your connection and try again." — action: "Retry" button that refetches `useFetchPlanTiers` |
| Error state (submission, existing — unchanged) | Inline field errors: "This subdomain is already taken", "Enter a valid domain name (e.g., yourbrokerage.com)", "This domain is already registered" — surfaced under the relevant field, not as a page-level banner |
| Destructive confirmation | None in this phase — no destructive actions exist in the onboarding wizard's plan/domain steps (downgrade confirmation copy is Phase 41 scope, out of bounds here) |

### Custom-domain-ownership toggle content (ONB-06/D-05 — Claude's discretion wording, delegated by user)

Shown only when `plan !== 'free'`, replacing the old `isPremium`-gated required field:

| Element | Copy |
|---------|------|
| Toggle question (Label, above `RadioGroup`) | "Do you currently own a custom domain?" |
| Subheader (always visible under the question, for both Yes/No states) | "You can register one through providers like GoDaddy, Namecheap, or Google Domains." |
| Radio option: Yes | "Yes, I own one" — reveals the existing custom domain `Input` (still optional to fill in) |
| Radio option: No (default on first render) | "No, not yet" — hides the input |
| Reassurance line (shown when "No" selected) | "That's alright — you can add a custom domain anytime from Settings." |
| Input helper text (unchanged, existing copy, shown only when "Yes" selected and input visible) | "You'll set up DNS records on the next screen. Domain verification can be done from admin settings after sign-up." |

Default toggle state: **No / collapsed** (per CONTEXT.md's Claude's Discretion recommendation — most signups won't have a domain ready).

### Loading state (new — plan-tiers fetch, Pitfall 3)

No `skeleton.tsx` primitive exists in this codebase (verified — not present in `components/ui/`). Do not introduce one for a single call site. Use the existing spinner convention instead (`Loader2` from `lucide-react`, `animate-spin`, already used identically in `SuccessStep.tsx` and `RemoveOwnerDialog.tsx`):

- Centered below the page heading, replacing the 3-card grid while `useFetchPlanTiers().isLoading` is true: `<Loader2 className="h-5 w-5 animate-spin" /> Loading plan details…`
