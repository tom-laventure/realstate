## Spacing Scale

Declared values (multiples of 4 only — Tailwind utility class mapping shown):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | gap-1 / p-1 | Icon gaps, badge internal padding |
| sm | 8px | gap-2 / p-2 | Inline element spacing, button icon gap |
| md | 16px | gap-4 / p-4 | Default element spacing, form field gap |
| lg | 24px | p-6 | Page padding, section padding (matches existing `p-6`) |
| xl | 32px | mt-8 | Between major card sections |
| 2xl | 48px | — | Reserved for future page-level breaks |
| 3xl | 64px | — | Reserved for future layout gaps |

Declared exceptions (non-multiples-of-4 matching existing codebase patterns):

| Value | Tailwind | Usage |
|-------|----------|-------|
| 12px | space-y-3 | Card list item gap — matches existing CustomDomainList `space-y-3` pattern |
| 20px | p-5 | Card internal padding — matches existing DomainCard `p-5` pattern |

Section gap: `mb-6` (24px) — matches existing DomainsAdminView header pattern.

Exceptions:
- Tooltip touch target minimum: 44px height on interactive tooltip triggers.
- Wizard step dots: 8px diameter circles, 8px gap between them.

System font stack inherited from `body` in `index.css`. No custom font loaded in this phase.

| Role | Size | Tailwind | Weight | Tailwind | Line Height |
|------|------|----------|--------|----------|-------------|
| Body | 14px | text-sm | 400 (regular) | font-normal | 1.5 (leading-normal) |

- Wizard step labels: `text-sm font-semibold`.
- Code/monospace blocks (CNAME record): `font-mono text-sm` with `bg-muted rounded-md p-3`.

## Card Status Variants

### Subdomain Card

- Lock icon (`Lock` size-4) inline before domain name, `text-muted-foreground`.
- shadcn `Tooltip`: trigger = Lock icon, content = "This domain is permanent and was assigned at registration."
- Type badge: Subdomain.
- Status badge: Active (always active; subdomain cannot phase out).
- Primary badge: shown if `domain.isPrimary`.
- Status description: "Your permanent brokerage subdomain."
- No verification meta (subdomains are not DNS-verified).
- Actions (Owner only): "Set as primary" button (`variant="default"`, `size="sm"`) — only if not already primary.
- Actions (Admin): read-only, no buttons.
- Actions (below Admin): read-only, no buttons.

### Active Custom Domain Card

- No lock icon.
- Type badge: Custom Domain.
- Status badge: Active.
- Primary badge: shown if `domain.isPrimary`.
- Status description: "Verified and serving traffic."
- Meta: "Last checked: {relative time}" — e.g. "Last checked: 3 minutes ago" using dayjs.
- Actions (Owner only): "Set as primary" (`variant="default"`, `size="sm"`) if not primary; "Delete" (`variant="outline"`, `size="sm"`).
- Actions (Admin): read-only.
- Actions (below Admin): read-only.

### Pending Custom Domain Card

- Type badge: Custom Domain.
- Status badge: Pending Verification.
- No Primary badge (pending domains cannot be primary — DPRI-02).
- Status description: "Waiting for DNS verification. CNAME must resolve before this domain goes live."
- Meta: "Last checked: {relative time or 'Not yet checked'}" — use `domain.lastCheckedAt`.
- Failure reason (shown only if `domain.consecutiveFailures > 0`): text-xs text-destructive — e.g. "CNAME record not detected."
- Auto-expiry note: "Unverified domains are removed after 7 days." — text-xs text-muted-foreground.
- Actions (Owner + Admin): "Verify now" button (`variant="default"`, `size="sm"`, with `Loader2` spinner while loading).
- Actions (Owner only): also "Delete" (`variant="outline"`, `size="sm"`).
- Actions (below Admin): read-only.

### Phasing Out Custom Domain Card

- Type badge: Custom Domain.
- Status badge: Phasing Out.
- No Primary badge.
- Status description: "DNS check failed. This domain will be decommissioned unless CNAME is restored."
- Meta: decommission countdown — e.g. "14 days remaining · decommissions Jun 15" (reuse `formatCountdown` from existing DomainCard).
- Last-checked meta: "Last checked: {relative time}" on separate line.
- Failure reason (if present): text-xs text-destructive.
- Actions (Owner + Admin): "Verify now" button (`variant="default"`, `size="sm"`, with spinner while loading).
- Actions (Owner only): also "Delete" (`variant="outline"`, `size="sm"`).
- Actions (below Admin): read-only.

### Frozen Custom Domain Card

- Type badge: Custom Domain.
- Status badge: Frozen.
- No Primary badge, no verify/delete actions of any kind.
- Status description: "This domain is inactive due to your current plan."
- Re-upgrade CTA: `Button` with `variant="outline"` `size="sm"` and `ExternalLink` icon — label "Upgrade plan". This button navigates to the plan upgrade page (no mutation).
- No action controls for any role.
- No last-checked meta (frozen domains are not actively checked).

## Add Domain Wizard (4-Step Dialog)

Triggered by "Add domain" button (Owner only).

Dialog: `Dialog` (not `AlertDialog`). `DialogContent` with `max-w-md` or `sm:max-w-md`. Dismissible with Escape or outside click. State resets on close (D-02).

### Step Indicator

4 dots displayed horizontally, centered, below the dialog title.
- Active step: filled circle `w-2 h-2 rounded-full bg-primary`.
- Completed step: filled circle `w-2 h-2 rounded-full bg-primary/40`.
- Upcoming step: hollow circle `w-2 h-2 rounded-full border border-border`.
- Gap between dots: `gap-2`.
- Located inside DialogHeader, below DialogDescription.

### Step 1: Enter Domain

- DialogTitle: "Add a custom domain"
- DialogDescription: "Enter the domain you want to connect to your brokerage."
- Form: `Label` ("Domain") + `Input` (type="text", placeholder="yourdomain.com", autoFocus).
- Validation: non-empty, basic domain format (no protocol prefix), not a reserved slug. Show `text-xs text-destructive` below input on error.
- Footer: `Button` "Next: DNS Setup" (`variant="default"`) — disabled if input invalid. `Button` "Discard" (`variant="ghost"`) — closes dialog.

### Step 2: DNS Instructions

- DialogTitle: "Configure your DNS"
- DialogDescription: "Add the following CNAME record to your DNS provider. Verification may take up to 24 hours."
- CNAME record display block:
  ```
  ┌─ bg-muted rounded-md p-3 space-y-2 ─────────────────┐
  │  Type   CNAME                                        │
  │  Name   {entered domain}                             │
  │  Value  {brokerage subdomain, e.g. abc.realstate.com}│
  └──────────────────────────────────────────────────────┘
  ```
  Each row: label `text-xs text-muted-foreground`, value `font-mono text-sm text-foreground`.
  Include a "Copy" button (`variant="ghost"` `size="sm"`) beside the Value row that copies the subdomain to clipboard. Show "Copied!" for 2 seconds after click.
- Footer: `Button` "Next: Primary" (`variant="default"`). `Button` "Back" (`variant="outline"`).

### Step 3: Primary Preference (conditional — only shown when another active domain exists, DADD-02)

- DialogTitle: "Set as primary?"
- DialogDescription: "The primary domain receives all traffic and is used in system emails. Currently: {current primary domain}."
- Two radio-style options (implement as two `Button` cards or two bordered divs with click handler, visually indicating selection):
  - Option A: "Yes, set as primary once verified" — selected by default if no other custom domain is active.
  - Option B: "No, keep {current primary} as primary" — default when another active domain already exists.
- Both options show a brief one-line description below the label: e.g. "Traffic and emails will switch once this domain is verified." / "This domain will go live but won't affect current traffic routing."
- Footer: `Button` "Next: Confirm" (`variant="default"`). `Button` "Back" (`variant="outline"`).

### Step 4: Confirm

- DialogTitle: "Ready to add {domain}?"
- DialogDescription: Summary of what will happen:
  - "Your domain will appear as Pending Verification immediately."
  - "Verification happens automatically every 30 minutes, or you can trigger it manually."
  - If primary preference = yes: "Once verified, this domain will become your primary."
- Footer: `Button` "Add domain" (`variant="default"`) — triggers `useAddCustomDomain` mutation. Shows `Loader2` spinner while loading. `Button` "Back" (`variant="outline"`).
- On success: dialog closes, toast "Domain added — verification pending", `queryClient.invalidateQueries({ queryKey: domainsKeys.all })` (D-03).

## Delete Domain Dialog

### Non-Primary Delete (DLCX-03)

Use existing `AlertDialog` pattern from `RemoveNowDialog.tsx`.

- AlertDialogTitle: "Delete {domain}?"
- AlertDialogDescription: "This domain will enter a phase-out period. It will be decommissioned on {formatted decommission date, e.g. 'Jun 15, 2026'}. Existing traffic will redirect to your primary domain."
- Footer: `AlertDialogCancel` "Keep domain". `AlertDialogAction` "Begin phase-out" with destructive classes (`bg-destructive text-destructive-foreground hover:bg-destructive/90`).

### Primary Domain Delete (DLCX-04, D-04)

Use `Dialog` (not `AlertDialog`) to allow the replacement Select inside.

- DialogTitle: "Choose a replacement primary domain"
- DialogDescription: "Before deleting {domain}, select which domain should become the new primary. Email links and redirects will update automatically."
- Replacement selector: `Select` component. Pre-selected: the brokerage subdomain (D-04). Lists all active non-primary domains (D-05). Label: "New primary domain".
- Decommission notice: `text-sm text-muted-foreground` — "{domain} will enter a {30}-day phase-out period and decommission on {date}."
- Footer: `Button` "Confirm deletion" (`variant="destructive"`) — disabled until replacement selected; triggers sequential calls (set_primary → destroy). `Button` "Discard" (`variant="ghost"`).
- Partial failure toast (D-06): "Domain deletion failed — {replacement} is now your primary domain." (`toast.error`).

## Verification Interactions

### "Verify now" Button

- Appears on: pending cards and phasing-out cards.
- Visible to: Owner + Admin roles.
- `Button size="sm" variant="default"` with `Loader2` spinner (`animate-spin`) replacing icon while `isVerifying` is true.
- Label: "Verify now" (idle) — no label change while loading (spinner replaces any leading icon).
- Disabled while `isVerifying`.
- On success — domain was already active or transitions pending → active: toast "Domain verified successfully" (existing hook behavior).
- On success — domain transitions phasing_out → active (rescue, D-11): toast "Domain rescued — phase-out has been cancelled" (D-12). Rescue detection: compare domain's pre-mutation status (pass `previousStatus` to hook or read from pre-mutation cache snapshot) against response domain.status.
- On failure: toast "DNS check failed — ensure your DNS records are set correctly" (existing hook behavior).
- Cache invalidated after any verify response via `domainsKeys.all`.

### Last-Checked Timestamp

- Format: relative using dayjs — "Last checked: 3 minutes ago" / "Last checked: 2 hours ago" / "Not yet checked".
- Position: below the status description line, above action row.
- Style: `text-xs text-muted-foreground`.
- Source: `domain.lastCheckedAt` (ISO string or null).

### Failure Reason

- Shown when: `domain.consecutiveFailures > 0` or a `failureReason` field is present on the domain.
- Text: plain-language message — "CNAME record not detected." The backend failure reason string is used directly if it exists, otherwise fall back to the generic message.
- Style: `text-xs text-destructive`.
- Position: below last-checked meta, above action row.

## Accessibility

- All interactive buttons have visible focus rings (shadcn default — do not override `focus-visible:ring-*`).
- Lock icon tooltip uses `TooltipProvider` wrapping the page; `TooltipTrigger asChild` wrapping the `Lock` icon button; `TooltipContent` for the label. Tooltip is keyboard accessible via focus.
- Wizard `DialogContent` traps focus; first focusable element (`Input` in step 1) receives `autoFocus`.
- `AlertDialog` for delete confirmations uses `AlertDialogAction` and `AlertDialogCancel` (correct ARIA roles).
- Domain URL text uses `title={domain.domain}` attribute for truncated values (screen reader and hover title).
- `Select` replacement dropdown in delete-primary dialog includes `Label` with `htmlFor` association.
- Destructive `AlertDialogAction` buttons must not be the default focused element on open — `AlertDialogCancel` should be focused first (shadcn AlertDialog default behavior, do not override).
