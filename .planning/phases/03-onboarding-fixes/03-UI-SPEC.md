## Spacing Scale

Tailwind default scale — no custom extensions in `tailwind.config.js`. All spacing in the
existing codebase uses Tailwind utility tokens. Established pattern for content areas:
`px-4 py-10` (outer wrapper), `space-y-6` (field groups), `gap-3` (button rows).

| Token | Tailwind | px | Usage |
|-------|----------|----|-------|
| xs | `gap-1` / `p-1` | 4px | Icon gaps, inline micro-padding |
| sm | `gap-2` / `p-2` | 8px | Compact element spacing, badge padding |
| md | `gap-3` / `p-3` | 12px | Info-card internal padding (see `bg-muted/30 p-3`) |
| default | `gap-4` / `p-4` | 16px | Card / block padding (see `DnsInstructions p-4`) |
| lg | `space-y-6` | 24px | Field group spacing within wizard steps |
| xl | `py-10` | 40px | Page-level top/bottom padding on wizard containers |
| 2xl | `max-w-md` / `max-w-lg` | — | Content width constraint (wizard: `max-w-md`; SuccessStep: `max-w-lg`) |

Exceptions:
- Welcome banner uses `px-4 py-3` (12px vertical) — intentionally compact to minimize layout displacement
- Touch targets for dismiss X button: minimum `h-8 w-8` (32px) with `p-0` — meets minimum touch target

**Placement:** Rendered at the top of the dashboard content area, directly inside
`GeneralDashboard.tsx`, above `<SummaryCards />`. Uses the existing content wrapper
`mx-auto flex w-full max-w-5xl flex-col gap-6 px-6 py-6`. The banner is the first child
inside that wrapper before `<SummaryCards />`.

**Component:** `WelcomeBanner` — a new component at
`frontend/src/components/dashboard/general/WelcomeBanner.tsx`.

**Visual structure:**

```
┌────────────────────────────────────────────────────────────────┐
│  bg-muted/50 border border-border rounded-lg px-4 py-3        │
│  flex items-start justify-between gap-4                        │
│                                                                │
│  [left column — flex-1]                                        │
│    <p className="text-sm font-medium text-foreground">         │
│      Welcome to {brokerageName}                                │
│    </p>                                                        │
│    <p className="mt-0.5 text-xs text-muted-foreground">        │
│      You're a member of the following groups:                  │  ← if groups exist
│      You haven't been added to any groups yet.                 │  ← if no groups
│    </p>                                                        │
│    [group chips row — mt-2 flex flex-wrap gap-1.5]             │
│      <Badge variant="secondary">{groupName}</Badge>  × N       │
│    (chips row omitted entirely when groups array is empty)     │
│                                                                │
│  [right — shrink-0]                                            │
│    <Button variant="ghost" size="icon"                         │
│            className="h-8 w-8 text-muted-foreground            │
│                       hover:text-foreground"                   │
│            aria-label="Dismiss welcome banner"                 │
│            onClick={onDismiss}>                                │
│      <X className="h-4 w-4" />                                 │
│    </Button>                                                   │
└────────────────────────────────────────────────────────────────┘
```

**Visibility rule:** Banner only renders when `welcomed_at` is null (D-20). Controlled by
`bannerVisible` local state in `GeneralDashboardContext` (or its parent layout context), initialized
from the `show_welcome_banner` flag returned by the profile endpoint.

**Dismiss interaction (D-18 — optimistic):**
1. User clicks X → `setBannerVisible(false)` immediately (banner disappears from DOM)
2. `dismissWelcomeMutation.mutate()` fires in background (PATCH to `POST /v1/account/profile/dismiss_welcome`)
3. No loading state on the button. No undo UI. No toast on success. Fire and forget.
4. If the PATCH fails, the banner stays hidden in the current session (optimistic — we do not
   re-show on error). The server will return `welcomed_at: null` on next page load if the
   PATCH truly failed, causing the banner to reappear on next visit — acceptable behavior.

**Group chips:** `<Badge variant="secondary">` from `@/components/ui/badge`. Text is the group
name. No icon inside the chip. `rounded-full` is applied by the `Badge` component's base class.

**No-groups state:** Body text changes from "You're a member of the following groups:" to
"You haven't been added to any groups yet." The chip row is not rendered. The dismiss X and
heading remain unchanged.

## Interaction Contracts

### DomainStep submit error flow

1. User clicks "Create brokerage"
2. `validate()` runs — if client-side invalid, show client-side errors, stop
3. `handleContinue` calls `await actions.submit(domain)` inside try/catch
4. While in-flight: button shows "Creating…", `disabled={state.isSubmitting}`
5. On success: wizard advances to SuccessStep (existing behavior, unchanged)
6. On thrown error: extract `error.response?.data?.error` or `.message`, set as
   `errors.subdomain = message` — field re-renders with error text below the subdomain input
7. Wizard does NOT advance — user stays on DomainStep

### DNS verify flow

1. User clicks "Check DNS status"
2. Local state → `'checking'`; button shows `Loader2` spinner + "Checking…"; button `disabled`
3. Mutation calls `POST /v1/admin/domains/:custom_domain_id/verify`
4. On success (verified): local state → `'verified'`; badge + two CTA buttons replace the
   single "Go to dashboard" button
5. On success (not yet verified) or on HTTP error: local state → `'not_yet'`; neutral message
   shown below button; button re-enabled for retry
6. No toast on either outcome — all feedback is inline

### Welcome banner dismiss flow

1. User clicks X button
2. `bannerVisible` set to `false` — banner removed from DOM immediately (no fade transition)
3. `dismissWelcome` mutation fires silently in background
4. No loading state, no toast, no confirmation

## Accessibility

- `WelcomeBanner` dismiss button: `aria-label="Dismiss welcome banner"`, `type="button"`, visible
  focus ring (`focus-visible:ring-2 focus-visible:ring-ring` from Button base class)
- DNS verify "Domain verified" badge: rendered as `<div role="status">` so screen readers
  announce the state change without explicit `aria-live`
- DNS verify button `disabled` state during checking: `aria-busy="true"` added to the button
- All error messages use `role="alert"` for assistive technology announcement — consistent with
  existing `Invitation.tsx` pattern at line 55
