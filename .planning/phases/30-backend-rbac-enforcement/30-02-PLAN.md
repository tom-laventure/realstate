<critical_insight>
Authorization `before_action` callbacks run BEFORE the controller action body. This means:
- **Deny-list tests (agent 403):** DO NOT need valid params or existing records. `require_admin!`/`require_owner!` renders 403 and halts the chain before the action ever looks up a record. Use any placeholder id (e.g. `"nonexistent"` or an existing record's id) — the 403 comes from the auth tier regardless.
- **Allow-list tests (agent 2xx):** The action body DOES run, so these need enough valid setup to return a success status instead of a 404/422. For reads/index this is trivial (empty collections return 200). For group-scoped mutations you must create the real records the action needs (a group, a filter_set, an estate/group_estate, an invitation, etc.) so the happy path returns 2xx. Read each controller's strong params + the matching factory to build valid input.
</critical_insight>
