## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin agent → API | Authenticated admin user POSTs to `/v1/admin/board_credentials` (downstream — exercised in Plan 02). This plan only modifies the model layer that the controller relies on. |
| App code → DB encryption layer | `encrypts :rets_username` / `encrypts :rets_password` ciphertext columns. Conditional validation may allow nil/empty plaintext for test boards. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01-01 | Tampering | `BrokerageBoardCredential.validates ... unless: real_estate_board&.is_test_board?` | mitigate | Conditional ONLY depends on the server-controlled `is_test_board` column of the associated `RealEstateBoard`. There is no request-controlled path to mutate `is_test_board` on a real board — Phase 11 added the column with `null: false, default: false`, no admin endpoint exposes it for UPDATE. Risk: an attacker would have to compromise the DB to flip `is_test_board` on REBGV/FVREB/CADREB (which are absent from seed data per Phase 11 anyway) to bypass RETS validation. |
| T-12-01-02 | Information Disclosure | Empty ciphertext for `rets_username_ciphertext` / `rets_password_ciphertext` columns on test board credentials | accept | Test board credentials store no real RETS secrets — by design. Active Record Encryption with nil/empty plaintext stores either nil or an empty ciphertext (per Assumption A3 in RESEARCH.md). This is the intended behavior and matches Phase 11 D-05 (no fake ciphertext seeded). Real board credential ciphertext is unchanged. |
| T-12-01-03 | Tampering | Safe navigator `real_estate_board&.is_test_board?` returns nil when `real_estate_board` association is unloaded | mitigate | `nil` is false-y, so `unless: -> { nil }` runs the presence validation (fail-safe default). The only path to reach validation with a nil association is `BrokerageBoardCredential.new` directly (no `find_or_initialize_by(real_estate_board:)`); in that case presence is enforced as before. |
| T-12-01-04 | Repudiation | Test board credential save with no audit trail differentiating "validation skipped" from "validated against RETS" | accept | `BrokerageBoardCredential` has `created_at` / `updated_at` and the board reference. Auditability of test vs real is implicit via `real_estate_board.is_test_board?`. No audit log is needed for development seed data. |
