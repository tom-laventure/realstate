# Phase 43 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn is not applicable. `landing/` is a static Astro site with a locked "zero JS by default" constraint (Phase 42 decision, reaffirmed by this phase's D-03: CSS-only hover/scroll polish, no JS, no client-side hydration). shadcn ships interactive React/Radix components requiring client hydration, which contradicts that lock. |
| Preset | not applicable |
| Component library | none — plain `.astro` components (`Hero.astro`, `ValueProp.astro`, `FeatureGrid.astro`, `ClosingCTA.astro`, `SiteHeader.astro`, `SiteFooter.astro`) styled directly with Tailwind v4 utility classes, per `.planning/research/ARCHITECTURE.md`'s recommended split |
| Icon library | `@lucide/astro` (current official package name — not the older `lucide-astro`) — renders static inline SVG at build time via Astro server components; add as a new dependency this phase. Zero client JS, matches the zero-JS lock. Do NOT use `lucide-react` here (that's `frontend/`'s package; this is a separate Astro project) |
| Font | System font stack — no custom webfont. Copy `frontend/src/index.css`'s `body` font-family exactly for cross-surface consistency and to avoid FOIT/font-loading complexity entirely (see PITFALLS.md Performance Traps): `-apple-system, BlinkMacSystemFont, 'Segoe UI', 'Roboto', 'Oxygen', 'Ubuntu', 'Cantarell', 'Fira Sans', 'Droid Sans', 'Helvetica Neue', sans-serif` |

Existing tokens already wired in `landing/src/styles/global.css` (Phase 42, Slate scheme, static copy — see file header comment for provenance/drift caveat, PITFALLS.md Pitfall 7): `--background`, `--foreground`, `--card`, `--card-foreground`, `--primary`, `--primary-foreground`, `--secondary`, `--muted`, `--muted-foreground`, `--accent`, `--destructive`, `--border`, `--sidebar`, `--sidebar-foreground`, `--sidebar-accent`. This phase must reuse these Tailwind utility classes (`bg-background`, `text-primary`, `border-border`, `bg-sidebar`, etc.) — do not invent new color values.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside feature pairs, badge padding |
| sm | 8px | Compact spacing (nav link gaps, footer column item gaps) |
| md | 16px | Default element spacing, card internal padding |
| lg | 24px | Card/section internal padding, gap between feature-grid items |
| xl | 32px | Gaps between hero elements (eyebrow → headline → subhead → CTA row) |
| 2xl | 48px | Spacing between major on-page sections on mobile (Hero/ValueProp/FeatureGrid/ClosingCTA boundaries) |
| 3xl | 64px | Spacing between major on-page sections on tablet+ |
| 4xl | 96px | Hero and section vertical padding on desktop (`py-24`) — intentionally more generous than the app shell's spacing, per FEATURES.md's differentiator note that the marketing site should read as "more whitespace, larger type scale" than the in-app SPA, not pixel-identical to it |

Exceptions: none beyond the 96px (`4xl`) desktop section-padding addition above — it is still a multiple of 8/4, just a new named step above the app's usual ceiling (`64px`), reserved for hero/section vertical rhythm on `lg:` breakpoints and up only. Mobile sections use `2xl` (48px), not `4xl`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.6 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 28px | 600 (semibold) | 1.2 |
| Display | 48px desktop (`text-5xl`) / 32px mobile (`text-4xl` scaling to `md:text-5xl`) | 600 (semibold) | 1.1 |

Only two weights used across the entire phase: 400 (body copy, legal-page paragraphs, feature descriptions) and 600 (nav links, CTA button labels, all headings, hero headline, footer column headings). Never introduce a third weight (e.g. no `font-bold`/700 anywhere).

- **Display** = hero `<h1>` only.
- **Heading** = every `<h2>` (ValueProp heading, FeatureGrid heading, ClosingCTA heading, legal-page section headings).
- **Label** = nav links, CTA button text, footer links/column headings, feature-pair item titles (the bolded label in each icon+text pair).
- **Body** = hero subhead, value-prop paragraph, feature-pair descriptions, legal-page paragraph text, footer copyright line.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `bg-background` (`oklch(0.97 0.003 256)`, near-white slate) | Page background for Hero, ValueProp, and both legal pages (`/privacy`, `/terms`) |
| Secondary (30%) | `--card` / `bg-card` (`oklch(1 0 0)`, white) for feature/content panels; `--sidebar` / `bg-sidebar` (`oklch(0.39 0.035 256)`, dark slate) for the footer band | FeatureGrid item cards use `bg-card border border-border`; `SiteFooter` uses `bg-sidebar text-sidebar-foreground` as a deliberate dark anchor at the bottom of the page — a common marketing-page convention, and Slate already defines this token pair for exactly this kind of dark-surface use |
| Accent (10%) | `--primary` / `bg-primary` \| `text-primary` (`oklch(0.39 0.035 256)`) | Reserved for: primary CTA button backgrounds (all three "Get Started" touchpoints — hero, post-value-prop, closing), the "RealtyBase" wordmark text in `SiteHeader`, feature-pair icon stroke color in `FeatureGrid`, and link color for in-body links on the legal pages (e.g. cross-references between Privacy Policy and Terms). Do not use `--primary` for anything else on the page. |
| Destructive | `--destructive` / `text-destructive`, `border-destructive/40`, `bg-destructive/10` (`oklch(0.59 0.21 25)`) | Reserved exclusively for the "pending legal review" banner on `/privacy` and `/terms` (LEGAL-03). This is a repurposed use — the marketing site has no transactional destructive actions (no deletes, no forms), so `--destructive` is applied at low opacity as the sole "this needs attention" signal available in the copied Slate token set, not as an error/danger action. Do not use it anywhere else on the site. |

Accent reserved for: the three "Get Started" CTA buttons, the nav wordmark, the 7 FeatureGrid icons, and in-body cross-reference links on the two legal pages — never for body text, borders on non-CTA elements, or decorative use.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Get Started" — links to `https://app.realtybase.ca/create` (absolute URL, no relative path — PITFALLS.md Pitfall 3). Identical label and button style at all three touchpoints: nav, post-hero, post-value-prop is the second touchpoint (D-02), closing section. |
| Secondary CTA (nav + footer) | "Log in" — links to `https://app.realtybase.ca/auth/login` (absolute URL). Styled visually secondary to "Get Started" (e.g. text/ghost style vs. filled `bg-primary` button) so it never competes with the primary conversion path. |
| Hero eyebrow | "Built for real estate brokerages" — small label above the headline, satisfies LAND-01's "names the audience" requirement explicitly and unambiguously within the 5-second scan. |
| Hero headline (H1, Display) | "Every listing, every group, every board — one workspace." |
| Hero subhead (Body) | "RealtyBase unifies MLS-synced listings, group collaboration, and role-based access — so your brokerage isn't held together by spreadsheets, group texts, and five disconnected tools." |
| Value-prop heading (H2, Heading) | "Run your brokerage from one place, not five." |
| Value-prop body | "Listings sync automatically from your connected MLS/RETS board. Agents collaborate inside shared groups. Owners and admins control exactly who can see and manage what. It's one connected workspace, built for how brokerages actually operate — not a bundle of disconnected tools." |
| Closing CTA heading (H2, Heading) | "Ready to bring your brokerage into one workspace?" |
| Closing CTA body | "Get started in minutes — no credit card, no sales call." |
| Closing CTA secondary link | "Already have an account? Log in" (small text link beneath the closing "Get Started" button) |
| Footer copyright | "© {current year} RealtyBase. All rights reserved." — compute the year at build time via Astro frontmatter (`new Date().getFullYear()`); this runs server/build-side only and does not violate the zero-client-JS lock (D-03), since it emits static HTML with no client hydration. |
| Footer contact | "hello@realtybase.ca" (D-08) — rendered as a `mailto:` link |
| Footer legal links | "Privacy Policy" → `/privacy`, "Terms of Service" → `/terms` |
| Legal page banner (LEGAL-03) | "This page is a placeholder and has not yet been reviewed by legal counsel. Do not rely on it as final legal terms." — rendered as a full-width callout directly below the page `<h1>`, before any body content (not buried in the footer — PITFALLS.md Pitfall 6). Uses the `TriangleAlert` icon from `@lucide/astro` at the start of the banner text. |
| Legal entity name | "RealtyBase Inc." — used consistently in both placeholder legal pages (D-09's discretion call: matches standard SaaS legal-template convention of naming a corporate entity, even as placeholder) |
| Legal pages meta | Both `/privacy` and `/terms` must carry a `noindex` meta tag while placeholder (LEGAL-04) — implementation detail for the executor, called out here because it's directly tied to the banner requirement above (Pitfall 6) |
| Feature-pair items (FeatureGrid, D-04/D-05 — 7 items, source order matters for visual grouping) | 1. **MLS/board-synced listings** (`RefreshCw` icon) — "Listings sync automatically from your connected MLS/RETS board — no manual re-entry." 2. **Group collaboration** (`Users` icon) — "Agents organize listings into groups with shared comments, ratings, documents, and dates." 3. **Multi-tenant isolation** (`ShieldCheck` icon) — "Every brokerage gets its own fully isolated, secure workspace." 4. **Role-based access** (`KeyRound` icon) — "Owner, admin, and agent tiers control who can manage listings, invite staff, and configure the brokerage." 5. **Custom domain** (`Globe` icon) — "Run RealtyBase on your own branded domain instead of a shared subdomain." 6. **Client sharing** (`Share2` icon) — "Invite clients into specific groups to view curated listings directly." 7. **Smart filter-set/client pairing** (`Filter` icon) — "Filter sets automatically pair client groups with matching listings." |
| Empty state | Not applicable — `landing/` is fully static/build-time content (ARCHITECTURE.md: "no CMS, no backend fetch"); there is no dynamic data-fetching path in this phase that could produce an empty state. |
| Error state | Not applicable — no forms, no client-side data fetching, no API calls exist on this site (ARCHITECTURE.md: "zero runtime coupling to backend/or frontend/"). If a 404 page is added in a later phase, it is out of scope here. |
| Destructive confirmation | Not applicable — no destructive actions exist on a static marketing site (no deletes, no account actions). The only reuse of the `--destructive` token this phase is the non-transactional legal-review banner above. |

**Layout guidance for the 7 feature pairs (D-05):** use source order exactly as listed above so that item 2 (Group collaboration) and item 3 (Multi-tenant isolation) — the pair the user explicitly called out as related — land adjacent to each other in a `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4` responsive grid (row 1 = items 1–4, row 2 = items 5–7, centered). This avoids a single-orphan last row and keeps the named pair visually grouped without needing a bespoke layout.
