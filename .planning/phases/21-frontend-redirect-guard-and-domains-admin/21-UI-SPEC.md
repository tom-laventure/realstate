## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), badge internal padding |
| sm | 8px | Compact element spacing, button gap (`gap-2`) |
| md | 16px | Card padding (`p-4`), section inner gap |
| lg | 24px | Page padding (`p-6`), section header bottom margin |
| xl | 32px | Between page sections |
| 2xl | 48px | Major section breaks (between Subdomains / Custom Domains) |
| 3xl | 64px | Not used in this phase |

- Card content uses `p-5` (20px) matching the established `CardContent` pattern from `ListingGroupsAdminView.tsx`.

Source: observed from `ListingGroupsAdminView.tsx`, `SideNav.tsx`, `SubdomainInput.tsx`

## Interaction States

### Domain Card — Default (active, non-primary)
- Card with `CardHeader`: domain name (truncated) + type badge + status badge in a flex row
- `CardContent`: if `phaseOutAt` present, countdown text (`text-xs text-muted-foreground`)
- Button row at card bottom (always visible, no kebab): "Set as primary" (outline) + "Edit" (outline, subdomain only) or "Remove" (outline, custom only)

### Domain Card — Primary
- Same card structure; replace action row with: "Primary" badge (sky-colored) + no "Set as primary" button
- "Edit" (subdomain) or remove actions still present if applicable

### Domain Card — Phasing Out
- Status badge: amber "Phasing Out"
- Countdown footer: `text-xs text-muted-foreground` — "12 days remaining · decommissions May 30"
- Button row: "Remove now" (destructive `variant="destructive"`) visible in place of "Edit"
- No "Set as primary" button (phasing-out domains cannot be set primary)

### Domain Card — Inline Edit Mode (DUI-04)
Card **toggles in place** — display content replaced by inline form:
- `DomainSlugInput` (slug input + static `.realstate.app` suffix)
- Validation error text: `text-xs text-destructive` below input, visible on-change
- Button row: "Save" (default, disabled when invalid or unchanged) + "Cancel" (outline)
- Card does not move in the grid — same dimensions as read mode

### Slot Banner — 1 slot remaining (DUI-06, D-12)
Appears **below the "Subdomains" section heading**, above the card list.
```
[yellow banner]  Next change will be your last until [date].
```
- Classes: `rounded-md border border-amber-200 bg-amber-50 px-4 py-3 text-sm text-amber-800`
- Visible only when mutation response includes `phase_out_warning`; dismissed on next page load
- No dismiss button

### Slot Banner — 0 slots available (DUI-07, D-13)
Appears **below the "Subdomains" section heading**, above the card list.
```
[red banner]  No subdomain slots available until [date].
```
- Classes: `rounded-md border border-red-200 bg-red-50 px-4 py-3 text-sm text-red-800`
- "Edit" buttons for all subdomains are disabled with `title` tooltip: `"Unavailable until [date]"`
- Immediately below the red banner: shadcn `Accordion` with single item
  - Trigger: `"Free a slot now?"` (`text-sm font-medium`)
  - Content: list of phasing-out subdomains, each with name + "Remove now" button (`size="sm" variant="destructive"`)

### Remove Now — Confirmation Dialog (DUI-09, D-14)
shadcn `AlertDialog`:
- Title: `"Remove [domain]?"`
- Description: `"This domain will stop resolving immediately and cannot be undone. Any links using this domain will break."`
- Cancel button: `variant="outline"`, label "Cancel"
- Confirm button: `variant="destructive"`, label "Remove domain"

### Custom Domain — Add Form (DUI-05)
Button `"Add domain"` opens an inline form (not a modal dialog) below the section header:
- Input: full custom domain (e.g., `app.acme.com`)
- Validation: non-empty, basic hostname format
- Save button: primary (`variant="default"`), label "Add domain"
- Cancel button: ghost/outline, label "Cancel"

### Pro Gate — Locked Custom Domains (DUI-08)
The Custom Domains section body (card area) replaced with a locked state card:
- `bg-muted/40 border border-dashed border-border rounded-lg p-8 text-center`
- Lock icon: `Lock` from lucide-react, `h-8 w-8 text-muted-foreground mx-auto mb-3`
- Heading: `"Custom domains require a Pro plan"` (`text-base font-semibold`)
- Body: `"Upgrade to Pro to add custom domains to your brokerage."` (`text-sm text-muted-foreground mt-1`)
- CTA button: `variant="default"`, label `"Upgrade to Pro"`, `mt-4`
- No management controls visible; "Add domain" button not rendered

### Loading State (page fetch)
- Card grid replaced by skeleton cards: 2 `Card` elements with `animate-pulse` divs mirroring card dimensions
- No spinner; skeleton is the loading affordance

### Empty State (no domains)
Not a realistic empty state — every brokerage has at least one subdomain (backfilled in Phase 19). This state does not need a design.

## PrimaryDomainRedirect — Guard Behavior Contract

| State | Render |
|-------|--------|
| `isMainDomain()` returns true | Skip entirely, render children immediately |
| Lookup in flight | Render `null` (blank screen — no spinner, no flash) |
| Lookup: current host = primary domain | Render children |
| Lookup: current host ≠ primary domain | `window.location.replace(primaryUrl)` — no render |
| Lookup: any error (network, 404, etc.) | Fail open — render children |

`primaryUrl` construction: `https://{primary_domain}{window.location.pathname}{window.location.search}`

Source: CONTEXT.md D-01, D-02, D-03, D-04

## Slug Validation Rules (DUI-04 Client-Side)

Reserved words to hardcode in `domainConstants.ts` (mirrored from `BrokerageDomain::RESERVED_SLUGS`):

```
admin, api, www, mail, smtp, ftp, staging, dev, test, app, auth, login,
signup, dashboard, static, assets, cdn, docs, help, support, status
```

Validation order (run on every `onChange`, before save):
1. Minimum 1 character
2. Pattern: `/^[a-z0-9][a-z0-9-]*[a-z0-9]$|^[a-z0-9]$/` — alphanumeric and hyphens, no leading/trailing hyphen
3. Not in the RESERVED_SLUGS list
4. Unchanged from current value → Save button disabled (no error shown)

Source: CONTEXT.md D-11; `backend/app/models/brokerage_domain.rb` RESERVED_SLUGS

## Accessibility Contract

- All `button` elements have descriptive `aria-label` when icon-only (e.g. close inline edit): `aria-label="Cancel edit"`
- `aria-current="page"` on active nav items — already enforced by `NavButton` and `PortalAdminSideNav` patterns
- `AlertDialog` uses Radix focus trap — no additional work needed
- "Remove domain" confirm button: receives focus automatically via Radix `AlertDialogAction`
- Disabled Edit button (0 slots): use `title` attribute for tooltip, not `aria-label` — keeps accessible name intact
- Inline validation errors: associated to input via `id` + `aria-describedby`
- Color is never the sole differentiator: status badges always include a text label alongside color
