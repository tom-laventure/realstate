Create `backend/app/models/user_calendar_connection.rb` (per D-10 — credential storage, D-01 provider, D-02 status tracking):

```ruby
class UserCalendarConnection < ApplicationRecord
  acts_as_paranoid

  belongs_to :user

  encrypts :credentials

  PROVIDERS = %w[google microsoft apple].freeze

  enum :status, {
    connected: "connected",
    error: "error",
    disconnected: "disconnected"
  }, prefix: :connection

  validates :provider, inclusion: {in: PROVIDERS, message: "must be google, microsoft, or apple"}
  validates :user_id, uniqueness: {scope: :provider, message: "already has a connection for this provider"}

  def credentials_hash
    JSON.parse(credentials || "{}")
  rescue JSON::ParserError
    {}
  end

  def credentials_hash=(hash)
    self.credentials = hash.to_json
  end
end
```

| External Gem ↔ App | Four new gems added; transitive deps expand attack surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Information Disclosure | `credentials_ciphertext` column | mitigate | `encrypts :credentials` with AR Encryption (already configured in `active_record_encryption.rb`); column is unreadable at-rest without encryption keys |
| T-05-01-02 | Information Disclosure | `UserCalendarConnection` model | mitigate | `credentials_hash` method parses JSON; `JSON::ParserError` rescued — no raw credential values logged; model must never include `credentials` field in serializer (enforced in Plan 04) |
| T-05-01-03 | Tampering | `provider` column | mitigate | `validates :provider, inclusion: {in: PROVIDERS}` rejects any value not in `%w[google microsoft apple]`; DB-level string column prevents injection |
| T-05-01-04 | Elevation of Privilege | Gem transitive deps | accept | New gems (`calendav`, `with_advisory_lock`, `google-apis-calendar_v3`) are from rubygems.org; versions verified 2026-05-12; no known CVEs at plan time |
