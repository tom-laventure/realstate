## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap (`gap-1`), inline badge padding |
| sm | 8px | Compact row spacing (`gap-2`), button internal padding |
| md | 16px | Default element spacing (`gap-4`), card content padding |
| lg | 24px | Section padding (`p-6`), between provider cards |
| xl | 32px | Layout gaps, tab content top margin |
| 2xl | 48px | Major section breaks (not used in this phase) |
| 3xl | 64px | Page-level spacing (not used in this phase) |

Exceptions:
- Minimum touch target for icon-only buttons: 44px height (`min-h-[44px]` or `h-10 w-10` for icon size variant). Used on connect/disconnect/re-sync buttons.
- Apple credential form input rows use `space-y-2` (8px) between label and input.

## Layout Contract

### Account Page — Calendar Tab Integration

The Calendar tab is added to the existing `Account.tsx` page. The current page has no `Tabs` component — it renders profile + groups side-by-side in a 12-column grid. The Calendar tab introduces a tabbed layout at the Account page level.

Tab structure:
```
Tabs (defaultValue="profile")
  TabsList
    TabsTrigger value="profile"   → "Profile"
    TabsTrigger value="calendar"  → "Calendar"
  TabsContent value="profile"     → existing Account content (MemberDetailCard + MemberGroupsList grid)
  TabsContent value="calendar"    → CalendarTab component
```

The page heading ("My Profile" + "Edit Profile" button) remains above the Tabs component, always visible.

### Calendar Tab Layout

```
<div class="space-y-6">
  <section>
    <h2 class="text-base font-semibold mb-1">Connected Calendars</h2>
    <p class="text-sm text-muted-foreground mb-4">
      Connect your calendar to sync property showing dates automatically.
    </p>
    <div class="grid gap-4 sm:grid-cols-1 md:grid-cols-3">
      <!-- ProviderCard × 3 (Google, Microsoft, Apple) -->
    </div>
  </section>
</div>
```

### Provider Card Layout

Each card is a `Card` component (rounded-xl, border, shadow-sm) with fixed internal structure:

```
Card (class="flex flex-col")
  CardContent (class="p-4 sm:p-6 flex flex-col gap-4 h-full")
    <!-- Header row -->
    <div class="flex items-center gap-2">
      [ProviderLogo 20x20] + <span class="text-base font-semibold">[Provider Name]</span>
    </div>

    <!-- Status row -->
    <div class="flex items-center gap-2">
      [StatusIcon 16x16 text-{color}]
      <Badge variant="outline" class="border-{color}/40 text-{color}">
        [Connected | Error | Disconnected]
      </Badge>
    </div>

    <!-- Last sync row (conditional — only when status !== 'disconnected') -->
    <p class="text-xs text-muted-foreground">
      Last synced: [relative timestamp or "Never"]
    </p>

    <!-- Spacer -->
    <div class="flex-1" />

    <!-- Action buttons (always at bottom) -->
    <div class="flex flex-col gap-2">
      <!-- When status === 'connected': -->
      <Button variant="outline" size="sm" disabled={isLoading}>
        [Unlink2 icon] Disconnect
      </Button>

      <!-- When status === 'error': -->
      <Button variant="default" size="sm" disabled={isLoading}>
        [RefreshCw icon animate-spin when loading] Re-sync
      </Button>
      <Button variant="outline" size="sm" disabled={isLoading}>
        [Unlink2 icon] Disconnect
      </Button>

      <!-- When status === 'disconnected' AND provider !== 'apple': -->
      <Button variant="default" size="sm" disabled={isLoading}>
        [Loader2 animate-spin when loading | Link2 when idle] Connect
      </Button>

      <!-- When status === 'disconnected' AND provider === 'apple': -->
      [AppleCredentialForm inline] (see below)
    </div>
```

### Disconnect Confirmation Dialog

Triggered when user clicks Disconnect. Uses shadcn Dialog.

```
Dialog
  DialogContent
    DialogHeader
      DialogTitle: "Disconnect [Provider] Calendar"
      DialogDescription: "Your calendar will stop receiving new property showing events. Past events already synced will remain in your calendar."
    DialogFooter
      Button variant="outline" onClick={closeDialog}: "Keep Connected"
      Button variant="destructive" onClick={confirmDisconnect}: "Disconnect"
```

## Interaction States

| Element | State | Visual Treatment |
|---------|-------|-----------------|
| Connect button (OAuth) | idle | default variant, Link2 icon |
| Connect button (OAuth) | loading | disabled + Loader2 animate-spin, no text change |
| Connect button (OAuth) | success | card status transitions to "connected" (no toast needed) |
| Connect iCloud button | idle | default variant, Link2 icon |
| Connect iCloud button | loading | disabled + Loader2 animate-spin |
| Connect iCloud button | error | form stays visible; error text appears below button (`text-sm text-destructive`) |
| Disconnect button | idle | outline variant |
| Disconnect button | clicked | opens Dialog (does NOT immediately fire API) |
| Disconnect confirm | loading | both dialog buttons disabled + Loader2 in destructive button |
| Re-sync button | idle | default variant, RefreshCw icon |
| Re-sync button | loading | disabled + RefreshCw animate-spin |
| Re-sync button | success | card status badge updates to "connected" or remains "error" |
| Provider card | any loading | card NOT skeleton-replaced — individual buttons show loading state only |

Loading spinner pattern (consistent with GoogleSignInButton):
```tsx
<span className="h-4 w-4 animate-spin rounded-full border-2 border-primary/30 border-t-primary" aria-hidden="true" />
```
Or use `<Loader2 className="h-4 w-4 animate-spin" />` for inline icon replacement.

## Accessibility Contract

- All interactive buttons have explicit `aria-label` when icon-only or ambiguous: e.g. `aria-label="Disconnect Google Calendar"`.
- All loading buttons set `aria-busy={true}` and `disabled` simultaneously.
- The Apple credential form uses `<form>` with `htmlFor` + `id` pairing for every Label/Input pair.
- The Apple password field uses `type="password"` — never `type="text"`.
- Status badges use `role="status"` or are wrapped in a container with `aria-live="polite"` so screen readers announce status changes without page reload.
- Dialog uses shadcn Dialog which handles focus trap and aria-modal automatically.
- Focus ring: inherited from shadcn button `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2` — never disable.
- Color contrast: `text-emerald-700` on white background exceeds 4.5:1. `text-amber-700` on white exceeds 4.5:1. Verified against WCAG AA.
