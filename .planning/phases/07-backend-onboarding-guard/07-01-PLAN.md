<objective>
Add a Rails `MainDomainOnly` controller concern that rejects any request to `/v1/onboarding/*` whose origin is not the configured main domain with HTTP 403, and include it in all three onboarding controllers. Cover the guard with an integration test exercising rejection (subdomain origin) and pass-through (main-domain origin) for all four onboarding routes.

Purpose: Phase 6 added frontend routing guards but those are UX-only (per decision 06-01). Without a backend check, a malicious actor on a brokerage subdomain can still call `POST /v1/onboarding/brokerage` directly and register a competing brokerage. DOM-04/DOM-05 close this hole by enforcing the main-domain restriction at the API layer where it is a real security boundary.

Output: One new concern file, three modified controllers (one-line addition each), and one new integration test file (~5 tests covering all four routes).
</objective>

    ```ruby
    # Guards onboarding endpoints to only allow requests originating from the
    # configured main domain (APP_BASE_DOMAIN). Used by /v1/onboarding/*
    # controllers to prevent brokerage subdomain users from calling endpoints
    # that create or modify pre-tenant state.
    #
    # Origin extraction mirrors BrokerageAuth#extract_domain_from_request —
    # Origin header is canonical (frontend domain), Host is fallback for
    # non-browser/dev cases. See decision 01-03 (Origin-first) and
    # decision 06-01 (frontend guards are UX-only; backend 403 is the real
    # security boundary).
    module MainDomainOnly
      extend ActiveSupport::Concern

      included do
        before_action :require_main_domain!
      end

      private

      # DOM-04: reject non-main-domain origins with HTTP 403.
      # DOM-05: main domain comes from APP_BASE_DOMAIN env var (no hardcoded strings).
      def require_main_domain!
        main_domain = ENV.fetch("APP_BASE_DOMAIN", "realstate.ca")

        origin_host = begin
          URI.parse(request.headers["Origin"].to_s).host&.downcase
        rescue URI::InvalidURIError
          nil
        end
        request_host = origin_host.presence || request.host.downcase

        unless request_host == main_domain
          render json: {error: "Forbidden"}, status: :forbidden
        end
      end
    end
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Rails API | Untrusted HTTP requests cross here; the `Origin`/`Host` headers are attacker-controllable in non-browser contexts (curl, Postman, scripted requests) but are validated by browsers in browser contexts. The `MainDomainOnly` guard is the API-layer gate for `/v1/onboarding/*`. |
| Brokerage subdomain user → Onboarding API | An authenticated user on `acme.realstate.ca` must not be able to create a competing brokerage or modify pre-tenant state via direct API calls. This is the primary attack vector Phase 7 closes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01-01 | Elevation of Privilege | `V1::Onboarding::BrokeragesController#create` from a brokerage subdomain | high | mitigate | `include MainDomainOnly` registers `before_action :require_main_domain!` which renders 403 when `request.headers["Origin"]` host ≠ `ENV.fetch("APP_BASE_DOMAIN", "realstate.ca")`. Test `POST /v1/onboarding/brokerage from brokerage subdomain returns 403` asserts the rejection. Order is enforced: include MainDomainOnly above include CognitoAuth so the domain check fires before authentication (wrong-domain → 403, not 401). |
| T-07-01-02 | Elevation of Privilege | `V1::Onboarding::DomainsController#check` and `#verify` from a brokerage subdomain | high | mitigate | Same concern at controller level covers both actions (no per-action scoping). Tests assert 403 for both routes. |
| T-07-01-03 | Elevation of Privilege | `V1::Onboarding::UsersController#update` from a brokerage subdomain | medium | mitigate | Same concern + test for `PATCH /v1/onboarding/user from brokerage subdomain returns 403`. |
| T-07-01-04 | Spoofing | Attacker forges `Origin` header in a direct API call (curl/Postman) | low | accept | Browser CORS enforcement is the primary defence — the `Origin` header is set by the user agent in browser contexts and cannot be controlled by JavaScript on `acme.realstate.ca` to claim `realstate.ca` as origin. Server-side guard is defence-in-depth. Non-browser callers (server-to-server, CLI) that intentionally set `Origin: https://realstate.ca` would still hit Cognito auth next — they must possess a valid JWT to do anything. The risk of an authenticated user maliciously crafting the Origin header is low because they already have main-domain access if they can do so legitimately. Documented in concern comments. |
| T-07-01-05 | Denial of Service | `APP_BASE_DOMAIN` env var unset in production | low | mitigate | `ENV.fetch("APP_BASE_DOMAIN", "realstate.ca")` default prevents a crash; production deployment runbook MUST set the value (existing practice — already used by `BrokeragesController` and `DomainsController`). |
| T-07-01-06 | Information Disclosure | Error body leaks internal state | low | mitigate | Response is the fixed string `{"error":"Forbidden"}` — no request data, no stack, no host names echoed. |
| T-07-01-07 | Tampering | Malformed `Origin` header (e.g. `"::::"`) crashes the request | medium | mitigate | `URI::InvalidURIError` rescue catches malformed URIs; falls back to `request.host`. Behavior is covered by the concern's defensive `begin/rescue` block (mirrors `BrokerageAuth`'s established pattern). |
