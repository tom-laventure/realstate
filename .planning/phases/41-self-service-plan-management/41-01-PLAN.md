<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser client → `PATCH /v1/admin/settings/plan` | Any authenticated brokerage user (owner/admin/agent/client) can craft this request directly; the frontend's disabled selector is not a security control |
| Request → tenant scope | `Current.brokerage` is resolved from the request Host by `BrokerageAuth`; the caller cannot target another tenant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-01 | Elevation of Privilege | `PlanController#update` | mitigate | `before_action :require_owner!` re-validates `current_membership.role == "owner"` from the DB on every request (never a JWT/client claim); Task 2 asserts 403 for admin/agent/client callers |
| T-41-02 | Tampering | plan scope | mitigate | Endpoint uses `Current.brokerage` (Host-resolved via BrokerageAuth); no `brokerage_id` param is accepted, so cross-tenant plan tampering is impossible by construction |
| T-41-03 | Tampering | plan value | mitigate | `AppConstants::PLAN_TIERS.key?(new_plan)` inclusion check before any mutation (422 on invalid), backed by the model's own `validates :plan, inclusion:` as a second layer; Task 2 asserts the invalid-plan case |
| T-41-04 | Denial of Service | queue dispatch | accept | Controller-level no-op guard prevents spurious enqueues on same-plan requests; rapid duplicate transitions are already handled by the job's WR-03 race guard — no additional throttling needed for this owner-only, low-frequency action |
</threat_model>
