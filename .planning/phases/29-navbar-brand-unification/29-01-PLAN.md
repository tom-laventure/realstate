<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build-time env → client bundle | `VITE_BRAND_LOGO_URL` is inlined at build time by Vite; it is operator-controlled, not user-controlled input |
| client → router | `navigate()` calls determine in-app navigation targets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01 | Tampering (XSS) | `<img src={import.meta.env.VITE_BRAND_LOGO_URL}>` in DashboardNavBar | accept | Value is a build-time env constant set by the operator, not user input. It is used only as an `<img src>` attribute (no `dangerouslySetInnerHTML`, no JS-URL navigation). A malicious `src` could at most load an external image; `img src` does not execute script. No mitigation beyond not making it clickable/interpolated. |
| T-29-02 | Tampering | `navigate()` targets in DashboardNavBar | mitigate | All `navigate()` targets are hardcoded internal string literals (`/account`). No env var or user input is passed to `navigate()`. Sign-out uses hardcoded `/auth/login`. |
| T-29-03 | Information disclosure | Sign-out flow | mitigate | Mirrors existing PortalNavBar flow exactly: `signOut({ global: true })` revokes all sessions, `clearToken()` purges local token, `clearActiveBrokerage()` clears Redux. No new exposure introduced. |
</threat_model>
