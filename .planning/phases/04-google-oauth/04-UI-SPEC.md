## Color

The project uses shadcn zinc base with CSS custom properties (oklch). All colors reference the design token, not hex literals.

| Role | CSS token | Approximate hex (light mode) | Usage |
|------|-----------|------------------------------|-------|
| Dominant (60%) | `--background` | #ffffff | Page background, card background |
| Secondary (30%) | `--muted` / `--card` | #f4f4f5 / #ffffff | Card surfaces, muted areas |
| Accent (10%) | `--primary` | #18181b | Spinner `border-t-primary`, button fill |
| Destructive | `--destructive` | #e63946 | Not used in this phase |

**Accent reserved for:** spinner border-top color in LoginSuccessful (`border-t-primary`), and the loading spinner in GoogleSignInButton during click state. Accent is NOT used for the Google button fill, the divider, or the badge — those use `border`, `muted-foreground`, and `secondary` respectively.

**Google button color rule:** The GoogleSignInButton uses `variant="outline"` — white background, `--border` stroke, `--foreground` text. This is intentional: the Google brand is represented by the Google logo SVG only. The button itself does not use Google blue (#4285F4) as a background, which would conflict with the shadcn design system and fail the 60/30/10 contract.

**Badge color:** Uses `variant="outline"` on the shadcn `<Badge>` component. Border is `--border`, text is `--muted-foreground`. No custom color. This matches the existing role badge pattern in `MemberDetailCard.tsx`.

## Surface Contracts

### Surface 1: GoogleSignInButton

**File:** `frontend/src/components/auth/GoogleSignInButton.tsx`

**States:**

| State | Visual |
|-------|--------|
| Idle | `variant="outline"` Button, full width (`w-full`), 44px min-height. Google SVG logo (16x16) left of label. Label: "Continue with Google" |
| Loading (click → redirect) | Spinner replaces the Google logo (same 16px slot). Label text unchanged. Button `disabled`. Spinner: `animate-spin h-4 w-4 border-2 border-primary/30 border-t-primary rounded-full`. Loading lasts ~500ms before signInWithRedirect fires. |
| Error | Inline error text below button: `text-sm text-destructive` with `role="alert"`. Error copy: see Copywriting Contract. Button returns to idle state. |

**Layout in CreateAccount.tsx:**

```
[email/password form — existing primary path]
[Submit button]

[divider: "— or —"]

[GoogleSignInButton — full width]
```

Divider markup: `<div className="relative my-4">` containing `<div className="absolute inset-0 flex items-center"><span className="w-full border-t border-border" /></div>` and `<div className="relative flex justify-center text-xs uppercase"><span className="bg-card px-2 text-muted-foreground">or</span></div>`.

The divider is rendered in both `mode === 'create'` and `mode === 'login'` stages (both show the Google option). It is NOT shown in the `stage === 'confirm'` or `stage === 'authenticated'` stages.

**Interaction sequence:**

1. User clicks button → `isLoading = true` → spinner appears, button disabled
2. ~500ms delay (visual feedback window) → `signInWithRedirect({ provider: 'Google', customState: base64(JSON.stringify({ brokerage: window.location.hostname })) })` fires
3. Browser navigates to Google — React component unmounts, no further state management needed
4. On return (OAuth error case only): button returns to idle, error message rendered

**Google logo:** Inline SVG, 16x16px, standard 4-color Google "G" mark. The SVG is embedded directly in the component (no external fetch). Viewbox: `0 0 24 24`. Colors: standard Google brand (#4285F4 blue, #34A853 green, #FBBC05 yellow, #EA4335 red).

**Accessibility:** `aria-label="Continue with Google"` on the Button. Spinner has `aria-hidden="true"`. When loading, Button has `aria-busy="true"`.

### Surface 2: LoginSuccessful (repurposed)

**File:** `frontend/src/containers/auth/LoginSuccessful.tsx`

**This screen is transient — it is displayed for the duration of the hash-read → localStorage write → navigate cycle (typically under 200ms). The existing visual design is preserved exactly.**

Existing markup is kept verbatim:
- Full viewport center: `flex min-h-screen items-center justify-center bg-background px-6 w-full`
- Card: `w-full max-w-sm flex-col items-center gap-4 rounded-2xl border border-border bg-card p-8 text-center shadow-sm`
- Spinner: `h-12 w-12 animate-spin rounded-full border-4 border-primary/20 border-t-primary`
- Heading: `text-lg font-semibold text-foreground` — "Finalizing your sign-in" (unchanged)
- Subtext: `text-sm text-muted-foreground` — "Loading your profile and workspace…" (unchanged)

**New behavior (not visual):** A `useEffect` on mount reads `window.location.hash`, extracts the token, writes to localStorage, clears the hash, then calls `navigate('/', { replace: true })`. No visual change is needed for this behavior — the spinner is the correct state while this runs.

**Error state:** If the hash is missing or malformed, show a different message in place of the subtext. Copy: "Something went wrong completing your sign-in. Please try again." with a "Back to sign in" link below (`<a href="/">Back to sign in</a>`, styled `text-sm text-primary underline-offset-4 hover:underline`). The spinner is hidden in the error state (spinner `hidden`, replaced by an inline alert icon from lucide: `<AlertCircle className="h-12 w-12 text-destructive" />`).

### Surface 3: Connected via Google badge

**File:** `frontend/src/components/view/admin/usersAdminView/memberAdminView/MemberDetailCard.tsx`

**Placement:** Added as a new row in the `space-y-4` detail list, immediately after the email row and before the Role row. Uses the same `flex items-start gap-3` pattern as all other rows in the card.

**Visual:**

```tsx
{member?.authProvider === 'google' && (
    <div className="flex items-start gap-3">
        <Shield className="mt-0.5 h-4 w-4 text-muted-foreground" />
        <div className="min-w-0">
            <div className="text-xs text-muted-foreground">Sign-in method</div>
            <Badge variant="outline" className="mt-0.5 border-sky-500/40 text-sky-700 text-xs">
                Connected via Google
            </Badge>
        </div>
    </div>
)}
```

Icon: `Shield` from lucide-react (conveys identity/auth without using the Google brand color in an icon slot). 16x16, `text-muted-foreground`.

Badge style: `variant="outline"` with `border-sky-500/40 text-sky-700` — matches the existing `agent` role badge color in this same component (`border-sky-500/40 text-sky-700`), establishing visual coherence between agent identity and Google identity.

When `authProvider` is null or absent: the row is not rendered. Purely conditional — no empty/placeholder state.

**Type update required:** `authProvider?: string` must be added to the `user` interface in `frontend/src/assets/types/userType.ts`.
