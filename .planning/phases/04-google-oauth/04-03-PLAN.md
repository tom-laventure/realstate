Create directory `auth-callback/` at the monorepo root (alongside `backend/`, `frontend/`, `lambda/`) and create `auth-callback/index.html`.

This is a fully static HTML/JS file — no build step, no framework. It must be deployable as-is by copying to a static hosting origin at `auth.realtybase.ca`.

Read `frontend/.env` first to get the actual Cognito config values (VITE_COGNITO_USER_POOL_ID, VITE_COGNITO_CLIENT_ID, VITE_COGNITO_DOMAIN). Embed them directly in the HTML — runtime env vars are not available in static files.

The page logic (in order):
1. Configure Amplify with the same Cognito settings as the main SPA (userPoolId, userPoolClientId, domain, redirectSignIn including `https://auth.realtybase.ca/oauth/callback`)
2. Call `fetchAuthSession()` — Amplify handles the PKCE code exchange automatically from the URL params (`?code=...&state=...`)
3. Extract `idToken` from `session.tokens.idToken.toString()`
4. Read the brokerage domain from Amplify's Hub event (preferred) OR parse the `state` query param. Since the callback page calls `fetchAuthSession()` (which triggers the Hub event), use a Hub listener to capture `customState` from the `signInWithRedirect` Hub event detail, which Amplify populates with the decoded `customState` value from the OAuth state param.
5. Validate the brokerage domain before redirecting — must end with `.realtybase.ca` to prevent open redirector
6. POST the idToken to `https://api.realtybase.ca/v1/sessions` (or the backend API URL configured for production — read from .env for VITE_API_URL if present, otherwise use the Rails API domain)
7. On success: `window.location.href = "https://" + brokerage + "/auth/login-success#token=" + jwt`
8. On error: show inline error message with a link back to the brokerage login page

**Note on customState parsing:** Per RESEARCH.md Pitfall 6, Amplify v6 does NOT expose `customState` directly from the state query parameter — the raw `state` param is Amplify-prefixed. The recommended approach is to listen for the Amplify Hub `signInWithRedirect` event, which includes `data.customState` containing the decoded custom state string. The callback page should:
1. Set up a Hub listener for the 'auth' channel before calling `fetchAuthSession()`
2. `fetchAuthSession()` triggers the Hub event
3. In the Hub event handler, `payload.data.customState` contains the base64 JSON from D-02
4. Parse: `JSON.parse(atob(payload.data.customState))` to get `{ brokerage: "broker1.realtybase.ca" }`

    const COGNITO_CLIENT_ID = 'REPLACE_WITH_VITE_COGNITO_CLIENT_ID'

    import { fetchAuthSession } from 'https://cdn.jsdelivr.net/npm/aws-amplify@6/dist/aws-amplify.js'

      if (payload.event === 'signInWithRedirect') {
        customState = payload.data?.customState || null

      const session = await fetchAuthSession()

      if (!idToken) {

        return

      // Format: base64(JSON.stringify({ brokerage: "broker1.realtybase.ca" }))
      let brokerage = null
      if (customState) {

          const decoded = JSON.parse(atob(customState))
          brokerage = decoded.brokerage

          // customState parse failure — fall through to validation error

        return

      const response = await fetch(BACKEND_URL + '/v1/sessions', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ id_token: idToken })
      })

      if (!response.ok) {
        const body = await response.json().catch(() => ({}))
        showError('Sign-in failed: ' + (body.error || response.statusText) + '. Please try again.')
        return
      }

      const { token } = await response.json()

      // Token handoff: redirect to brokerage domain with JWT in URL hash (per D-04).
      // Hash is browser-only — not sent in Referer headers, not in server access logs.
      window.location.href = 'https://' + brokerage + '/auth/login-success#token=' + token

      unlisten()
      showError('Something went wrong completing your sign-in. Please try again.')
      console.error('OAuth callback error:', err)
    }

**1. Rewrite LoginSuccessful.tsx** — add hash-reading useEffect, preserve existing JSX verbatim, add error state per UI-SPEC.

Per D-07: On mount, read `window.location.hash`, extract `token`, call `setToken(token)`, clear the hash, navigate to `/`.
Per Pitfall 5: `useEffect` must use `[]` dependency (runs once on mount). Read token → setToken → clear hash → navigate — all in one sequential invocation.

```tsx
import { useEffect, useState } from 'react'
import { useNavigate } from 'react-router-dom'
import { AlertCircle } from 'lucide-react'
import { setToken } from '@/lib/auth'

const LoginSuccessful = () => {
    const navigate = useNavigate()
    const [error, setError] = useState(false)

    useEffect(() => {
        // Read hash BEFORE any navigate/state change (Pitfall 5: navigate exits component)
        const hash = window.location.hash
        const params = new URLSearchParams(hash.replace(/^#/, ''))
        const token = params.get('token')

        if (!token) {
            setError(true)
            return
        }

        // Write token to localStorage using the canonical key from lib/auth.ts ('auth_token')
        setToken(token)
        // Clear hash BEFORE navigate — hash change fires before component unmounts
        window.location.hash = ''
        navigate('/', { replace: true })
    }, []) // Empty deps: runs exactly once on mount

    if (error) {
        return (
            <div className="flex min-h-screen items-center justify-center bg-background px-6 w-full">
                <div className="flex w-full max-w-sm flex-col items-center gap-4 rounded-2xl border border-border bg-card p-8 text-center shadow-sm">
                    <AlertCircle className="h-12 w-12 text-destructive" />
                    <div>
                        <div className="text-lg font-semibold text-foreground">Something went wrong</div>
                        <div className="text-sm text-muted-foreground">We couldn&apos;t complete your sign-in. Please try again.</div>
                    </div>
                    <a
                        href="/"
                        className="text-sm text-primary underline-offset-4 hover:underline"
                    >
                        Back to sign in
                    </a>
                </div>
            </div>
        )
    }

    return (
        <div className="flex min-h-screen items-center justify-center bg-background px-6 w-full">
            <div className="flex w-full max-w-sm flex-col items-center gap-4 rounded-2xl border border-border bg-card p-8 text-center shadow-sm">
                <div className="h-12 w-12 animate-spin rounded-full border-4 border-primary/20 border-t-primary" />
                <div>
                    <div className="text-lg font-semibold text-foreground">Finalizing your sign-in</div>
                    <div className="text-sm text-muted-foreground">Loading your profile and workspace…</div>
                </div>
            </div>
        </div>
    )
}

export default LoginSuccessful
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OAuth state param → callback page | The brokerage domain comes from the OAuth state param decoded via Amplify's customState — must be validated before use as a redirect target |
| auth-callback page → POST /v1/sessions | CORS must allow auth.realtybase.ca (handled in Wave 1, Plan 01) |
| URL hash → LoginSuccessful.tsx | JWT arrives in hash from auth.realtybase.ca; read once on mount and immediately cleared |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Tampering | auth-callback/index.html — state param open redirector | mitigate | ASVS V5: brokerage domain validated with `endsWith('.realtybase.ca')` before using in `window.location.href`. An attacker-controlled state param cannot redirect to an arbitrary domain. |
| T-04-03-02 | Information Disclosure | Token in URL hash | accept | ASVS V3: URL fragment is not sent in HTTP Referer headers (browser spec). `window.location.hash = ''` is called immediately after `setToken()` — token exists in hash for milliseconds only. Same-origin JS cannot read other tabs' hashes. Accepted: existing localStorage auth pattern is same risk level. |
| T-04-03-03 | Spoofing | LoginSuccessful.tsx — empty hash | mitigate | ASVS V5: `params.get('token')` returns null if hash is absent/malformed → `setError(true)` — no token is written, user sees error state with back-link. No partial authentication possible. |
| T-04-03-04 | Tampering | auth-callback Amplify CDN import | accept | CDN unavailability shows a blank page (no redirect, no token handoff). No security risk — failure is denial of service, not data exfiltration. Risk accepted for simplicity; can be mitigated by switching to a bundled script in a future iteration. |
</threat_model>
