module V1
  class SessionsController < ApplicationController
    include CognitoAuth
    include BrokerageAuth

    before_action :authenticate_cognito_user!, only: [:destroy]

    # Signing out should succeed regardless of brokerage membership status.
    def skip_brokerage_membership?
      true
    end

    # POST /v1/sessions
    def create
      if params[:id_token].present?
        # OAuth path (per D-05) — Google sign-in via intermediary callback page
        # CRITICAL: Use JWT.decode(token, nil, false) — NOT TokenService.verify.
        # TokenService.verify uses HS256 (app secret); Cognito idTokens are RS256.
        claims, _header = JWT.decode(params[:id_token], nil, false)

        # String-keyed claims (JWT.decode returns strings, not symbols)
        email_verified = claims["email_verified"]

        unless email_verified
          render json: {error: "Google account email is not verified"}, status: :unprocessable_entity
          return
        end

        user = User.find_or_initialize_by(cognito_sub: claims["sub"])
        user.email = claims["email"] if user.email.blank?

        if user.first_name.blank?
          full_name = claims["name"].presence || user.email.split("@").first
          parts = full_name.split(/\s+/, 2)
          user.first_name = claims["given_name"].presence || parts[0] || "User"
          user.last_name = claims["family_name"].presence || parts[1] || "Unknown"
        end

        user.name = claims["name"] if user.name.blank?
        user.auth_provider = "google"
        user.save!

        render json: {token: TokenService.issue(user)}, status: :ok
      elsif params[:email].present? && params[:password].present?
        # Existing email/password path — unchanged
        claims = CognitoService.initiate_auth(email: params[:email], password: params[:password])

        user = User.find_or_initialize_by(cognito_sub: claims[:sub])
        user.email = claims[:email] if user.email.blank?

        if user.first_name.blank?
          full_name = claims[:name].presence || user.email.split("@").first
          parts = full_name.split(/\s+/, 2)
          user.first_name = claims[:first_name].presence || parts[0] || "User"
          user.last_name = claims[:last_name].presence || parts[1] || "Unknown"
        end

        user.name = claims[:name] if user.name.blank?
        user.save!

        render json: {token: TokenService.issue(user)}, status: :ok
      else
        render json: {error: "Email and password are required"}, status: :unprocessable_entity
      end
    rescue JWT::DecodeError => e
      render json: {error: "Invalid token: #{e.message}"}, status: :unauthorized
    rescue CognitoService::AuthError => e
      render json: {error: e.message}, status: :unauthorized
    rescue ActiveRecord::RecordInvalid => e
      render json: {error: "Could not create user account: #{e.message}"}, status: :unprocessable_entity
    end

    # DELETE /v1/sessions
    def destroy
      CognitoService.admin_user_global_sign_out(Current.user.cognito_sub)
    rescue => e
      Rails.logger.warn("Sign-out error: #{e.class} - #{e.message}")
    ensure
      head :no_content
    end
  end
end

```ruby
    private

    # Fetches the Cognito JWKS (JSON Web Key Set) for RS256 idToken verification.
    # Cached in Rails.cache for 1 hour to avoid an HTTP round-trip on every login.
    # Cache miss path makes one synchronous HTTPS GET to COGNITO_CONFIG[:jwks_uri].
    # If the fetch fails, raises — caller's JWT::DecodeError rescue does NOT catch this,
    # so a JWKS network failure surfaces as a 500 (correct: token cannot be verified).
    def cognito_jwks
      Rails.cache.fetch("cognito_jwks", expires_in: 1.hour) do
        response = HTTParty.get(COGNITO_CONFIG[:jwks_uri])
        raise "JWKS fetch failed: HTTP #{response.code}" unless response.success?
        response.parsed_response
      end
    end
```

**Why `private` placement at the bottom:** the controller currently has no private methods, but Rails convention is private methods at the end of the class body. The `cognito_jwks` helper is internal to this controller — not part of the public action surface.

The existing rescue covers them all → returns 401 with `{ error: "Invalid token: ..." }`. Do NOT add additional rescues.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05-01 | Spoofing | SessionsController#create id_token branch | mitigate | ASVS V3.1.1 / V7.1.1: RS256 signature verification against Cognito JWKS. `algorithms: ["RS256"]` allow-list prevents algorithm-confusion (e.g., `alg: "none"` or HS256 attacks using public key as HMAC secret). `verify_iss: true` + `verify_aud: true` reject tokens from other Cognito pools or other client apps. | T-04-05-02 | Denial of Service | Cognito JWKS HTTP fetch on every login | mitigate | `Rails.cache.fetch("cognito_jwks", expires_in: 1.hour)` reduces JWKS fetches to ~1/hour per cache backend. Solid Cache is the configured store (per Phase 01) — backed by PostgreSQL, persists across processes. JWKS is small (~1KB) — cache size is negligible. |
| T-04-05-03 | Denial of Service | Cognito JWKS endpoint unreachable (network failure / AWS outage) | accept | If JWKS fetch fails, `cognito_jwks` raises a generic StandardError → propagates to the default Rails 500 handler (NOT caught by `JWT::DecodeError` rescue). This is correct behavior: when the verification material is unavailable, no login should succeed. Risk: temporary OAuth outage during AWS Cognito IDP outages. Acceptable — same outage prevents users from completing PKCE upstream anyway. |
| T-04-05-04 | Elevation of Privilege | skip_before_action :resolve_brokerage on :create | mitigate | Skip is `only: [:create]` — `:destroy` still resolves brokerage for sign-out scoping. `Current.brokerage` is nil during `:create`, but the action does NOT reference `Current.brokerage` in either the OAuth or email/password branches (verified by grep). `User.find_or_initialize_by(cognito_sub:)` is brokerage-agnostic. | T-04-05-05 | Cross-Site Scripting | auth-callback showError DOM injection | mitigate | ASVS V5.3.3: All user-controlled content rendered via `textContent` or property assignment on createElement nodes — never `innerHTML`. `<script>alert(1)</script>` in the message argument renders as literal text. | T-04-05-06 | Information Disclosure | JWKS cache key collision | accept | Cache key `"cognito_jwks"` is global (not namespaced by user/brokerage).
