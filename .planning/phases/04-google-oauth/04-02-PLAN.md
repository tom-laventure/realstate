<objective>
Create the PreSignUp Lambda that links a Google sign-in to an existing Cognito email/password user account. This prevents duplicate account creation when a user who registered with email/password later signs in with Google using the same email.

Purpose: AUTH-02 requirement — account linking must happen atomically at Cognito sign-up time. Without this Lambda, every Google sign-in for an existing email creates a second Cognito user and finds-or-creates a second DB user record.

Output: `lambda/pre_signup/index.js` — Node.js 20.x, AWS SDK v3, ready to zip and upload to AWS Lambda as the Cognito user pool PreSignUp trigger.

<!-- Lambda trigger event shape (from RESEARCH.md Pattern 6 — Cognito PreSignUp trigger) -->

Cognito PreSignUp trigger event structure:
```json
{
  "triggerSource": "PreSignUp_ExternalProvider",
  "userPoolId": "us-east-1_XXXXXXX",
  "userName": "Google_123456789012345678901",
  "request": {
    "userAttributes": {
      "email": "user@example.com",
      "email_verified": "true",
      "given_name": "John",
      "family_name": "Doe",
      "name": "John Doe"
    }
  },
  "response": {}
}
```

Key facts about the event:
- `event.userName` format: `"{ProviderName}_{ProviderUserId}"` (e.g., "Google_115123456789012345678")
- `event.triggerSource` for Google: `"PreSignUp_ExternalProvider"`
- `event.triggerSource` for email/password: `"PreSignUp_SignUp"` — must pass through unchanged
- `email_verified` in userAttributes is a STRING "true"/"false" (not boolean) — evaluate with `=== "true"` not `=== true`
- `DestinationUser.ProviderAttributeName: "email"` is the correct linkage method for email-aliased Cognito pools (NOT "username") — prevents UserNotFoundException when the pool uses email as the username alias

AWS SDK v3 commands used:
- `CognitoIdentityProviderClient` from `@aws-sdk/client-cognito-identity-provider`
- `AdminLinkProviderForUserCommand` from `@aws-sdk/client-cognito-identity-provider`

AdminLinkProviderForUserCommand parameters:
- `UserPoolId`: from `event.userPoolId`
- `DestinationUser.ProviderName`: `"Cognito"` (the existing email/password user)
- `DestinationUser.ProviderAttributeName`: `"email"` (look up by email, not username)
- `DestinationUser.ProviderAttributeValue`: the user's email address
- `SourceUser.ProviderName`: the provider name from `event.userName.split("_")[0]` (e.g., "Google")
- `SourceUser.ProviderAttributeName`: `"Cognito_Subject"` (the federated user's provider-side ID)
- `SourceUser.ProviderAttributeValue`: the provider user ID from `event.userName.split("_")[1]` (the part after the first underscore)

IMPORTANT: `event.userName` split must handle provider IDs that may contain underscores — use `split("_", 2)` which splits into at most 2 parts, taking the first as the provider name and the rest as the provider user ID. However, per AWS docs, the format is `"{ProviderName}_{ProviderUserId}"` and Google user IDs are purely numeric. Use `indexOf("_")` split for safety:
```js
const underscoreIdx = event.userName.indexOf("_")
const providerName = event.userName.substring(0, underscoreIdx)
const providerUserId = event.userName.substring(underscoreIdx + 1)
```

```javascript
/**
 * Cognito PreSignUp Lambda Trigger — Account Linking
 *
 * Triggered before Cognito creates a new user during sign-up.
 * When a Google sign-in matches an existing email/password user,
 * links the Google identity to the existing Cognito account.
 *
 * Runtime: Node.js 20.x
 * Deploy: Upload as zip to AWS Lambda; set as Cognito user pool PreSignUp trigger.
 *
 * Security: Verifies email_verified === "true" before linking to prevent
 * account takeover via an unverified Google email claim.
 */

const {
  CognitoIdentityProviderClient,
  AdminLinkProviderForUserCommand,
} = require("@aws-sdk/client-cognito-identity-provider");

const client = new CognitoIdentityProviderClient({
  region: process.env.AWS_REGION,
});

exports.handler = async (event) => {
  // Pass through all non-federated-provider triggers unchanged.
  // PreSignUp_SignUp (email/password) and PreSignUp_AdminCreateUser
  // must not be intercepted.
  if (event.triggerSource !== "PreSignUp_ExternalProvider") {
    return event;
  }

  const { email, email_verified: emailVerifiedRaw } =
    event.request.userAttributes;

  // email_verified in Cognito userAttributes is a string "true"/"false", not boolean.
  const emailVerified = emailVerifiedRaw === "true";

  // Security gate (AUTH-02): never link without a verified email.
  // An unverified Google email could be used to take over any existing account.
  if (!emailVerified) {
    throw new Error(
      "Google account email is not verified. Sign-in rejected to prevent account takeover."
    );
  }

  // Parse the provider name and provider user ID from the Cognito userName.
  // Format: "{ProviderName}_{ProviderUserId}" (e.g., "Google_115123456789")
  // Google user IDs are purely numeric but we use indexOf for safety.
  const underscoreIdx = event.userName.indexOf("_");
  const providerName = event.userName.substring(0, underscoreIdx);
  const providerUserId = event.userName.substring(underscoreIdx + 1);

  try {
    await client.send(
      new AdminLinkProviderForUserCommand({
        UserPoolId: event.userPoolId,
        // DestinationUser: the existing email/password Cognito user.
        // ProviderAttributeName: "email" looks up by email attribute (not username string).
        // Required for pools with email aliases — prevents UserNotFoundException.
        DestinationUser: {
          ProviderName: "Cognito",
          ProviderAttributeName: "email",
          ProviderAttributeValue: email,
        },
        // SourceUser: the incoming Google federated identity.
        SourceUser: {
          ProviderName: providerName,
          ProviderAttributeName: "Cognito_Subject",
          ProviderAttributeValue: providerUserId,
        },
      })
    );
  } catch (err) {
    // AliasExistsException means this Google account is already linked to
    // the Cognito user — first-link race condition or duplicate trigger.
    // This is not an error: return event and let sign-in proceed normally.
    if (err.name !== "AliasExistsException") {
      throw err;
    }
  }

  return event;
};
```

No `package.json` is needed in the lambda directory — `@aws-sdk/client-cognito-identity-provider` is provided by the Lambda execution environment (AWS SDK v3 is available in all Node.js 20.x Lambda runtimes). If a package.json is desired for local testing, it is optional and out of scope for this plan.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Google OAuth claim → Lambda | event.request.userAttributes comes from Google via Cognito; must not be trusted without email_verified check |
| Lambda → Cognito adminLinkProviderForUser | Lambda has elevated IAM permissions (AmazonCognitoPowerUser or inline policy); it must gate carefully before calling |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Spoofing | email_verified check in Lambda | mitigate | ASVS V2: Lambda verifies `emailVerifiedRaw === "true"` (string, not boolean) before calling adminLinkProviderForUser. If false/absent, throws Error which Cognito surfaces as sign-up failure. Prevents email-impersonation account takeover. |
| T-04-02-02 | Tampering | AliasExistsException handling | mitigate | Only `AliasExistsException` is swallowed (already-linked = no-op). All other errors are re-thrown, causing Cognito to reject the sign-up. This prevents silent failures masking real AWS errors. |
| T-04-02-03 | Elevation of Privilege | Lambda IAM permissions | accept | Lambda requires `cognito-idp:AdminLinkProviderForUser` IAM permission on the user pool. Principle of least privilege — this is a narrow, specific permission. Configuration is an external (AWS console/Terraform) step, not code. |
| T-04-02-04 | Tampering | ProviderAttributeName "email" vs "username" | mitigate | Using `ProviderAttributeName: "email"` (not "username") ensures the lookup finds email-aliased users correctly. "username" lookup can fail silently with UserNotFoundException on email-alias pools. |
</threat_model>
