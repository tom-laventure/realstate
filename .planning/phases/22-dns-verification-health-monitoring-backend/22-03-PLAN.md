Modify `backend/app/models/brokerage.rb`. Add two public instance methods after the existing `phasing_out_count_for` method:

```ruby
# DPRD-01, DPRD-03, DPRD-05: Plan downgrade — freeze all custom domains and promote subdomain to primary.
# Called by Ops::PlanController (manual testing) and future billing webhook (v2).
# IMPORTANT: DomainMailer.downgrade_notice is called AFTER the transaction commits.
def freeze_custom_domains!
  ApplicationRecord.transaction do
    # DPRD-01: freeze active, pending, and phasing_out custom domains
    brokerage_domains.domain_type_custom
                     .where(status: %w[active pending phasing_out])
                     .update_all(status: "frozen")
    # DPRD-03: clear all primary flags, then set subdomain as primary
    brokerage_domains.update_all(is_primary: false)
    brokerage_domains.domain_type_subdomain
                     .status_active
                     .first
                     &.update!(is_primary: true)
  end
  # Email after transaction commits — DPRD-05
  # Note: Plan 02 (DomainMailer) must be complete before this method is invoked in production.
  DomainMailer.downgrade_notice(self).deliver_now!
end

# DPRD-06: Plan re-upgrade — restore frozen custom domains to active.
# Does NOT restore is_primary to frozen domains — owner must manually reassign primary.
def unfreeze_custom_domains!
  brokerage_domains.domain_type_custom
                   .status_frozen
                   .update_all(status: "active")
end
```

IMPORTANT notes:
- `update_all` is safe here for bulk status transitions because:
  - `frozen` does not trigger `status_requires_verified` (only `status_active?` triggers it)
  - For unfreeze (frozen → active), `update_all` bypasses the `status_requires_verified` validation, but previously-active domains were verified. Unfreeze restores them to active correctly.
- Do NOT wrap `unfreeze_custom_domains!` in a transaction — it is a single `update_all` statement (atomic by itself)
- The `deliver_now!` call in `freeze_custom_domains!` is outside the transaction to avoid holding the DB connection during email delivery

1. Create `backend/app/controllers/ops/plan_controller.rb`:

```ruby
module Ops
  # D-06: JSON endpoint for manual freeze/unfreeze of brokerage custom domains.
  # Used for testing before billing webhook integration (v2).
  # Returns JSON — must skip CSRF (inherited from BaseController which has protect_from_forgery).
  class PlanController < BaseController
    skip_before_action :verify_authenticity_token, raise: false
    before_action :set_brokerage

    # POST /ops/brokerages/:brokerage_id/plan
    # Params: { freeze: true|false }
    def update
      freeze = ActiveModel::Type::Boolean.new.cast(params[:freeze])
      if freeze
        @brokerage.freeze_custom_domains!
        render json: {status: "frozen", brokerage_id: @brokerage.id}, status: :ok
      else
        @brokerage.unfreeze_custom_domains!
        render json: {status: "unfrozen", brokerage_id: @brokerage.id}, status: :ok
      end
    rescue ActiveRecord::RecordInvalid => e
      render json: {error: e.message, details: e.record.errors.full_messages}, status: :unprocessable_entity
    rescue => e
      render json: {error: e.message}, status: :unprocessable_entity
    end

    private

    def set_brokerage
      @brokerage = Brokerage.without_deleted.find(params[:brokerage_id])
    rescue ActiveRecord::RecordNotFound
      render json: {error: "Brokerage not found"}, status: :not_found
    end
  end
end
```
