Wire `FreeTierBanner` and `hasPlanCapability` (from Plan 04) into the three brokerage-scoped gated surfaces: Board Registrations (PLAN-04 frontend), the client-invite form in AddUserToGroupView (PLAN-05 frontend, D-04 hide-entirely), and the Domains page (PLAN-08 frontend). The plan-capability check is resolved in each surface's CONTAINER (the `use*Context` hook that already owns the data-flow), which calls `useFetchBrokerage` + `hasPlanCapability` and exposes a plain boolean in its returned `state`. This honors CLAUDE.md's `Component → Context (Brain) → TanStack Hook → API → Axios` rule and keeps `src/components/view/**` pure (no hook calls inside presentational components).

Purpose: These are the UX layer over the backend gates. The banners explain the restriction in context (the user's specific ask, D-09), and D-04 hides the client-invite form entirely rather than letting it fail on submit.
Output: Three container hooks + three parent boards + three pure components modified, each with a co-located RTL render test. No banner uses a CTA/link (UI-SPEC).
</objective>
