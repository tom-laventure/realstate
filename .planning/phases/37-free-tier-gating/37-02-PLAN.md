<objective>
Add the one architecturally-distinct Free-tier gate: calendar sync (PLAN-07). Unlike the board/invite/domain gates, calendar is USER-scoped, not brokerage-scoped (D-06) — `UserCalendarConnection` belongs to `User`, and a user keeps calendar access if ANY of their memberships is paid. Also expose the resulting boolean to the frontend so the Calendar tab can decide banner-vs-provider-grid (consumed by Plan 06).

Purpose: `Current.brokerage` is resolved per-request from Origin/Host and does NOT reflect a user's full membership set — gating calendar on `Current.brokerage.plan_config.calendar_sync` would be the wrong scope (RESEARCH Pitfall 1). The correct check is a fresh cross-brokerage query per request.
Output: New `User#any_paid_brokerage_membership?`, two gated calendar controllers, a new `calendar_sync_available` response field, a new factory, model + integration tests.
</objective>
