# Phase 37 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase does not introduce new pages or major layouts. It is a *restriction* phase — hiding/limiting existing actions (board select, client-invite button, calendar connect UI) and adding one new reusable UI element: an informational restriction banner shown on 4 existing surfaces (D-09 in 37-CONTEXT.md). This contract is scoped accordingly: it declares the banner's visual/copy contract precisely and defers to already-shipped tokens/components for everything else (this codebase has no custom Tailwind theme — it runs on shadcn's default zinc/new-york CSS-variable tokens defined in `frontend/src/index.css`).

| Property | Value |

Reuse what's already installed: `Badge`, `Button`, `Card`, `Dialog`, `Select`, `Popover`, `Tooltip` (all present in `frontend/src/components/ui/`). Do **not** install shadcn's `alert` primitive for the new banner — the codebase already has an established in-house informational-notice pattern (see Color section below); introducing a second visual system for the same purpose would violate CLAUDE.md's "consistency over novelty" rule.

## Spacing Scale

Declared values (must be multiples of 4) — confirmed by existing usage across `frontend/src/components/view/admin/**` (e.g. `p-6`, `gap-2`, `mb-1`, `space-y-4`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside banners (`gap-2` on icon+text row is 8px; use `gap-1.5`/6px only where matching an existing sibling pattern, see exception) |
| sm | 8px | Compact spacing — banner internal padding-y, badge gaps |
| md | 16px | Default banner padding-x (`px-4`), spacing between banner and the page element it explains |
| lg | 24px | Section padding (page-level `p-6` wrappers already in place on Board Registrations / Group detail / Domains / Calendar tab) |
| xl | 32px | Layout gaps — not touched this phase |
| 2xl | 48px | Major section breaks — not touched this phase |
| 3xl | 64px | Page-level spacing — not touched this phase |

Exceptions: `gap-1.5` (6px) is used codebase-wide for icon+label micro-alignment (e.g. `ConnectBoardDialog.tsx` info notice, `DomainCardList.tsx` legend badges). Continue this exact exception for the new banner's icon+heading row — do not introduce a different micro-gap value.

## Typography

Scoped to this phase's touched surfaces (banner copy, hidden/shown labels). Matches existing Tailwind/shadcn defaults already used throughout `frontend/src/components/view/admin/**` — no new scale is being introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (`font-normal`) | 1.5 |
| Label | 12px (`text-xs`) | 500 (`font-medium`) | 1.4 |
| Heading | 16px (`text-base`) | 600 (`font-semibold`) | 1.3 |
| Display | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 |

Application to the new `FreeTierBanner`:
- Banner heading → **Heading** role (16px/600) — e.g. "You're on the Free plan"
- Banner body copy → **Body** role (14px/400)
- Any inline badge/meta text inside the banner → **Label** role (12px/500)
- Page `<h1>` titles the banner sits under (e.g. "Domains", group name) are pre-existing **Display** role — unchanged by this phase.

## Color

This app has no custom color tokens in `tailwind.config.js` — all color comes from shadcn's CSS-variable theme in `frontend/src/index.css` (oklch-based, zinc base).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` / `var(--background)` | Page background, card surfaces |
| Secondary (30%) | `bg-muted` / `bg-secondary` / `border-border` | Cards, section dividers, badges (e.g. "Subdomain" badge) |
| Accent (10%) | `bg-primary` / `text-primary` (near-black in light theme: `oklch(0.21 0.006 285.885)`) | Reserved for: primary action buttons only — "Add domain" button, "Connect" button in `ConnectBoardDialog`, submit buttons. **Not used** by the new restriction banners (banners are informational, not actionable — see Copywriting Contract). |
| Destructive | `text-destructive` / `bg-destructive` (`oklch(0.577 0.245 27.325)`) | Destructive actions and error text only. Not used for restriction banners — a Free-tier restriction is expected/normal state, not an error. |

**New semantic surface for this phase — Info banner:**

| Role | Value | Usage |
|------|-------|-------|
| Info banner surface | `border-blue-200 bg-blue-50 text-blue-800` (light theme) | Reused verbatim from the existing established pattern in `ConnectBoardDialog.tsx` (`test-board-info` step, line ~130) — do not invent a new blue. This is the codebase's only existing "explanatory notice" pattern; it has no dark-mode variant today (pre-existing limitation, not introduced by this phase — do not attempt to fix dark mode as part of this work). |

Accent reserved for: primary CTA buttons that already exist on each page (Add domain, Connect board, group actions). The new restriction banners must **not** use accent/primary color — they are neutral/informational (blue notice box), never styled as a call-to-action.

**Flagged for planner/executor:** `DomainCard.tsx` (line ~193) has an existing "Upgrade plan" button (gated `admin+`) that links to `window.location.href = '/admin/plan'` — this route does not exist anywhere in the frontend router (grep confirms zero route definitions for `/admin/plan`; it is a dead link, likely a placeholder from the BILL-01 stub). **Do not replicate this dead link pattern in the new Phase 37 banners.** Per D-09/D-02 in 37-CONTEXT.md, banners are explanatory text only — no "Upgrade" button/link should be added, since there is no working upgrade destination in this milestone (BILL-01 is v2/out of scope).

## Copywriting Contract

Per 37-CONTEXT.md D-09, four banners are required. Each follows the same shape: bold heading naming the plan, one sentence explaining the specific restriction, no CTA button (see Color section flag above). Component: single reusable `FreeTierBanner` (props: `message: string`, optional `heading` defaulting to `"Free plan"`) — Claude's Discretion item from CONTEXT.md, resolved here as one shared component, not four bespoke banners, to guarantee visual consistency and because the copy structure is identical across all four surfaces.

| Element | Copy |
|---------|------|
| Primary CTA | **None.** This phase removes/restricts actions — it introduces no new call-to-action element. (Existing page-level CTAs like "Add domain" and "Connect" are unchanged; they simply have fewer options for Free-tier brokerages.) |
| Board Registrations banner | Heading: **"Free plan"** · Body: "Only the TEST board is available on the Free plan — it's pre-loaded with sample listings so you can explore the platform. Upgrade to Independent or Growth to connect real MLS/RETS boards." |
| Group detail banner (client-invite hidden) | Heading: **"Free plan"** · Body: "Inviting clients isn't available on the Free plan. Upgrade to Independent or Growth to give clients access to this group." |
| Domains page banner (copy update only — see note below) | Heading: **"Free plan"** · Body: "Custom domains aren't available on the Free plan — your brokerage runs on its subdomain. Upgrade to Independent or Growth to connect your own domain." |
| Account Calendar tab banner (replaces connect UI per D-08) | Heading: **"Free plan"** · Body: "Calendar sync isn't available on the Free plan. Upgrade to Independent or Growth to sync property showings to your calendar." |
| Empty state | Not applicable — this phase creates no new empty-data state. The TEST board is always present (seeded), so the board-select list is never empty for Free-tier brokerages. |
| Error state (403 `plan_required`) | If a client-side race or direct-API-call bypasses the hidden UI and hits a backend 403, surface: "This action requires a paid plan. [Contact your brokerage owner to upgrade / Refresh and try again]" — reuse existing generic error-toast pattern already in the codebase (do not build new error UI for this edge case; it should be rare given D-01–D-08's UI-level hiding). |
| Destructive confirmation | Not applicable — Phase 37 introduces no new destructive actions. (No delete/remove/revoke flows are added; it is purely additive gating + informational banners.) |

**Domains page banner note:** 37-CONTEXT.md D-09 states a "Pro gate" banner already exists on this page from v1.6 (DUI-09) and only needs a copy/terminology update (basic/premium → free/independent/growth). Codebase verification during this research found **no such banner currently rendered** in `DomainCardList.tsx` / `AddDomainWizard.tsx` / `DomainCard.tsx` — the only related artifact is a "Pro gate locked card" design that was specified in `21-UI-SPEC.md` (v1.5) but does not appear to have shipped in current code, and a `DomainCard.tsx` "Frozen" status badge (unrelated — that's for a domain frozen by a *downgrade*, Phase 38 scope, not a gate on *adding* one). **Flag for planner/executor:** verify at plan time whether a Pro-gate banner exists elsewhere (e.g. conditionally rendered, feature-flagged) before assuming "copy update only" — if none exists, this surface needs the same new `FreeTierBanner` treatment as the other three, not just a copy edit.
