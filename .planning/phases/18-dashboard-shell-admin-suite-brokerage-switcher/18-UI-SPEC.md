## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), ChevronDown gap in switcher trigger (`gap-1.5` = 6px — acceptable non-standard gap for tight icon pairing) |
| sm | 8px | Inner vertical stacking in section cards (`gap-3` = 12px between icon and label) |
| md | 16px | Grid gap between section cards (`gap-4`); nav bar horizontal padding (`px-4`) |
| lg | 24px | Section card inner padding (`p-6`) |
| xl | 32px | Dashboard main content vertical padding (`py-8`) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Nav bar height: `h-16` (64px) — matches existing `NavBar.tsx` exactly. Non-token height, established in Phase 16.
- Dashboard max-width: `max-w-lg` (512px) — wider than auth screens (`max-w-sm` = 384px) because this is the actual dashboard landing, not a transient auth card.
- Dashboard horizontal screen padding: `px-6` (24px) — consistent with all portal screens.
- `gap-1.5` (6px) between brokerage name and ChevronDown in switcher trigger — tight icon pairing, acceptable deviation.

Source: `NavBar.tsx` + `BrokerageSelection.tsx` + `PortalShell.tsx` spacing patterns (verified 2026-05-26)

## Card Pattern (CRITICAL — Phase 18 Extension)

Phase 18 introduces two new visual surfaces:

### 1. PortalNavBar surface

Adopts `bg-sidebar border-b border-sidebar-border` — matches the existing `NavBar.tsx` outer frame exactly. The portal nav bar is visually indistinguishable from the brokerage subdomain nav bar in its chrome, even though the content differs (no notifications, no logo — brokerage name + switcher instead).

Do NOT use `bg-background` or `bg-card` for the nav bar.

### 2. Dashboard section link cards (raw div card — NOT shadcn Card)

Phase 18 is the portal landing page — the user has just selected their brokerage. While this is the "actual dashboard," the design context places it as a portal entry point before drilling into admin panels via `/admin/*`. The raw div card pattern is preserved for the section link cards to maintain visual consistency with the portal card language established in Phases 16–17.

The shadcn `<Card>` pattern is appropriate for content inside the admin panels (`/admin/*`) — those screens are outside Phase 18 scope.

**Section link card pattern:**
```tsx
<button
    className="rounded-xl border border-border bg-card p-6 flex flex-col gap-3 text-left transition-colors hover:bg-muted/50 focus-visible:outline-none focus-visible:ring-1 focus-visible:ring-primary/30 w-full"
    onClick={() => navigate('/admin/users')}
>
    <Users className="h-5 w-5 text-muted-foreground" />
    <div className="text-sm font-semibold text-foreground">Users</div>
</button>
```

Do NOT use `<Card>`, `<CardHeader>`, `<CardTitle>`, `<CardDescription>`, or `<CardContent>` for `PortalShell` or `PortalNavBar`.

Source: D-09 from 18-CONTEXT.md; Phase 16 + Phase 17 raw div card rationale (verified 2026-05-26)

### Screen 2: PortalNavBar Component

**Purpose:** Persistent nav bar for the portal dashboard. Shows active brokerage name (as switcher trigger), role badge, and sign-out.

**Outer structure** (mirrors `NavBar.tsx` exactly):
```tsx
<header className="border-b border-sidebar-border bg-sidebar">
    <div className="flex h-16 items-center justify-between gap-3 px-4">
        <div>{/* left: brokerage switcher */}</div>
        <div className="flex items-center gap-2">{/* right: role badge + sign-out */}</div>
    </div>
</header>
```

**Left side — Brokerage Switcher (D-11, D-13):**
```tsx
<DropdownMenu>
    <DropdownMenuTrigger asChild>
        <Button
            variant="ghost"
            className="flex items-center gap-1.5 px-2 text-sm font-semibold text-sidebar-foreground hover:bg-sidebar-accent hover:text-sidebar-accent-foreground"
        >
            {activeBrokerage.name}
            <ChevronDown className="h-4 w-4 text-muted-foreground" />
        </Button>
    </DropdownMenuTrigger>
    <DropdownMenuContent align="start" className="w-52">
        {adminBrokerages.map((b) => (
            <DropdownMenuItem key={b.id} onClick={() => handleSwitch(b)} className="flex items-center justify-between">
                <span>{b.name}</span>
                {b.id === activeBrokerage.id && <Check className="h-4 w-4 text-primary" />}
            </DropdownMenuItem>
        ))}
    </DropdownMenuContent>
</DropdownMenu>
```

Notes:
- `w-52` (208px) dropdown — sufficient for typical brokerage names without being oversized.
- Active brokerage gets `Check` icon in `text-primary` — the only accent color in this component.
- `ChevronDown` uses `text-muted-foreground` — visual affordance signal, not primary content.
- Trigger uses `gap-1.5` (6px) — tight coupling of name + chevron reads as one unit.
- `align="start"` — dropdown opens below the left edge of the trigger, not the right.

**Right side — Role badge + Sign-out:**
```tsx
<div className="flex items-center gap-2">
    <span className="inline-flex items-center rounded-full bg-muted px-2 py-0.5 text-xs text-muted-foreground capitalize">
        {activeBrokerage.role}
    </span>
    <Button
        variant="ghost"
        size="sm"
        onClick={handleSignOut}
        className="text-sidebar-foreground hover:bg-sidebar-accent hover:text-sidebar-accent-foreground"
    >
        Sign Out
    </Button>
</div>
```

Notes:
- Role badge identical to Phase 17 `BrokerageSelection.tsx` role badge — `bg-muted text-muted-foreground capitalize`. Do not use a `Badge` component (none installed).
- Sign-out: `variant="ghost" size="sm"` — consistent with secondary nav actions in existing `NavBar.tsx`.
- `gap-2` (8px) between role badge and sign-out button — tight, cohesive right cluster.
- Text: "Sign Out" — exact same copy as `NavBar.tsx` account dropdown item. Never "Logout" or "Log out".

**Null guard:** If `activeBrokerage` is null, `return null`. The loading state (spinner card) in `PortalShell` renders while brokerage validation is in progress, before `PortalNavBar` is mounted.

## Interaction Contracts

### Interaction 1: Section card — navigate to admin panel

| State | Visual |
|-------|--------|
| Idle | `border-border bg-card` at rest |
| Hover | `bg-muted/50` tint — signals navigation affordance |
| Focus-visible | `ring-1 ring-primary/30` — keyboard navigation signal |
| Click | `navigate('/admin/...')` — immediate client-side navigation |

No loading state on the section cards. Admin routes are registered and render synchronously (no lazy loading).

### Interaction 2: Brokerage switcher — open dropdown

| State | Visual |
|-------|--------|
| Idle | Brokerage name + `ChevronDown` at rest |
| Hover | `hover:bg-sidebar-accent hover:text-sidebar-accent-foreground` tint on trigger |
| Dropdown open | `DropdownMenuContent` opens below trigger, align start, `w-52` |
| Active brokerage row | `Check` icon (primary color) on right side |
| Non-active rows | Name only, no indicator |

### Interaction 3: Brokerage switch (D-14)

1. User clicks a non-active brokerage in the dropdown.
2. `dispatch(setActiveBrokerage(selected))` → Redux updated immediately.
3. `navigate('/dashboard/:newId')` → `PortalShell` re-runs its mount effect with the new `brokerageId`.
4. `PortalShell` validates new ID against `adminBrokerages[]` in Redux (already populated) → dispatches updated `activeBrokerage` → re-renders dashboard with new brokerage context.
5. `PortalNavBar` re-renders with the new brokerage name from Redux.
6. All admin panel data re-fetches automatically when the user navigates to an admin panel (existing panels fetch on mount, scoped by the Axios interceptor's `X-Brokerage-Id`).
7. No explicit loading state in the nav bar during the switch — transition is instantaneous at the Redux/routing level.

### Interaction 4: Sign-out

1. User clicks "Sign Out" button.
2. `signOut({ global: true })` via AWS Amplify.
3. `clearToken()` clears localStorage auth token.
4. `window.location.href = '/auth/login'` — hard redirect, same as `NoAccess.tsx` and existing `NavBar.tsx`.

No confirmation dialog. Sign-out is reversible (user can sign back in).

## Accessibility

- `PortalNavBar` brokerage switcher: `DropdownMenuTrigger asChild` wraps a `<Button>` — keyboard accessible, announces as button, Radix manages focus trap in dropdown.
- Section cards: native `<button>` elements — keyboard accessible by default, in natural tab order.
- Focus rings: `focus-visible:ring-1 focus-visible:ring-primary/30` on all interactive elements — visible keyboard signal. Never removed without a replacement.
- Role badge: `capitalize` CSS + semantic text — screen readers announce "Owner" or "Admin" from text node.
- `Check` icon on active brokerage: visual indicator. The dropdown item text (brokerage name) is the primary accessible label; the check is supplementary. Acceptable for a temporary dropdown context.
- Sign-out button: "Sign Out" label is self-describing — no `aria-label` needed.
- `ChevronDown` icon in switcher trigger: decorative — add `aria-hidden="true"` or let Radix handle it via `asChild` passthrough.
- Color contrast: `text-sidebar-foreground` on `bg-sidebar` — inherits Phase 16 verification (passes WCAG AA). `text-foreground` on `bg-background` — passes 4.5:1. `text-muted-foreground` on `bg-card` — sufficient for 14px regular labels.
- No modals or focus traps beyond the `DropdownMenu` — Radix/shadcn manages focus restoration on close.
- `<main>` landmark element wraps the dashboard content — correctly scoped for screen reader navigation.
