## Card Pattern (CRITICAL — inherited from Phase 16)

Phase 17 screens are siblings of the auth-destination screens established in Phase 16. All new screens use the **raw div card pattern** — not the shadcn `<Card>` component.

**Rationale:** `BrokerageSelection` and `PortalShell` are transient routing destinations — the user has just signed in or been redirected from the wizard. They sit in the same position in the user journey as `LoginSuccessful`, `NoAccess`, and `DashboardPlaceholder`. Visual consistency requires matching the exact card construction. The shadcn `<Card>` pattern is reserved for access-gated content screens (user is inside an app context with a nav shell — Phase 18 scope).

### Outer wrapper (required for all new screens)

```tsx
<div className="flex min-h-screen items-center justify-center bg-background px-6 w-full">
    <div className="flex w-full max-w-sm flex-col items-center gap-4 rounded-2xl border border-border bg-card p-8 text-center shadow-sm">
        {/* screen content */}
    </div>
</div>
```

Do NOT use `<Card>`, `<CardHeader>`, `<CardTitle>`, `<CardDescription>`, or `<CardContent>` for any Phase 17 components.

### Brokerage selection card (inner — per brokerage)

Each brokerage in the list uses a separate interactive div card:

```tsx
<button
    className="w-full rounded-xl border border-border bg-card px-5 py-4 text-left shadow-sm transition-colors hover:bg-muted/50 focus-visible:outline-none focus-visible:ring-1 focus-visible:ring-primary/30"
    onClick={() => navigate(`/dashboard/${brokerage.id}`)}
>
    <div className="text-lg font-semibold text-foreground">{brokerage.name}</div>
    <div className="mt-1">
        <span className="inline-flex items-center rounded-full bg-muted px-2 py-0.5 text-xs text-muted-foreground capitalize">
            {brokerage.role}
        </span>
    </div>
</button>
```

Notes:
- Use a `<button>` element (not a `<div>`) for the per-brokerage card — keyboard accessible by default, no ARIA workaround needed.
- `text-left` overrides the parent `text-center` from the outer wrapper — brokerage name and badge should be left-aligned within each card.
- `w-full` ensures each card spans the full max-w-sm container.
- `hover:bg-muted/50` provides clear affordance without requiring an explicit "Select" button inside the card.

Source: D-08 from 17-CONTEXT.md + Phase 16 UI-SPEC.md card pattern (verified 2026-05-25)

## Screen Contracts

### Screen 1: Brokerage Selection (`/dashboard`)

**Replaces:** `DashboardPlaceholder.tsx`

**Purpose:** Multi-brokerage admins choose which brokerage context to enter. Single-brokerage admins are auto-redirected without seeing this screen.

**Auto-redirect (BROK-02, D-07):** On mount, if `adminBrokerages.length === 1`, dispatch `setActiveBrokerage(adminBrokerages[0])` and `navigate('/dashboard/${adminBrokerages[0].id}', { replace: true })` immediately — no UI rendered.

**Layout:** `flex min-h-screen items-center justify-center bg-background px-6 w-full`

**Outer card:** `flex w-full max-w-sm flex-col items-center gap-4 rounded-2xl border border-border bg-card p-8 text-center shadow-sm`

**Structure (top to bottom):**
1. Heading div: `text-lg font-semibold text-foreground` — "Select a brokerage"
2. Subtitle div: `text-sm text-muted-foreground` — "Choose the brokerage you want to manage."
3. List of brokerage cards: `flex flex-col gap-3 w-full` — one `<button>` per `AdminBrokerage`
   - Each card: `w-full rounded-xl border border-border bg-card px-5 py-4 text-left shadow-sm transition-colors hover:bg-muted/50 focus-visible:outline-none focus-visible:ring-1 focus-visible:ring-primary/30`
   - Brokerage name: `text-lg font-semibold text-foreground`
   - Role badge: `inline-flex items-center rounded-full bg-muted px-2 py-0.5 text-xs text-muted-foreground capitalize` below the name with `mt-1` spacing

**Click behavior:** Entire card button is the tap target. On click: dispatch `setActiveBrokerage(brokerage)` → `navigate('/dashboard/${brokerage.id}')`.

**No explicit "Select" button inside the card.** The whole card is the interactive surface.

Source: D-08, D-09 from 17-CONTEXT.md; BROK-01, BROK-02 from REQUIREMENTS.md (verified 2026-05-25)

### Screen 2: Portal Shell (`/dashboard/:brokerageId`)

**Purpose:** Minimal placeholder proving `/dashboard/:brokerageId` routes render correctly. Phase 18 builds the actual dashboard content here.

**On mount behavior (D-06, D-12, D-13):**
1. Read `:brokerageId` from URL params.
2. If `adminBrokerages` in Redux is non-empty: find matching brokerage. If found, dispatch `setActiveBrokerage`. If not found (URL tampering), `navigate('/dashboard', { replace: true })`.
3. If `adminBrokerages` in Redux is empty (wizard redirect case — `LoginSuccessful` was not the entry point): call `fetchAdminBrokerages()`, show loading spinner during fetch. On resolve: validate and dispatch. On error: redirect to `/dashboard`.

**Loading state (D-13):**

**Layout:** `flex min-h-screen items-center justify-center bg-background px-6 w-full`

**Card:** `flex w-full max-w-sm flex-col items-center gap-4 rounded-2xl border border-border bg-card p-8 text-center shadow-sm`

**Loading structure:**
1. Spinner: `h-12 w-12 animate-spin rounded-full border-4 border-primary/20 border-t-primary` — identical to `LoginSuccessful` loading spinner
2. Heading: `text-lg font-semibold text-foreground` — "Loading your workspace"
3. Body: `text-sm text-muted-foreground` — "Preparing your brokerage dashboard…"

**Resolved state (brokerage validated):**
Same outer card layout. Structure:
1. Heading: `text-lg font-semibold text-foreground` — "Admin Portal"
2. Body: `text-sm text-muted-foreground` — "Your brokerage dashboard is being prepared."

**No button, no further action.** Phase 18 replaces this content entirely.

Source: D-05, D-06, D-12, D-13 from 17-CONTEXT.md (verified 2026-05-25)

## Interaction Contracts

### Interaction 1: Brokerage card click

| State | Visual |
|-------|--------|
| Idle | Card at default styles — `border-border bg-card shadow-sm` |
| Hover | `bg-muted/50` background tint — signals clickability |
| Focus-visible | `ring-1 ring-primary/30` — keyboard navigation indicator |
| Active (click) | `navigate()` is called; component unmounts; no loading spinner shown on this screen |

No loading state on the selection screen itself — navigation is client-side and instantaneous. The PortalShell handles any async fetch after navigation.

### Interaction 2: Auto-redirect (single brokerage, BROK-02)

No UI rendered. On mount, if `adminBrokerages.length === 1`, immediately call `navigate('/dashboard/${id}', { replace: true })`. The user never sees the selection screen. No spinner, no flash.

### Interaction 3: PortalShell loading (empty Redux on direct URL entry, D-13)

| State | Trigger | Visual |
|-------|---------|--------|
| Loading | `adminBrokerages` empty in Redux on mount | Spinner card (loading copy) |
| Validated | Fetch succeeds, brokerageId matches | Static placeholder card (resolved copy) |
| Invalid brokerageId | ID not in fetched list | `navigate('/dashboard', { replace: true })` — no error UI shown |
| Fetch error | API failure | `navigate('/dashboard', { replace: true })` — no error UI shown |

## Accessibility

- `BrokerageSelection` brokerage cards use native `<button>` elements — keyboard accessible, focusable in tab order, no ARIA role needed.
- Focus ring on brokerage cards: `focus-visible:ring-1 focus-visible:ring-primary/30` — visible keyboard signal. Never removed without replacement.
- Role badge text is lowercase from the database (`owner`, `admin`) and should be `capitalize` CSS — screen readers will announce "owner" or "admin" correctly from the text node.
- Spinner in `PortalShell` loading state: add `role="status" aria-label="Loading your workspace"` on the spinner div — announces loading state to screen readers.
- No modals, overlays, or focus traps in this phase.
- Color contrast: `text-foreground` on `bg-card` exceeds WCAG AA 4.5:1. `text-muted-foreground` on white — sufficient at 14px regular per Phase 16 verification.
- `hover:bg-muted/50` on brokerage cards does not rely on color alone — card boundary (border) provides a secondary visual signal.
