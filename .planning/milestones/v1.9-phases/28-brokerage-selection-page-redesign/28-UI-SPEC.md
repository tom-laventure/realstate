## Color

All colors use shadcn CSS variables (zinc base, light mode default).

| Role | CSS Variable | Usage |
|------|-------------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)` = white) | Full page background surface |
| Secondary (30%) | `--card` (`oklch(1 0 0)`) + `--border` | Brokerage cards (white on white, separated by border + shadow) |
| Accent (10%) | `--primary` (`oklch(0.21 0.006 285.885)` ≈ near-black zinc) | Card hover ring (`focus-visible:ring-primary/30`), card border on hover |
| Muted surface | `--muted` (`oklch(0.967 0.001 286.375)`) | Role badge background (secondary variant) |
| Muted text | `--muted-foreground` (`oklch(0.552 0.016 285.938)`) | Stats line (`clientCount · memberCount`), owner names |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)`) | Not used in this phase |

**Accent reserved for:** card focus-visible ring only. No other elements use `--primary` as an accent in this phase.

**60/30/10 interpretation for this page:** The page is a light neutral surface (white background, white cards) — visual hierarchy comes from border, shadow, and typography weight rather than strong color contrast. Cards lift from the page via `border border-border shadow-sm`.

**Card hover state:** `hover:bg-muted/50` (existing pattern from current `BrokerageSelection.tsx`) — subtle zinc tint on pointer entry.

Source: `frontend/src/index.css` (all CSS variable values), existing `BrokerageSelection.tsx` (hover pattern).

Existing shadcn components to reuse (no new installations required):

| `Card` | `@/components/ui/card` | Brokerage card wrapper (no CardHeader/CardContent split per D-01) |

**Badge variant decision:** Use `secondary` (zinc muted background, dark text). Rationale: `secondary` (`--muted` background, `--secondary-foreground` text) reads as a quiet label — appropriate for a role indicator that is informational, not actionable. `outline` (border-only) is also valid but `secondary` visually groups better with the muted stat line below it.

## Interaction Contracts

### Loading State

While `isLoading === true` or `adminBrokerages.length === 0` after mount fetch:

- Render a centered spinner card — preserve existing loading UI from current `BrokerageSelection.tsx` (spinner + "Loading your workspace" heading + "Preparing your brokerage dashboard…" subtext)
- The loading card uses the existing `max-w-sm` centered layout — acceptable for loading state even though the full page is not centered. No redesign of loading state required.
- Spinner: `h-12 w-12 animate-spin rounded-full border-4 border-primary/20 border-t-primary`

Source: existing `BrokerageSelection.tsx` (loading JSX preserved), Claude's Discretion.

### Single-Brokerage Auto-Redirect

- After fetch resolves: if `adminBrokerages.length === 1`, dispatch `setActiveBrokerage` and call `navigate('/dashboard/${id}', { replace: true })` immediately.
- User never sees the selection page.
- Guard: only fires when loading is complete and length is exactly 1.

Source: D-09, D-10 (CONTEXT.md).

### Card Click Navigation

- Clicking anywhere on the card dispatches `setActiveBrokerage(brokerage)` then calls `navigate('/dashboard/${brokerage.id}')`.
- No secondary confirm step.
- Keyboard: card must be reachable via Tab and activatable via Enter/Space.

Source: D-02 (CONTEXT.md).

### Hover / Focus Transitions

- Duration: `transition-all duration-150` — fast enough to feel responsive, not jarring.
- Hover: muted background tint + slightly elevated shadow.
- Focus-visible: 2px ring in `primary/30`.

### Error State

When the re-fetch on mount fails (`.catch()` branch in `BrokerageSelection.tsx`): navigate to `/no-access` with `{ replace: true }`. No in-page error UI is rendered. Source: existing `BrokerageSelection.tsx` (preserved behavior).

## Accessibility Baseline

- Page heading is a semantic `<h1>`.
- Optional subtitle is a `<p>` immediately following the `<h1>`.
- Each brokerage card is a `<button>` element (or `<div role="button" tabIndex={0}>`), ensuring keyboard navigability.
- Focus-visible ring is always present (never suppressed).
- Spinner has `role="status"` and `aria-label="Loading your workspace"` (preserve from existing implementation).
- Role badge text is visible — do not rely on color alone to convey role.
- Sufficient contrast: muted-foreground on background meets WCAG AA for informational text at 14px.
