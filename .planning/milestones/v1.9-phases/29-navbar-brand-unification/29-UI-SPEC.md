## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`) — chevron next to brokerage name |
| sm | 8px | Button padding, gap between right-side actions (`gap-2`) |
| md | 16px | Horizontal navbar padding (`px-4`) |
| lg | 24px | Left-side flex spacing |
| xl | 32px | — |
| 2xl | 48px | — |
| 3xl | 64px | Navbar height: `h-16` = 64px |

Exceptions:
- Navbar height is locked at `h-16` (64px) — matches both existing navbars exactly.
- Logo wrapper click target in PortalNavBar uses `-p-1` Button ghost padding so the img is not overly padded.
- Touch targets for icon-only buttons (`size="icon"`) render at 36px × 36px (shadcn default); sufficient for pointer devices in this admin context.
- 12px (`gap-3`): inner switcher left section spacing — unlisted intermediate, multiple of 4.

## Component Anatomy

### DashboardNavBar (new — `frontend/src/containers/portal/DashboardNavBar.tsx`)

```
<header class="border-b border-sidebar-border bg-sidebar">
  <div class="flex h-16 items-center justify-between gap-3 px-4">

    <!-- Left: brand logo (static, no click) -->
    {VITE_BRAND_LOGO_URL &&
      <img
        src={import.meta.env.VITE_BRAND_LOGO_URL}
        alt="Platform logo"
        class="h-8 max-w-[8rem] object-contain"
        aria-hidden="true"   <!-- decorative; screen readers identify app by page title -->
      />
    }

    <!-- Right: account dropdown -->
    <DropdownMenu>
      <DropdownMenuTrigger asChild>
        <Button
          variant="ghost"
          size="icon"
          aria-label="account menu"
          class="text-sidebar-foreground hover:bg-sidebar-accent hover:text-sidebar-accent-foreground"
        >
          <UserCircle class="h-5 w-5" />
        </Button>
      </DropdownMenuTrigger>
      <DropdownMenuContent align="end" class="w-44">
        <DropdownMenuItem>Account Settings</DropdownMenuItem>
        <DropdownMenuItem>Sign Out</DropdownMenuItem>
      </DropdownMenuContent>
    </DropdownMenu>

  </div>
</header>
```

**Logo sizing rationale:** `h-8` (32px) — one step down from NavBar's `h-10` (40px) because the DashboardNavBar has no brokerage context to visually compete with; smaller logo keeps the navbar clean. `max-w-[8rem]` prevents wide logos from consuming too much horizontal space.

### PortalNavBar (modified — `frontend/src/containers/portal/PortalNavBar.tsx`)

```
<!-- Left div: brand logo (clickable) + brokerage switcher dropdown -->
<div class="flex items-center gap-2">

  {VITE_BRAND_LOGO_URL &&
    <button
      onClick={() => navigate('/dashboard')}
      aria-label="Go to brokerage selection"
      class="rounded-md p-1 hover:bg-sidebar-accent focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring"
    >
      <img
        src={import.meta.env.VITE_BRAND_LOGO_URL}
        alt="Platform logo"
        class="h-8 max-w-[8rem] object-contain"
      />
    </button>
  }

  <DropdownMenu>  <!-- existing switcher, trigger text: {activeBrokerage.name} + ChevronDown only -->
    ...
  </DropdownMenu>

</div>
```

**Per-brokerage logo removal:** `brokerageData?.logoUrl` img inside the `DropdownMenuTrigger` is deleted. The trigger retains only the brokerage name text and `ChevronDown` icon (`gap-2` between them).

**Gap between brand logo and switcher:** `gap-2` (8px) — tight enough to read as a unit, loose enough to be distinct elements.

**Wrapper element choice:** Plain `<button>` element (not shadcn `Button`) for the logo click wrapper. Using `Button variant="ghost"` would add default horizontal padding that distorts logo proportions. The plain `<button>` with explicit `p-1` is cleaner.

## Interaction States

### Brand logo in DashboardNavBar (static)
- No hover, no focus ring, no cursor change.
- `cursor-default` (browser default for img).
- `aria-hidden="true"` — purely decorative; the page `<title>` carries the app name.

### Brand logo button in PortalNavBar (clickable)
- Default: img rendered as-is.
- Hover: `hover:bg-sidebar-accent` on the `<button>` wrapper (subtle background tint).
- Focus-visible: `focus-visible:ring-2 focus-visible:ring-ring` — visible keyboard focus ring.
- Active/click: navigates to `/dashboard` synchronously via `navigate('/dashboard')`.
- `aria-label="Go to brokerage selection"` on the `<button>` wrapper.

### Account dropdown trigger (DashboardNavBar)
- Trigger: `Button variant="ghost" size="icon"` with `UserCircle h-5 w-5` icon.
- `aria-label="account menu"` — matches NavBar.tsx pattern exactly.
- Hover: `hover:bg-sidebar-accent hover:text-sidebar-accent-foreground`.
- Focus-visible: shadcn Button default focus ring.
- Dropdown opens: `align="end"`, width `w-44`.

### Account dropdown items (DashboardNavBar)
- "Account Settings": `onClick` → `navigate('/account')`.
- "Sign Out": `onClick` → `signOut({ global: true })` + `dispatch(clearActiveBrokerage())` + `clearToken()` + `window.location.href = '/auth/login'`.
- Both items: standard `DropdownMenuItem` hover state (shadcn default: `focus:bg-accent`).

### Absent brand logo (VITE_BRAND_LOGO_URL empty/undefined)
- Condition: `import.meta.env.VITE_BRAND_LOGO_URL` is falsy.
- Result: the `<img>` element AND its wrapper (if any) are not rendered — no empty space, no broken-image icon.
- Left side of DashboardNavBar shows nothing (right side account menu unchanged).
- Left side of PortalNavBar shows only the brokerage switcher (no gap or placeholder).
- No broken `<img>` tag is ever rendered — guard condition must be checked before rendering.
