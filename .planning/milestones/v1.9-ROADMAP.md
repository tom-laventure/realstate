# Milestone v1.9: Dashboard & Navbar Enhancement

**Status:** ✅ SHIPPED 2026-06-06
**Phases:** 27–29
**Total Plans:** 5

## Overview

Enriched the main-domain brokerage selection experience and unified SaaS branding across both main-domain navbars. Backend endpoint extended to return per-brokerage context in a single response; frontend redesigned from a narrow centered panel to a full-width card grid; new `DashboardNavBar` component created for the selection screen; `PortalNavBar` updated with a clickable brand logo sourced from a single env var.

## Phases

### Phase 27: Backend Enrichment + Frontend Types

**Goal**: The admin brokerages endpoint returns per-brokerage context (client count, member count, owner names) in a single response, and the frontend type system is ready to consume it.
**Depends on**: Nothing (first phase of milestone)
**Requirements**: DASH-01, DASH-02
**Plans**: 2 plans

Plans:
- [x] 27-01: Enrich AdminBrokeragesController#index with bulk membership query (backend)
- [x] 27-02: Extend AdminBrokerage TypeScript interface + correct REQUIREMENTS.md label (frontend)

**Success Criteria:**
1. `GET /v1/account/admin_brokerages` returns `client_count`, `member_count`, and `owners` for each brokerage with no additional network requests
2. Frontend `AdminBrokerage` interface includes `clientCount`, `memberCount`, `owners: { firstName: string; lastName: string }[]` as required fields

**Key Decisions:**
- Inline hash derivation (no serializer) — payload is small; dedicated serializer adds overhead without benefit
- Bulk membership query pattern: collect IDs, guard empty, fire one scoped query, `group_by` in Ruby for stats derivation
- Required fields (no `?`) — endpoint always returns all three; optional would force nullish checks in Phase 28

### Phase 28: Brokerage Selection Page Redesign

**Goal**: The `/dashboard` brokerage selection screen uses a full-width layout and each card surfaces the enriched per-brokerage data delivered by Phase 27.
**Depends on**: Phase 27
**Requirements**: DASH-03, DASH-04
**Plans**: 1 plan

Plans:
- [x] 28-01: Create BrokerageCard component + rewrite BrokerageSelection with full-width layout and auto-redirect

**Success Criteria:**
1. `/dashboard` page no longer centers cards in a narrow panel — layout spans full viewport width
2. Each brokerage card displays name, role badge, client count, agent count, and all owner full names
3. Edge cases: zero clients, multiple owners, single-brokerage auto-redirect fires without layout breakage

**Key Decisions:**
- Button-as-card pattern: apply shadcn card classes directly to `<button>` element — no div wrapper nesting
- Auto-redirect as synchronous conditional after loading guard (not `useEffect`) per D-10
- `Badge variant=secondary` — muted background reads as informational, not actionable
- Owners row omitted entirely (not placeholder) when `owners` array is empty

### Phase 29: Navbar Brand Unification

**Goal**: Both main-domain navbars display the SaaS brand logo sourced from a single env var, and the `/dashboard` selection screen has its own dedicated navbar with account menu only.
**Depends on**: Phase 28
**Requirements**: DASH-05, DASH-06, DASH-07
**Plans**: 2 plans

Plans:
- [x] 29-01: Create DashboardNavBar + wire into BrokerageSelection + add VITE_BRAND_LOGO_URL to .env.example
- [x] 29-02: Add clickable brand logo to PortalNavBar left of switcher, remove per-brokerage trigger logo

**Success Criteria:**
1. `/dashboard` page shows a navbar with brand logo on left + account menu (Account Settings + Sign Out) on right — no brokerage selector or role badge
2. `PortalNavBar` shows brand logo as clickable `<button>` (→ `/dashboard`) immediately left of brokerage selector dropdown
3. `VITE_BRAND_LOGO_URL` is single env-var source for both navbars; absence gracefully hides logo in both places

**Key Decisions:**
- `DashboardNavBar` is new standalone component (not `NavBar.tsx` with props) — avoids importing notifications bell and auth hooks not needed on `/dashboard`
- Plain `<button>` (not shadcn `Button`) for brand logo in `PortalNavBar` — `Button variant=ghost` adds horizontal padding that distorts logo proportions
- `navigate('/dashboard')` target hardcoded literal — env var never flows into navigation (security)
- Brand logo static (no click handler) in `DashboardNavBar` — user is already on `/dashboard`
