# Requirements: RealState SaaS Platform — v1.11 Brokerage Ownership Management

**Defined:** 2026-07-12
**Core Value:** Brokerage agents can discover, evaluate, and coordinate on listings inside their isolated workspace — safely and reliably.

## v1.11 Requirements

Requirements for this milestone. Each maps to roadmap phases.

### Settings Page

- [x] **SET-01**: `/admin/settings` page exists with Ownership Management as the first (and currently only functional) section; a Billing section is stubbed below it with a `# TODO: Add billing management section` comment, not rendered as user-facing UI
- [x] **SET-02**: Owners have full access to the Ownership Management section (view + all add/remove actions); admins and agents have read-only access (owner list + role descriptions, no action buttons); clients have no access to `/admin/settings` at all (existing route guard handles this — no new guard needed)

### Current Owners

- [x] **OWN-01**: Current Owners section lists all brokerage owners, each entry showing full name + email (no avatars, no timestamps)

### Add Owner

- [x] **OWN-02**: "Add Owner" action is visible to owners only
- [x] **OWN-03**: Add Owner opens a modal (Dialog/AlertDialog) containing a searchable dropdown filtered to brokerage users whose current role is `admin` or `agent` (clients excluded); each option shows name + current role; a note beneath the dropdown reads "Only admins and agents can be promoted to owner."
- [x] **OWN-04**: Add Owner modal displays clear warning copy explaining what owner-level permissions grant, before the confirm action
- [x] **OWN-05**: Confirming Add Owner calls the promote API; the promoted user's previous role is fully replaced by `owner` (no memory of prior role stored); on success, the owners query key is invalidated to refetch the list
- [x] **OWN-13**: *(Added Phase 35, amends OWN-03/OWN-04 UI)* Add Owner modal gains a final review step after the existing warning: a summary screen showing the selected user and the change about to be made, with the single confirm button that triggers the promote API living on this review step (not on the warning step). Brings Add Owner's step structure in line with Remove Owner's three-step pattern (OWN-07).

### Remove Owner

- [x] **OWN-06**: Each owner entry has a Remove action, visible to owners only
- [x] **OWN-07**: *(Amended during Phase 35 discussion — was two-step)* Remove Owner opens a three-step modal: Step 1 is a warning explaining what removing this user's owner access means, recommending reassignment to `client` only if the goal is to fully remove the user's admin privileges; Step 2 is a required role picker (radio group) with options `admin`, `agent`, `client`, defaulting to `admin`; Step 3 is a final review screen summarizing the target user and the selected role change, with a single confirm button that triggers the API.
- [x] **OWN-08**: Confirming step 3 calls the demote API to reassign the owner to the selected role; on success, the owners query key is invalidated to refetch the list
- [x] **OWN-09**: Self-demotion is allowed as long as at least one other owner remains after the change
- [x] **OWN-10**: If the target is the only owner, the Remove button is disabled with a tooltip explaining why removal is blocked

### Backend API

- [x] **API-01**: `GET /admin/settings/owners` returns the list of current brokerage owners (name, email)
- [x] **API-02**: `GET /admin/settings/owners/eligible` returns brokerage users with role `admin` or `agent`, for the Add Owner dropdown
- [x] **API-03**: `POST /admin/settings/owners` promotes a user to owner; requires the caller to have the `owner` role
- [x] **API-04**: `PATCH /admin/settings/owners/:id` demotes an owner and reassigns their role to `admin`/`agent`/`client`; requires the caller to have the `owner` role; rejects the request if the target is the last owner
- [x] **API-05**: All new endpoints validate the caller's role via JWT claims server-side — frontend role gates are UX-only and must not be the sole enforcement

### Lockdown (existing add-agent endpoint)

- [x] **LOCK-01**: `POST /admin/brokerage/add-agent` rejects `owner` role assignment with HTTP 403 Forbidden — owner role can only be assigned via the new settings endpoint
- [x] **LOCK-02**: The role selector on the `/admin/brokerage/add-agent` frontend page no longer offers "owner" as an option (only `admin` and `agent` assignable there)
