  <what-built>
    A new "Plan" section on `/admin/settings` (below Ownership Management): a 3-way segmented selector (Free / Independent / Growth) with the current tier highlighted, owner-editable and read-only for admin/agent; a downgrade confirmation dialog for paid→free changes; and an owner-gated `PATCH /v1/admin/settings/plan` endpoint that enqueues the real `ApplyPlanTransitionJob` cascade.
  </what-built>
  <how-to-verify>
    Preconditions: backend running (`cd backend && rails server`, port 8080) and frontend running (`cd frontend && npm run dev`, port 3000). Use a brokerage where you have an owner account and can also sign in as an admin or agent of the same brokerage.

    1. As an OWNER, go to `/admin/settings`. Confirm a "Plan" section appears below "Ownership Management", showing the current tier highlighted in a segmented control (Free | Independent | Growth).
    2. As the owner, click an UPGRADE or LATERAL tier (e.g. Independent → Growth, or Free → Independent). Confirm: the change applies immediately with NO dialog, a success toast reads `Plan updated to {Tier}` (e.g. "Plan updated to Growth"), and the highlighted tier updates.
    3. As the owner, from a PAID tier click "Free". Confirm a confirmation dialog appears titled `Downgrade to Free?` with the freeze/suspend warning and buttons `Keep current plan` / `Downgrade to Free` (red). Click `Keep current plan` — confirm the dialog closes and the tier stays on the paid tier (no change, no toast).
    4. Repeat step 3 and click `Downgrade to Free` — confirm the tier switches to Free and a `Plan updated to Free` toast appears. (Backend job runs asynchronously; no spinner/polling is expected.)
    5. Sign in as an ADMIN or AGENT of the same brokerage, go to `/admin/settings`. Confirm the Plan section shows the current tier highlighted but the selector is DISABLED (dimmed, non-clickable) with the caption `Only owners can change the brokerage's plan.` — not a plain text/badge replacement.
    6. Server-side enforcement (PLAN-25): while signed in as the admin/agent, open browser devtools and, on any existing `/v1/admin/*` request in the Network tab, copy the `Authorization` header value. In the console run:
       `fetch('/v1/admin/settings/plan', { method: 'PATCH', headers: { 'Content-Type': 'application/json', 'Authorization': '<paste the Bearer token here>' }, body: JSON.stringify({ plan: 'growth' }) }).then(r => console.log('status', r.status))`
       Confirm the logged status is `403`, proving the disabled UI is backed by real server-side owner enforcement.
    7. Optional integrity check: after step 4's downgrade, reload the Domains admin page and confirm the previously-custom domain now reflects the frozen state (the cascade ran). Per D-07 the plan mutation does not proactively refresh Domains, so a manual reload is expected.
  </how-to-verify>
