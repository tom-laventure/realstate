# Phase 41 — UI Design Contract

> Visual and interaction contract for the new "Plan" section on `/admin/settings` (owner-editable 3-way plan selector + downgrade confirmation dialog). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `frontend/components.json` detected, not created by this phase) |
| Preset | style: `new-york`, baseColor: `zinc`, cssVariables: `true`, iconLibrary: `lucide` |
| Component library | Radix UI primitives (via shadcn), base `radix` |
| Icon library | `lucide-react` (project-wide constraint, CLAUDE.md) |
| Font | System UI stack — `-apple-system, BlinkMacSystemFont, 'Segoe UI', 'Roboto', 'Oxygen', ...` (`src/index.css`); no custom webfont, none introduced by this phase |

**Existing components reused as-is (no new shadcn installs needed — all already present in `npx shadcn info` output):** `Card`/`CardHeader`/`CardTitle`/`CardDescription`/`CardContent`, `Tabs`/`TabsList`/`TabsTrigger` (`variant="default"`), `AlertDialog`/`AlertDialogContent`/`AlertDialogHeader`/`AlertDialogTitle`/`AlertDialogDescription`/`AlertDialogFooter`/`AlertDialogCancel`/`AlertDialogAction`, `Button`.

No `RadioGroup` (rejected per RESEARCH.md — wrong visual shape for a "compact segmented control"). No `Dialog` (rejected — D-01/D-02 want a single plain-warning dialog, not `RemoveOwnerDialog`'s multi-step wizard shape). No `Badge` (D-03 renders the current tier via the Tabs' active-pill state, not a separate badge).

## Spacing Scale

Declared values (must be multiples of 4), matching this codebase's existing settings-page conventions (`OwnershipManagementSection.tsx`, `tabs.tsx`, `alert-dialog.tsx`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps if an icon is added to the section header (optional; `OwnershipManagementSection`'s `UserPlus` icon uses `mr-2` = 8px, not 4px — no icon is required for this section since there's no "Add" action) |
| sm | 8px | `AlertDialogFooter`'s `sm:space-x-2` button gap; `Tabs` track internal padding (`p-1` on `TabsList`) |
| md | 16px | `CardHeader`'s `space-y-2 pb-4` (matches `OwnershipManagementSection`'s header spacing exactly); read-only caption margin above/below the disabled selector |
| lg | 24px | `Card` padding (`p-6` on `CardHeader`/`CardContent`, shadcn default); section-to-section margin (`mt-6` between `OwnershipManagementSection` and the new `PlanManagementSection`, matching existing precedent) |
| xl | 32px | Not used by this phase's single Card section |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions: none. All spacing is inherited unmodified from existing `Card`/`Tabs`/`AlertDialog` primitives and the `OwnershipManagementSection` sibling's layout — no new spacing values are introduced. No icon-only touch targets in this phase (Tabs triggers ship with text labels; dialog buttons ship with text labels).

|------|------|--------|-------------|

**Phase-introduced weights (2 max, per contract rule):** regular (400) and semibold (600). The 500-weight `TabsTrigger` label is inherited from the existing `tabs.tsx` primitive (used unmodified) and is not a new weight this phase adds — same precedent Phase 40 established for the `Label` primitive's 500 weight.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` — `oklch(1 0 0)` (white, light mode) | Page background, `Card` surface for the Plan section, `AlertDialogContent` background |
| Secondary (30%) | `--secondary` / `--muted` — `oklch(0.967 0.001 286.375)` (light zinc) | `TabsList`'s track background (`bg-muted`, `variant="default"`), `CardDescription`/`text-muted-foreground` copy, disabled `TabsTrigger` dimmed state (`disabled:opacity-50` layered over the muted track) |
| Accent (10%) | `--primary` — `oklch(0.21 0.006 285.885)` (near-black, light mode) | **Not introduced by this phase.** The `Tabs` `variant="default"` active-pill state renders neutral (`data-[state=active]:bg-background`/`text-foreground`), not primary-colored, and there is no separate "Save"/"Apply" button for upgrade/lateral changes (D-05: change applies immediately on tab selection). Accent remains reserved project-wide for the onboarding wizard's CTAs/badges established in Phase 40 — do not add a new primary-colored button, badge, or highlight ring to the Plan section |
| Destructive | `--destructive` — `oklch(0.577 0.245 27.325)` (red) | The downgrade confirmation dialog's "Downgrade to Free" `AlertDialogAction` only (`bg-destructive text-destructive-foreground hover:bg-destructive/90`, explicit override of `AlertDialogAction`'s primary default — mirrors `DeleteDomainDialog.tsx`). No other destructive UI in this phase |

Accent reserved for: nothing in this phase (see above) — this is a deliberate, explicit declaration so the checker/executor does not introduce an unplanned primary-colored "Save" button or highlight where D-05's immediate-apply UX and D-03's neutral segmented-control styling call for none.

**Visual focal point:** The active/highlighted pill in the segmented `Tabs` control is the primary visual anchor for the Plan section — it is the only element indicating the brokerage's current tier, so its `data-[state=active]:bg-background` contrast against the muted track must remain the clearest visual signal on the card.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Section title | `Plan` |
| Section description | `Choose the plan that fits your brokerage. Downgrading to Free freezes your custom domain and suspends real board credentials and client memberships.` |
| Read-only caption (admin/agent view, shown below the disabled selector) | `Only owners can change the brokerage's plan.` |
| Primary CTA (only explicit button this phase introduces) | `Downgrade to Free` — the `AlertDialogAction` confirm button in the downgrade dialog. Upgrades and lateral (Independent ↔ Growth) changes have **no** CTA button — selecting a `TabsTrigger` applies the change immediately per D-05 |
| Empty state | Not applicable — `brokerage.plan` is always exactly one of `free`/`independent`/`growth`; there is no zero-state for "current plan" |
| Error state (brokerage fetch, pre-existing `useFetchBrokerage` failure) | `Couldn't load your current plan. Refresh the page to try again.` — mirrors `OwnershipManagementSection`'s existing error copy pattern (`"Couldn't load owners. Try refreshing the page."`) |
| Error state (plan-change mutation failure) | Toast: `Couldn't update your plan. Please try again.` (`toast.error`, fired from the same `useUpdatePlan` mutation's `onError`, for both the direct-selection and dialog-confirm call sites — see RESEARCH.md Pitfall 4) |
| Success toast (plan-change mutation success) | `Plan updated to {Tier}` — e.g. `Plan updated to Growth`, `Plan updated to Free` (`Tier` = capitalized display name: Free / Independent / Growth) — per D-06, fired immediately on HTTP 200, no job-completion wait |
| Destructive confirmation — Downgrade dialog title | `Downgrade to Free?` |
| Destructive confirmation — Downgrade dialog body | `Your custom domain will be frozen and real board credentials and client memberships will be suspended. You can restore everything by upgrading again.` — generic, no itemized counts, per D-01 |
| Destructive confirmation — Downgrade dialog buttons | Cancel: `Keep current plan` · Confirm: `Downgrade to Free` (destructive-styled) — plain Confirm/Cancel per D-02, no type-to-confirm friction |

## Interaction Contract (phase-specific — supplements standard copy/color/spacing contracts above)

| Behavior | Contract |
|----------|----------|
| Owner selecting Independent or Growth (upgrade or lateral) | Applies immediately on `TabsTrigger` click — no confirmation dialog (D-05). Fires the plan-change mutation directly |
| Owner selecting Free while currently on a paid tier (downgrade) | Opens the `DowngradeConfirmDialog` (`AlertDialog`) before any mutation fires. Selecting a tier does NOT itself change the tab's visual selection until confirmed — cancelling must leave the currently-active tier still highlighted |
| Admin/agent view | Renders the identical `Tabs`/`TabsList`/`TabsTrigger` markup with every `TabsTrigger` `disabled`, current tier still visually highlighted via the same `data-[state=active]` styling — never swapped for a plain text/badge (D-04) |
| Job feedback | No spinner, no polling, no pending state (D-06). On HTTP 200: optimistically re-render the new tier as active + fire the success toast. The `ApplyPlanTransitionJob` cascade runs after the response returns |
| Query invalidation | Only `adminBrokerageKeys.all` is invalidated after a successful plan change (D-07). Do not invalidate Domains or Boards query keys from this mutation |
