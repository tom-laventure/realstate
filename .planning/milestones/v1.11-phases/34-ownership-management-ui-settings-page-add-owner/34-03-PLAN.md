  <what-built>
    The `/admin/settings` page now renders an Ownership Management section: a Current Owners list (name + email), an owner-only Add Owner modal (searchable admin/agent dropdown, 3-point warning, confirm-to-promote), and a read-only RolePermissions card for admin/agent viewers. Backend owner-only enforcement shipped in Phase 33.
  </what-built>
  <how-to-verify>
    Start the stack (`cd frontend && npm run dev`; backend already running on 8080). Then:

    1. As an OWNER account, visit `/admin/settings`.
       - Expect: an "Ownership Management" card is the first/only functional section; NO Billing UI is visible anywhere on the page.
       - Expect: the Current Owners list shows each owner's full name + email as plain stacked rows (no table, no avatars, no "You" badge on your own row).
       - Expect: an "Add Owner" button is visible in the section header.
    2. Click "Add Owner". In the modal:
       - Search the dropdown — only admin/agent users appear (no clients, no existing owners).
       - Confirm the note "Only admins and agents can be promoted to owner." appears beneath the dropdown.
       - Select a user — a warning box appears listing all three points: (a) they can remove/demote other owners, (b) full brokerage data + settings access, (c) future billing access.
       - Click "Confirm Add Owner". Expect a success toast and the Current Owners list refetches to include the newly promoted user. Reopen "Add Owner" — the just-promoted user is gone from the eligible dropdown.
    3. As an ADMIN (or AGENT) account, visit `/admin/settings`.
       - Expect: the Current Owners list is visible, the RolePermissions card (Owner/Admin/Agent descriptions — NO Client card) is shown, and there is NO "Add Owner" button.
    4. Negative path (backend boundary): as an ADMIN account, send a direct `POST /v1/admin/settings/owners` with body `{ "user": { "user_id": "<some-eligible-uid>" } }` and the admin's JWT.
       - Expect: HTTP 403 (server-side `require_owner!`, Phase 33). The hidden button is NOT the only defense.
    5. (If reachable) A CLIENT account visiting `/admin/settings` is redirected/blocked by the existing route guard — never sees the page.
  </how-to-verify>
