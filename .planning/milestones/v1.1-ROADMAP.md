# Milestone v1.1: Domain Access Control

**Status:** ✅ SHIPPED 2026-05-16
**Phases:** 6–7
**Total Plans:** 2

## Overview

Enforces strict domain-based routing across the full stack. The main domain serves only the brokerage creation flow; brokerage subdomains never expose `/create`. Frontend routing guards are UX enforcement; the backend 403 guard is the real security boundary. All main domain and subdomain routing is driven by env vars (`VITE_MAIN_DOMAIN`, `APP_BASE_DOMAIN`) — no hardcoded strings.

### Phase 7: Backend Onboarding Guard

**Goal:** Rails API rejects all onboarding requests not originating from the main domain.

**Requirements:** DOM-04, DOM-05

**Plans:** 1 plan

Plans:

- [x] 07-01: `MainDomainOnly` concern + apply to all onboarding controllers

**Success criteria:**
1. `POST /v1/onboarding/brokerage` from a brokerage subdomain returns HTTP 403 — ✓ Verified
2. `POST /v1/onboarding/brokerage` from the main domain succeeds as before — ✓ Verified
3. Domain check and verify endpoints also return 403 from non-main-domain origins — ✓ Verified

**What was delivered:**
- `backend/app/controllers/concerns/main_domain_only.rb` — Rails `ActiveSupport::Concern` with `require_main_domain!` before_action; Origin-first host extraction with `request.host` fallback; `URI::InvalidURIError` rescue; reads `APP_BASE_DOMAIN` via `ENV.fetch`
- 3 onboarding controllers (`BrokeragesController`, `DomainsController`, `UsersController`) each gain `include MainDomainOnly` above `include CognitoAuth` — domain check fires before JWT authentication
- `backend/test/integration/onboarding_domain_guard_test.rb` — 5 tests (4 rejection + 1 pass-through); 22 total backend tests passing, 0 regressions

**Key decisions:**
- Duplicate Origin extraction vs shared helper: duplicated from `BrokerageAuth` intentionally — concerns have different semantics; sharing would couple orthogonal security boundaries
- Simple `{error: "Forbidden"}` shape (not nested admin shape) — matches onboarding controller conventions
- Class-level include (no `only:`/`except:` scoping) — all onboarding actions need the guard

## Milestone Summary

**Key Decisions:**

- DomainGuard as route-tree wrapper components (not router-level split) — consistent with ProtectedRoute pattern; clean tree navigation
- isMainDomain() UX-only; backend 403 is the real trust boundary (decision 06-01, closed in Phase 7)
- Origin-first header extraction for backend guard (mirrors BrokerageAuth) — browser-canonical; falls back to Host for dev/non-browser
- Duplicate concern logic preferred over shared helper — orthogonal security concerns should not be coupled
- ENV-driven domain config on both frontend (`VITE_MAIN_DOMAIN`) and backend (`APP_BASE_DOMAIN`) — no hardcoded strings

**Issues Resolved:**

- Phase 6 frontend guards were UX-only — Phase 7 backend guard closes the API security hole
