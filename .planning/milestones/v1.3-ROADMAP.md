# Milestone v1.3: Test Board & Board Management

**Status:** ✅ SHIPPED 2026-05-24
**Phases:** 11–14
**Total Plans:** 11

## Overview

Replace multi-board seed data with a single TEST board (real North Vancouver addresses + coords), add a test board connect flow that skips RETS credentials and auto-associates listings, and add delete/edit CRUD to the Board Registrations table.

## Phases

### Phase 11: DB Migration & Seed Overhaul

**Goal**: The database has an `is_test_board` flag on boards, the TEST board is the only seeded board with `is_test_board: true`, and 100 listings with real North Vancouver addresses and hardcoded lat/lng are seeded without pre-attached `BrokerageEstate` rows
**Depends on**: Phase 10 (v1.2 complete)
**Requirements**: SEED-01, SEED-02, SEED-03, SEED-04, BOARD-01, BOARD-02
**Plans**: 3 plans

Plans:

- [x] 11-01-PLAN.md — Migration + model scopes + serializer (`is_test_board` column, `test_boards`/`real_boards` scopes, `:is_test_board` serializer attribute) — completed 2026-05-22
- [x] 11-02-PLAN.md — Constants + board seed overhaul + seeds.rb cleanup (`BOARD_SHORT_CODES → TEST`, `09_real_estate_boards.rb → TEST only`, remove dropped file references) — completed 2026-05-22
- [x] 11-03-PLAN.md — Estate seed rewrite + file deletions (`NV_LISTINGS`, remove `BrokerageEstate`/`GroupEstate`, delete 06/07/08, `db:reset` verification) — completed 2026-05-22

**Key decisions:**
- `is_test_board` uses `null: false, default: false` — PostgreSQL >=11 metadata-only migration, no backfill needed
- `test_boards`/`real_boards` scope pair created symmetrically as Phase 12 prep
- `NV_LISTINGS`: per-street lat bands (49.32nn) with 0.0001 steps guarantee all 100 lat values unique
- `db:seed:replant` used for verification (neondb prevents `db:reset` due to connection proxy)
- `seed_board_credentials!` deleted entirely — dev DB starts empty; no fake ciphertext

### Phase 12: Board Connect Flow — Backend

**Goal**: Connecting a board via `POST /v1/admin/board_credentials` bulk-inserts `BrokerageEstate` rows for all estates on that board, and test boards bypass RETS credential validation entirely
**Depends on**: Phase 11
**Requirements**: BOARD-03, BOARD-04
**Plans**: 3 plans

Plans:

- [x] 12-01-PLAN.md — Model conditional validation + factories (`BrokerageBoardCredential unless: real_estate_board&.is_test_board?`, `RealEstateBoard` factory with `:test_board` trait, `BrokerageBoardCredential` factory, model unit tests) — completed 2026-05-23
- [x] 12-02-PLAN.md — Controller updates + integration tests (`BoardCredentialsController#create` board lookup widening + RETS bypass + `BrokerageEstate.insert_all`, `BoardsController#index` widening, BOARD-03/04 integration tests) — completed 2026-05-23
- [x] 12-03-PLAN.md — `Estate#accessible_by` scope restructure + scope unit tests (move `real_boards` filter inside first EXISTS, `BrokerageEstate` path becomes board-type-agnostic) — completed 2026-05-23

**Key decisions:**
- Fixed pre-existing AR Encryption bug: `encrypts :rets_username_ciphertext` (column name) not `encrypts :rets_username` — saves had been failing silently
- `BrokerageEstate.insert_all unique_by: [:brokerage_id, :estate_id]` — idempotent re-connect
- `board.is_test_board? || Rails.env.development?` RETS bypass guard
- `Estate#accessible_by`: outer `joins+merge` removed; `is_test_board = false` moved inside first EXISTS subquery — real-board semantics preserved, test-board estates now reachable
- `SocketError` added to `RetsAuthService` rescue clause — DNS failure in test env returned 500 instead of 422

### Phase 14: Board Credential CRUD

**Goal**: Admins can delete or update any board credential row directly from the Board Registrations table
**Depends on**: Phase 13
**Requirements**: BOARD-06, BOARD-07, BOARD-08
**Plans**: 3 plans

Plans:

- [x] 14-01-PLAN.md — Backend: routes update + `BoardCredentialsController#destroy` + `#update` + integration tests (10 tests covering destroy/update happy paths, RETS branch both directions, IDOR on both actions, `BrokerageEstate` preservation, `real_estate_board_id` reassignment rejection) — completed 2026-05-24
- [x] 14-02-PLAN.md — Frontend infrastructure: install shadcn alert-dialog (Wave 0 blocker), extend `boardType.ts` with `UpdateBoardCredentialPayload`, create `deleteBoardCredential` + `updateBoardCredential` API modules, create `useDeleteBoardCredential` (with `onError` toast) + `useUpdateBoardCredential` (no `onError` — propagates to dialog) hooks — completed 2026-05-24
- [x] 14-03-PLAN.md — Frontend UI: create `EditBoardCredentialDialog` (test vs real board branches, inline error display), extend `BoardRegistrations` to 5-column grid with per-row ⋯ dropdown + `AlertDialog` delete confirmation, extend `BrokerageAdminBoardContext` with `handleDeleteCredential`/`handleEditCredential` actions, pass actions through `BrokerageAdminBoard`. — completed 2026-05-24

**Key decisions:**
- Separate `update_credential_params` — permits only `rets_username`/`rets_password`; never `real_estate_board_id` (board reassignment forbidden)
- Controlled `AlertDialog` pattern (open prop + `deleteTarget` state) — `AlertDialogTrigger` inside `DropdownMenuItem` causes Radix portal/focus conflicts
- `useUpdateBoardCredential` has no `onError` — `mutateAsync` rejection propagates to `EditBoardCredentialDialog` catch block for inline `serverError` display
- `useDeleteBoardCredential` uses fire-and-forget `mutate` — dialog closes on confirm; `onError` toast is sole failure feedback

## Milestone Summary

**Key Decisions:**
- AR Encryption column naming: `encrypts :rets_username_ciphertext` (not `:rets_username`) — DB column name must match `encrypts` declaration
- `Estate#accessible_by` restructure: outer JOIN+merge removal enables test-board access while preserving real-board security
- Controlled `AlertDialog` outside Radix dropdown tree — canonical pattern for cross-context dialog triggers
- Fire-and-forget delete + propagating update: different hook patterns for different UX requirements

**Issues Resolved:**
- Pre-existing AR Encryption bug that prevented any `BrokerageBoardCredential.save` from succeeding
- `Estate#accessible_by` outer JOIN was dropping all test-board estates before EXISTS checks ran
- `SocketError` in `RetsAuthService` caused 500 on DNS failure instead of 422
- `db:seed:replant` strategy for neondb environments where `db:reset` is blocked by connection proxy

**Issues Deferred:**
- Microsoft Calendar sync (CAL-04) — adapter built, activate by expanding `PROVIDERS`
- Apple CalDAV sync (CAL-05) — adapter built, activate by expanding `PROVIDERS`
- `CR-01`: `BrokerageDomain.exists?` missing `.active` scope in `DomainsController#check`
- `CR-02`: S3 favicon upload outside transaction — orphaned on DB failure
- Pre-existing standardrb violations in routes.rb lines 46-48 (calendar routes from Phase 5)

**Technical Debt Incurred:**
- Test board RETS bypass uses `is_test_board? || Rails.env.development?` — the `development?` branch was added to survive test env without real RETS; acceptable at current scale
