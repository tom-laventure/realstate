# Requirements Archive — v1.4 Main Domain Admin Portal

**Archived:** 2026-05-27
**Milestone:** v1.4 — Main Domain Admin Portal
**Status:** ✅ COMPLETE — All 14 requirements shipped

---

## Portal — Main Domain Dashboard Shell

- [x] **PORTAL-01**: User can access `/dashboard/*` on the main domain (routes exist alongside `/create/*`) — Phase 16 (16-01, 16-02)
- [x] **PORTAL-02**: User can reach board registrations, user management, group management, and invitations from the main domain dashboard — Phase 18 (18-02, 18-04, 18-05)
- [x] **PORTAL-03**: User can see the active brokerage name and their role displayed in the dashboard nav bar — Phase 18 (18-03, 18-04, 18-05)

## Auth — Authentication Routing & Access Control

- [x] **AUTH-05**: User signing in on the main domain with ≥1 admin role is redirected to the brokerage selection screen — Phase 16 (16-02)
- [x] **AUTH-06**: User signing in on the main domain with no admin roles anywhere sees a no-access screen explaining they must use their brokerage subdomain — Phase 16 (16-01, 16-02)
- [x] **AUTH-07**: Unauthenticated user accessing `/dashboard/*` is redirected to sign-in — Phase 16 (16-02)

## Brok — Brokerage Selection & Switching

- [x] **BROK-01**: User can see a card per brokerage they admin (with brokerage name and role) on the brokerage selection screen — Phase 17 (17-02)
- [x] **BROK-02**: User admining exactly one brokerage bypasses the selection screen and lands directly on the dashboard — Phase 17 (17-02)
- [x] **BROK-03**: User can switch the active brokerage via a dropdown in the nav bar without leaving the current page — Phase 18 (18-01, 18-03)
- [x] **BROK-04**: Switching brokerage via the nav dropdown updates all visible admin panel data to the newly selected brokerage — Phase 18 (18-01, 18-03)

## BE — Backend API

- [x] **BE-01**: Admin user can call `GET /v1/account/admin_brokerages` and receive a list of all brokerages where they hold an admin or owner role — Phase 15 (15-02)
- [x] **BE-02**: Backend resolves `Current.brokerage` from `X-Brokerage-Id` request header when the request Host is the main domain, enabling existing `/v1/admin/**` endpoints to serve main-domain requests — Phase 15 (15-01)
- [x] **BE-03**: Admin endpoint called from main domain without a valid `X-Brokerage-Id` header returns HTTP 400 Bad Request — Phase 15 (15-01)

## ONB — Post-Create Flow

- [x] **ONB-04**: User completing the brokerage creation wizard is redirected to the main domain dashboard with the newly created brokerage auto-selected — Phase 17 (17-03)

---

## Future Requirements (carried to v1.5+)

- Brokerage switch data refreshes while preserving active tab position (UX polish, deferred)
- Deep-link into specific admin panel by URL (e.g. `/dashboard/boards`) while preserving brokerage context across navigation

## Out of Scope

- Non-admin users managing profile from main domain — main domain portal is admin-only; agents use their brokerage subdomain
- Main domain showing listing data — /dashboard is admin-management only, not a listing discovery interface
- Creating additional brokerages from the dashboard — creation wizard lives at /create, not from within the portal
- Invitation accept flows on main domain — invitations resolve to brokerage subdomains (existing ONB-02)
