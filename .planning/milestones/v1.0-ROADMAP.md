# Milestone v1.0: Security, OAuth & Calendar

**Status:** ✅ SHIPPED 2026-05-13
**Phases:** 1–5
**Total Plans:** 30

## Overview

Milestone 2 hardened the platform before expanding it. Phase 1 closed the active RBAC gap and removed all documented security/debt issues. Phase 2 built the test suite immediately after, proving Phase 1 works. Phase 3 fixed the two broken onboarding flows that blocked new user activation. Phase 4 shipped Google social login as a single atomic change (Lambda + button landed together). Phase 5 delivered personal Google calendar sync — model and job infrastructure first, then the Google provider and settings UI (Microsoft and Apple deferred to v2).

## Milestone Summary

**Key Decisions:**
- `Admin::BaseController#require_admin!` pattern — imperative authorization, no declarative gem, inherited by all 13 admin controllers
- Google OAuth ships atomically — PreSignUp Lambda and "Sign in with Google" button must land in the same phase; never button without Lambda
- Fixed intermediary callback URL strategy — `auth.realtybase.ca/oauth/callback` resolves brokerage tenant from OAuth state parameter
- SolidQueue + advisory locks for CalendarSyncJob — concurrent token refresh serialized via PostgreSQL advisory locks on `UserCalendarConnection.id`
- Microsoft and Apple calendar adapters built but scoped out of v1.0 — PROVIDERS constant and providerOrder narrowed to Google only

**Issues Resolved:**
- Ruby 4.0 SyntaxError on factory trait brace syntax — switched to do..end blocks
- `with_advisory_lock ~> 7.5` incompatible with Rails 7.1.4 — downgraded to ~> 5.3
- Vitest 4.x ESM incompatibility with jsdom 27.x — `execArgv: ['--experimental-require-module']`
- OAuth routes namespace conflict — flat route `get "google/authorize"` resolves to correct controller path

**Issues Deferred:**
- Microsoft Calendar (CAL-04) — adapter code in codebase, activate in v2 by expanding PROVIDERS constant
- Apple Calendar (CAL-05) — adapter code in codebase, activate in v2 by expanding PROVIDERS constant
- Two-way calendar sync — requires webhooks and conflict resolution
- Render.com PostgreSQL migrations for calendar tables — must be applied from Render environment

**Technical Debt Incurred:**
- `omniauth-azure-activedirectory-v2` is deprecated (post-install warning to switch to `omniauth-entra-id`) — rename deferred to v2
- Microsoft/Apple adapters present in codebase but untested end-to-end
