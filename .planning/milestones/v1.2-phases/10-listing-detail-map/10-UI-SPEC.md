## Interaction Contract

### Map Section Placement

**Placement:** In `EstateDashboard.tsx`, between `<EstateSummaryCard>` and `<EstateSectionTabs>`. The map shows property-level geographic metadata — it belongs in the "about this property" zone, not inside a user-activity tab. Placing it before the tabs ensures it is always visible (not hidden behind a tab click) and never re-mounts on tab switch.

**Container dimensions:**
- Width: `w-full` (fills `max-w-5xl` container, same as other sections)
- Height: `h-64` (256px) — 128px shorter than the group dashboard map (`h-96`) because this is a supplemental panel in a dense detail page
- Border: `rounded-xl border border-border overflow-hidden`
- Outer wrapper spacing: inherits `gap-6` from EstateDashboard's `flex flex-col gap-6` — no additional margin needed

**Section label:** Above the map border, not inside it. Uses `space-y-2` wrapper:
```
<p className="text-sm font-medium text-muted-foreground">Property location</p>
<div className="h-64 w-full overflow-hidden rounded-xl border border-border">
  <MapGL ... />
</div>
```

### Coordinate Guard

The map section is **absent, not broken**, when coordinates are unavailable. The guard lives in `EstateDashboard.tsx`, not inside `EstateLocationMap.tsx`:

```tsx
{state.estate.listingDetail?.latitude != null &&
 state.estate.listingDetail?.longitude != null && (
    <EstateLocationMap
        latitude={state.estate.listingDetail.latitude}
        longitude={state.estate.listingDetail.longitude}
        address={state.estate.listingDetail.address}
    />
)}
```

Use `!= null` (not `!` or `!== null`) — handles both `null` and `undefined` while correctly accepting `0.0` as a valid coordinate (equator). Never render `<MapGL>` with `NaN` or null coordinate values.

### Map Behavior

| Property | Value | Rationale |
|----------|-------|-----------|
| Default center | `{ longitude, latitude }` from props | Listing's exact location — no fallback needed; map only renders when coordinates exist |
| Initial zoom | 14 | Street-level visibility; shows neighborhood context without showing the entire city |
| Map style | `mapbox://styles/mapbox/streets-v12` | Matches GroupMapPanel — consistent across all maps in the product |
| Gesture handling | `cooperativeGestures` prop on `<MapGL>` | Prevents scroll-wheel hijacking; established Phase 9 pattern |
| Interaction | Fully interactive (pan, zoom via NavigationControl) | Users may want to explore the neighborhood |
| Fit bounds | Not applicable — single pin, map centers on the pin by default | No `fitBounds` call needed |

### Pin

The primary visual anchor of `EstateLocationMap` is the `MapPin` icon rendered in `fill-primary` at the listing's coordinates — the only colored element in the map, drawing the eye to the property's exact location.

- Component: `<Marker longitude={longitude} latitude={latitude}>` from `react-map-gl/mapbox`
- Icon inside marker: `<MapPin className="h-7 w-7 fill-primary text-primary drop-shadow-sm" />`
- `aria-label`: `address ? \`Property at ${address}\` : 'Property location'`
- No popup on click — single listing, user is already on the detail page; clicking the pin adds no information
- No hover state — Mapbox Marker has no built-in hover; adding one would require a custom overlay, which is out of scope

### Navigation Control

- Component: `<NavigationControl position="top-right" />` from `react-map-gl/mapbox`
- Renders zoom in/out buttons and compass — standard Mapbox control
- No additional controls (scale, geolocate, fullscreen) — out of scope for this phase

### Token-Missing State

Displayed when `VITE_MAPBOX_TOKEN` is an empty string (dev/CI environment without the token configured):

```
┌──────────────────────────────────────────────────────┐  ← h-64, border-dashed
│                                                      │
│     Map token not configured                         │  ← text-sm text-muted-foreground
│                                                      │
└──────────────────────────────────────────────────────┘
```

Container: `flex h-64 w-full items-center justify-center rounded-xl border border-dashed text-sm text-muted-foreground`

This renders instead of `<MapGL>` — the map library is never initialized without a token. This is a developer-facing message, not a user-facing error.

## States Inventory

Every visual state `EstateLocationMap` and its insertion point in `EstateDashboard` must handle:

| State | Trigger | Visual |
|-------|---------|--------|
| Section absent | `listingDetail?.latitude == null` or `listingDetail?.longitude == null` | No map section rendered at all — gap-6 between EstateSummaryCard and EstateSectionTabs is unchanged |
| Token missing | `import.meta.env.VITE_MAPBOX_TOKEN` is empty string | `h-64` dashed border container with centered `"Map token not configured"` text |
| Map rendered | Both coordinates present, token set | `h-64` Mapbox map with pin at listing coordinates, `NavigationControl` top-right |
| Pin visible | Always when map renders | `MapPin` icon at listing lat/lng, `fill-primary text-primary drop-shadow-sm` |

No loading state is needed for the map itself — `react-map-gl` renders the container immediately and loads tiles asynchronously; the container background remains while tiles load (Mapbox default behavior). No spinner overlay required.

No error state beyond the token-missing placeholder. If Mapbox tile loading fails (network issue), Mapbox GL renders a blank canvas — this is acceptable and outside the scope of this phase to handle.
