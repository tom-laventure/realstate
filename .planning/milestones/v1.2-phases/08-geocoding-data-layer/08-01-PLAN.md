<objective>
Add `latitude`, `longitude`, and `geocoding_failed` columns to the `listing_details` table, expose them through `ListingDetailSerializer` (which is already wired into both group dashboard `index` and `show` responses via `EstateSerializer#listing_detail`), and document them on the `ListingDetail` model with attribute hints for readability.

Purpose: Establish the data layer foundation for Phase 8. Without these columns, the geocoding service and job (Plan 02) have nowhere to write coordinates, and the frontend (Phase 9) has no fields to read. This plan must land first because the job in Plan 02 calls `listing_detail.update!(latitude:, longitude:)` against these columns.

Output: A reversible migration, an updated serializer (3 new attributes), updated `db/schema.rb` after running `rails db:migrate`, and documentation-only attribute hints on the model.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01-01 | Information Disclosure | ListingDetailSerializer exposing coordinates | accept | Coordinates are intrinsic to the listing (already public via MLS); exposure to authenticated brokerage agents is the explicit feature requirement (MAP-01). Existing multi-tenancy controls (`BrokerageAuth` resolves `Current.brokerage`, `accessible_by` scope in `GroupEstatesQuery`) prevent cross-tenant data leak — coordinates inherit those controls because they ride on the same serializer the existing endpoints already use. |
| T-08-01-02 | Tampering | Coordinates writable via mass assignment | mitigate | No API endpoint accepts `latitude`/`longitude` as params in Phase 8 (D-07). The only writers are `GeocodeListingsJob` (Plan 02) and direct DB updates. `ListingDetail` model does not include the fields in any `permit` filter because no controller permits them. |
| T-08-01-03 | Integrity | Storing coordinates as `float` would silently lose precision | mitigate | Migration uses `decimal(10,6)` — 6 decimal places preserved exactly. `GeocodingService` (Plan 02) calls `.to_d` on Nominatim's string responses to avoid float intermediate. |
| T-08-01-04 | Denial of Service | Adding 3 columns to a large `listing_details` table could lock the table | accept | This is a single-tenant SaaS in early stage with no production load constraints documented in STATE.md. `add_column` with `default: false, null: false` on PostgreSQL ≥ 11 is a metadata-only change (no table rewrite). The two NULL-able decimal columns are also metadata-only. No backfill performed in the migration. |

Residual risks: None requiring action in this plan.
</threat_model>
