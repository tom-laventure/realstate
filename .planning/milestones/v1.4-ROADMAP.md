# Milestone v1.4: Main Domain Admin Portal

**Status:** ✅ SHIPPED 2026-05-27
**Phases:** 15–18
**Total Plans:** 11

## Overview

Built the main-domain admin portal giving brokerage admins a central hub to manage all their brokerages without relying on individual subdomain URLs. Extended BrokerageAuth to resolve brokerage context from a request header, added a cross-brokerage admin_brokerages endpoint, expanded the frontend routing to support /dashboard/* alongside /create/*, and delivered a full portal experience: brokerage selection screen, per-brokerage admin suite, nav-bar brokerage switcher, and a domain-adaptive admin shell.

## Milestone Summary

**Key Decisions:**

- `main_domain_request?` reuses `extract_domain_from_request` — no duplication of URI.parse block (single source of truth)
- `AdminBrokeragesController` excludes BrokerageAuth — cross-brokerage endpoint design
- `useFetchAdminBrokerages` is an imperative wrapper (not useQuery) — LoginSuccessful is a fire-once lifecycle component
- `noAccess` route has no ProtectedRoute — avoids redirect loop for unauthenticated users
- `setToken` placed before API call — axios interceptor reads localStorage; reversed order causes 401
- `activeBrokerage` Redux state is in-memory only — never persisted to localStorage/sessionStorage
- `AdminDomainShell` single-route pattern — avoids React Router path conflicts from domain-guarded duplicate /admin/ blocks
- Portal components use raw div card pattern — not shadcn Card, per UI-SPEC.md contract established in Phase 16

**Issues Resolved:**

- Login.tsx deviation (Phase 16): email/password sign-in bypasses LoginSuccessful entirely via CreateAccount → signIn.ts → onAuthenticated; fixed by adding domain-branching logic to Login.tsx as well
- RequireRole blank panel (Phase 18): RequireRole checked isUserLoaded which is always false on main domain; fixed by isMainDomain() bypass before that check

**Technical Debt Carried Forward:**

- CR-01: `BrokerageDomain.exists?` missing `.active` scope in DomainsController#check — pre-existing since v1.1
- CR-02: S3 favicon upload outside transaction — orphaned on DB failure — pre-existing since v1.1
- Microsoft Calendar sync (CAL-04) and Apple CalDAV sync (CAL-05) — adapters built in v1.0, not yet activated
