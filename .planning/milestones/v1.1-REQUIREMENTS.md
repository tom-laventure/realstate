## v1.1 Requirements

### Domain Routing & Access Control (DOM)

- [x] **DOM-01**: Frontend reads main domain from `VITE_MAIN_DOMAIN` env var and detects whether `window.location.hostname` matches the main domain at runtime
  - **Outcome:** Validated — `isMainDomain()` utility in `frontend/src/helpers/domain.ts` reads `VITE_MAIN_DOMAIN`; 4 unit tests covering main-domain and subdomain cases
  - **Phase:** 6 | **Completed:** 2026-05-14

- [x] **DOM-02**: On the main domain, all routes except `/create/*` render a 404 (not-found) page; authenticated app routes (dashboard, admin, account) are inaccessible from the main domain
  - **Outcome:** Validated — `SubdomainOnly` guard wraps all non-`/create` routes; wildcard route renders `NotFound` component
  - **Phase:** 6 | **Completed:** 2026-05-14

- [x] **DOM-03**: On brokerage subdomains and custom domains, navigating to `/create` (or any `/create/*` sub-path) redirects to `/` (brokerage dashboard)
  - **Outcome:** Validated — `MainDomainOnly` guard on `/create` route tree redirects to `/` on subdomain hostnames
  - **Phase:** 6 | **Completed:** 2026-05-14

- [x] **DOM-04**: All `/v1/onboarding/*` backend endpoints reject requests not originating from the main domain with HTTP 403; applies to brokerage create, domain check/verify, and user profile update
  - **Outcome:** Validated — `MainDomainOnly` Rails concern registered as `before_action` in all three onboarding controllers; 4 rejection integration tests passing
  - **Phase:** 7 | **Completed:** 2026-05-16

- [x] **DOM-05**: Backend reads the main domain from the existing `APP_BASE_DOMAIN` env var for origin validation; no hardcoded domain strings in guard logic
  - **Outcome:** Validated — `ENV.fetch("APP_BASE_DOMAIN", "realstate.ca")` is the only domain reference; no hardcoded strings outside the ENV.fetch default
  - **Phase:** 7 | **Completed:** 2026-05-16
