# Milestone v1.5: Domain Management

**Status:** ✅ SHIPPED 2026-05-29
**Phases:** 19–21
**Total Plans:** 10

## Overview

Give brokerage admins full control over their domains — a Domains admin page to view, edit, and manage their subdomain and optional custom domain (Pro), designate a primary domain, understand phase-out timelines for retiring domains, and automatically redirect users arriving on non-primary domains to the primary domain.

## Phases

### Phase 19: Domain Schema & Auth Integration

**Goal**: Extend brokerage_domains with lifecycle columns, backfill existing data as active primary subdomains, and update BrokerageAuth + the Caddy TLS endpoint to route by status — so phasing-out domains still resolve and decommissioned ones don't
**Depends on**: Phase 18
**Plans**: 3 plans

Plans:

- [x] 19-01-PLAN.md — Lifecycle columns migration (add 4 columns, backfill, replace unique index)
- [x] 19-02-PLAN.md — BrokerageDomain model (enums, RESERVED_SLUGS, routable scope, validations)
- [x] 19-03-PLAN.md — Routing integration (BrokerageAuth + DomainsController + factory + tests)

**Details:**
- Atomic migration adds `domain_type`, `status`, `is_primary`, `phase_out_at` to `brokerage_domains`; SQL backfill sets all existing rows to `domain_type: subdomain`, `status: active`, `is_primary: true`; replaces full unique index with partial `WHERE status != 'decommissioned'`
- `BrokerageDomain` model: string-backed Rails enums for domain_type/status, `RESERVED_SLUGS` constant (10 words), `routable` scope (active+phasing_out), subdomain slug format validation, status-requires-verified invariant
- `BrokerageAuth` updated from `.find_by(verified: true)` to `.routable` scope; `DomainsController#check` updated to `.status_active` scope; brokerage_domain factory gets three new column defaults

## Milestone Summary

**Key Decisions:**

- `phase_out!` sets 30-day window; `decommission!` immediate; max 2 phasing-out per type — slot constraint enforced in controller
- Pro-tier gate on custom domains: `plan == 'premium'`; basic-tier → HTTP 403 + upgrade message
- `PrimaryDomainRedirect` uses `window.location.replace` (not href) — no back-button history entry
- `lookupDomain` uses BASE axios (no auth token) — correct for public unauthenticated endpoint
- `BrokerageAuth` uses `.routable` (active+phasing_out) for tenant resolution; `DomainsController#check` uses `.status_active` — phasing_out domains route but don't get TLS provisioned

**Issues Resolved:**

- Portal `PortalShell` 2×2 grid missing Domains card — added in UAT fix
- `DomainCard.tsx` `isPrimary` badge not scoped to active status — fixed `domain.isPrimary && isActive`
- Slot-warning banner showing when already blocked — fixed with `hasSlots` guard
- `.active` scope missing from CORS dev bypass — fixed

**Issues Deferred:**

- DNS verification for custom domains — best-effort uniqueness check at input time only; true ownership enforcement deferred to v1.6
- Server-side HTTP 301 redirect at the Caddy layer — client-side redirect on app init is sufficient for this milestone

**Technical Debt Incurred:**

- REQUIREMENTS.md checkbox sync gap continues — 11 requirements left unchecked at phase close despite being implemented (Phase 20 requirements)
